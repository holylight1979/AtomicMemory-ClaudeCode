# 環境變數

> 控制 Claude Code 行為的環境變數參考。

環境變數可以控制 Claude Code 的行為，例如模型選擇、身份驗證、請求路由和功能切換。許多相同的行為也可以透過[設定檔](https://code.claude.com/docs/zh-TW/settings.md)欄位、[CLI 旗標](https://code.claude.com/docs/zh-TW/cli-reference.md)或工作階段內命令（如 `/model`）進行設定。

本頁涵蓋以下內容：

* [在您的 shell 或設定檔中設定環境變數](#set-environment-variables)
* [當行為可以透過多種方式設定時，檢查哪個值適用](#precedence)
* [查詢 Claude Code 讀取的變數](#variables)
* [查看當變數關閉功能旗標擷取時，哪些功能停止運作](#features-that-need-feature-flag-fetching)

## 設定環境變數

您在 shell 中設定的變數只在該終端機工作階段期間有效，而設定檔中的變數則在每次執行 `claude` 時都會套用。

### 在 shell 中設定變數

在啟動 `claude` 之前設定變數：

> [tab] macOS, Linux, WSL
>
> ```bash theme={null}
> export API_TIMEOUT_MS="1200000"
> claude
> ```
>
> 若要在每個工作階段都設定它，請將 `export` 行新增到 `~/.bashrc`、`~/.zshrc` 或您的 shell 設定檔。

> [tab] Windows PowerShell
>
> ```powershell theme={null}
> $env:API_TIMEOUT_MS = "1200000"
> claude
> ```
>
> 若要在每個工作階段都設定它，請執行 `[Environment]::SetEnvironmentVariable("API_TIMEOUT_MS", "1200000", "User")` 並開啟新的終端機。

> [tab] Windows CMD
>
> ```batch theme={null}
> set API_TIMEOUT_MS=1200000
> claude
> ```
>
> 若要在每個工作階段都設定它，請執行 `setx API_TIMEOUT_MS "1200000"` 並開啟新的終端機。

指派行在成功時不會列印任何內容。若要確認變數已設定，請在同一個 shell 中將其列印出來：

> [tab] macOS, Linux, WSL
>
> ```bash theme={null}
> echo $API_TIMEOUT_MS
> ```

> [tab] Windows PowerShell
>
> ```powershell theme={null}
> echo $env:API_TIMEOUT_MS
> ```

> [tab] Windows CMD
>
> ```batch theme={null}
> echo %API_TIMEOUT_MS%
> ```

### 在設定檔中設定變數

在 `settings.json` 檔案的 `env` 鍵下新增變數，如果檔案不存在則建立它。Claude Code 會直接從檔案讀取它們，因此無論如何啟動 `claude`，它們都會生效。執行中的工作階段會在您儲存檔案時將新的和已變更的值套用到其環境，但在啟動時讀取其變數一次的功能（例如 [OpenTelemetry 監控](https://code.claude.com/docs/zh-TW/monitoring-usage.md)）會保留其啟動值，直到您重新啟動為止。從檔案中移除變數不會在執行中的工作階段中取消設定它；移除會在您下次啟動 `claude` 時生效。

```json ~/.claude/settings.json theme={null}
{
  "env": {
    "API_TIMEOUT_MS": "1200000",
    "BASH_DEFAULT_TIMEOUT_MS": "300000"
  }
}
```

Claude Code 會依原樣將這些值複製到其環境中。這些值不會經過任何 shell 處理，因此 `~` 或 `$HOME` 等簡寫會保持輸入時的樣子。對於接受路徑的變數（例如 `CLAUDE_CONFIG_DIR`），請寫入絕對路徑：`"CLAUDE_CONFIG_DIR": "/home/you/.claude-work"`。

您選擇的檔案控制變數套用的對象：

| 檔案 | 套用對象 |
| :- | :- |
| `~/.claude/settings.json` | 您，在每個專案中 |
| `.claude/settings.json` | 在專案中工作的所有人，簽入原始碼控制 |
| `.claude/settings.local.json` | 您，僅在此專案中，當 Claude Code 將設定儲存到它時會被 gitignore；如果您手動建立它，請將其新增到您的 gitignore |
| 受管理的設定 | 您組織中的所有人，由管理員部署 |

請參閱 [設定檔](https://code.claude.com/docs/zh-TW/settings.md#where-settings-live) 以了解每個檔案的位置，以及 [設定優先順序](https://code.claude.com/docs/zh-TW/settings.md#settings-precedence) 以了解當多個檔案設定相同變數時它們如何結合。

## 優先順序

某些行為同時具有環境變數和專用設定鍵，Claude Code 讀取哪一個的順序因鍵而異。對於 `ANTHROPIC_MODEL` 和 `CLAUDE_CODE_AUTO_CONNECT_IDE`，Claude Code 會先讀取變數，只有在變數未設定時才使用 `model` 或 `autoConnectIde` 設定。對於您要設定的配對，請檢查下方變數的列，以及 [設定參考](https://code.claude.com/docs/zh-TW/settings-reference.md) 上的鍵項目。

當相同的變數同時在您的 shell 和設定檔 `env` 區塊中設定時，設定檔值會在大多數工作階段中套用。Claude Code 會將每個 `env` 項目寫入程序環境，取代從 shell 繼承的值。[`env` 值如何與您的 shell 互動](https://code.claude.com/docs/zh-TW/settings-reference#how-env-values-interact-with-your-shell) 涵蓋保留繼承值的工作階段，以及 [`env` 設定](https://code.claude.com/docs/zh-TW/settings-reference#when-claude-code-applies-env-values) 說明何時套用它們。少數變數有特殊處理；[`env` 設定](https://code.claude.com/docs/zh-TW/settings-reference#env) 列出例外。

在設定檔中，您可以設定變數，但無法移除變數。若要覆寫無法取消設定的變數，例如由您無法控制的 shell 設定檔匯出的過時 `CLAUDE_CODE_USE_VERTEX`，請在 `env` 區塊中將其設定為空字串：`"CLAUDE_CODE_USE_VERTEX": ""`。Claude Code 將空值視為未設定以進行提供者選擇。子程序仍會繼承空值。

在設定檔之間，`env` 值遵循 [設定優先順序](https://code.claude.com/docs/zh-TW/settings.md#settings-precedence)，因此受管設定項目會覆寫使用者或專案設定中的相同變數。專案和本機設定無法設定某些變數，例如 `CLAUDE_CONFIG_DIR` 和 OpenTelemetry 匯出器變數。[Claude Code 在 `env` 中忽略的變數](https://code.claude.com/docs/zh-TW/settings-reference#variables-claude-code-ignores-in-env) 列出它們，以及仍然適用的 OpenTelemetry 關閉值。

環境變數如何與 CLI 旗標和工作階段內命令互動因功能而異：`--model` 和 `/model` 會覆寫 `ANTHROPIC_MODEL`，而 `CLAUDE_CODE_EFFORT_LEVEL` 會覆寫 `--effort` 和 `/effort`。當變數與另一個設定來源互動時，[變數](#variables) 列表中的其列會說明優先順序或連結到記錄該項目的頁面。

Claude Code 在啟動時讀取 shell 環境變數，因此對它們的變更會在您下次啟動 `claude` 時生效。在設定檔中 `env` 鍵下設定的變數會在檔案變更時重新套用到執行中的工作階段，但 [在設定檔中設定變數](#in-settings-files) 所述的僅啟動時例外除外。

## 變數

數值型變數（例如逾時、token 預算與重試次數）除了純數字外，也接受科學記號與數字分隔符號寫法，除非該變數的列中註明僅接受純數字。例如，Claude Code 會將 `2e3` 讀取為 2000，將 `64_000` 讀取為 64000。在 v2.1.211 之前，這些寫法可能會在無提示的情況下設定成小得多的值，例如 `1e6` 會將逾時設定為 1。

> [!NOTE]
>
> 對於開啟或關閉某項行為的變數，設定 `1`、`true`、`yes` 或 `on` 即可開啟，設定 `0`、`false`、`no` 或 `off` 即可關閉，不區分大小寫。
>
> 有些變數只判斷是否已設定，因此任何非空值（包括 `0`）都會開啟該行為，而要關閉該行為，需取消設定該變數或將其設為空值。以下變數採用此方式：
>
> * `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`
> * `DISABLE_TELEMETRY`
> * `DISABLE_ERROR_REPORTING`
> * `CLAUDE_CODE_TMUX_TRUECOLOR`
> * `IS_DEMO`
>
> 每個變數的列中也會說明其各自的規則。

| 變數 | 用途 |
| :- | :- |
| `ANTHROPIC_API_KEY` | 以 `X-Api-Key` 標頭傳送的 API 金鑰。設定後，即使您已登入，也會使用此金鑰而非您的 Claude Pro、Max、Ultra、Team 或 Enterprise 訂閱。在非互動模式（`-p`）中，只要存在此金鑰就一定會使用。在互動模式中，系統會提示您核准該金鑰一次，之後它才會覆寫您的訂閱。若要改用您的訂閱，請執行 `unset ANTHROPIC_API_KEY` |
| `ANTHROPIC_AUTH_TOKEN` | `Authorization` 標頭的自訂值（您在此設定的值會加上 `Bearer ` 前綴） |
| `ANTHROPIC_AWS_API_KEY` | [Claude Platform on AWS](https://code.claude.com/docs/zh-TW/claude-platform-on-aws.md) 的工作區 API 金鑰，於 AWS Console 中產生。以 `x-api-key` 傳送，且優先於 AWS SigV4 |
| `ANTHROPIC_AWS_BASE_URL` | 覆寫 [Claude Platform on AWS](https://code.claude.com/docs/zh-TW/claude-platform-on-aws.md) 端點 URL。用於自訂區域或透過 [LLM 閘道](https://code.claude.com/docs/zh-TW/llm-gateway)路由時。預設為 `https://aws-external-anthropic.{region}.api.aws`。Claude Code 解析區域時採用[與 Amazon Bedrock 相同的優先順序](https://code.claude.com/docs/zh-TW/amazon-bedrock.md#3-configure-claude-code) |
| `ANTHROPIC_AWS_WORKSPACE_ID` | [Claude Platform on AWS](https://code.claude.com/docs/zh-TW/claude-platform-on-aws.md) 的必要設定。在每個請求中以 `anthropic-workspace-id` 標頭傳送 |
| `ANTHROPIC_BASE_URL` | 覆寫 API 端點，以透過代理伺服器或閘道路由請求。關於該閘道拒絕 MCP 工具搜尋時會發生什麼情況，請參閱[透過 LLM 閘道進行工具搜尋](https://code.claude.com/docs/zh-TW/mcp.md#tool-search-through-a-gateway)。自 v2.1.196 起，當此變數指向 `api.anthropic.com` 以外的主機時，[Remote Control](https://code.claude.com/docs/zh-TW/remote-control.md#requirements) 會停用，與其在 Amazon Bedrock、Google Cloud's Agent Platform 和 Microsoft Foundry 上的行為一致 |
| `ANTHROPIC_BEDROCK_BASE_URL` | 覆寫 Amazon Bedrock 端點 URL。用於自訂 Amazon Bedrock 端點或透過 [LLM 閘道](https://code.claude.com/docs/zh-TW/llm-gateway)路由時。請參閱 [Amazon Bedrock](https://code.claude.com/docs/zh-TW/amazon-bedrock.md) |
| `ANTHROPIC_BEDROCK_MANTLE_BASE_URL` | 覆寫 Amazon Bedrock Mantle 端點 URL。請參閱 [Mantle 端點](https://code.claude.com/docs/zh-TW/amazon-bedrock.md#use-the-mantle-endpoint) |
| `ANTHROPIC_BEDROCK_REGION_PREFIX` | Claude Code 優先嘗試的跨區域推論設定檔前綴（`us`、`eu`、`apac`、`jp`、`au` 或 `global`），而非從 AWS 區域推導出的前綴。在 AWS GovCloud 區域中會被忽略。需要 Claude Code v2.1.224 或更新版本。請參閱 [Amazon Bedrock](https://code.claude.com/docs/zh-TW/amazon-bedrock.md#cross-region-inference-profile-prefixes) |
| `ANTHROPIC_BEDROCK_SERVICE_TIER` | Amazon Bedrock [服務層級](https://docs.aws.amazon.com/bedrock/latest/userguide/service-tiers-inference.html)（`default`、`flex` 或 `priority`）。以 `X-Amzn-Bedrock-Service-Tier` 標頭傳送。請參閱 [Amazon Bedrock](https://code.claude.com/docs/zh-TW/amazon-bedrock.md#service-tiers) |
| `ANTHROPIC_BETAS` | 要包含在 API 請求中的額外 `anthropic-beta` 標頭值，以逗號分隔。Claude Code 已會傳送其所需的 beta 標頭；在 Claude Code 加入原生支援之前，可使用此變數選擇加入 [Anthropic API beta](https://platform.claude.com/docs/en/api/beta-headers)。不同於需要 API 金鑰身分驗證的 [`--betas` 旗標](https://code.claude.com/docs/zh-TW/cli-reference#cli-flags)，此變數適用於所有驗證方式，包括 Claude.ai 訂閱 |
| `ANTHROPIC_CUSTOM_HEADERS` | 要加入請求的自訂標頭（`Name: Value` 格式，多個標頭以換行分隔）。若名稱或值包含 HTTP 標頭無法承載的字元，例如彎引號或零寬空格，請求會失敗，並顯示依位置識別該組名稱與值的錯誤。需要 Claude Code v2.1.227 或更新版本。[Invalid request header value](https://code.claude.com/docs/zh-TW/errors.md#invalid-request-header-value) 列出確切的字元集以及檢查執行的位置。若值設定的是憑證、組織或租用戶、路由或 API 行為相關的標頭，例如 `Authorization` 或 `Host`，當由伺服器受管設定傳遞時，它會被視為[需要核准的設定](https://code.claude.com/docs/zh-TW/server-managed-settings.md#environment-variables-and-the-approval-dialog)。若來自專案或本機設定，此類值會遵循[何時套用 `env` 值的規則](https://code.claude.com/docs/zh-TW/settings-reference#when-claude-code-applies-env-values) |
| `ANTHROPIC_CUSTOM_MODEL_OPTION` | 要在 `/model` 選擇器中新增為自訂項目的模型 ID。使用此變數可讓非標準或閘道專屬的模型可供選擇，而不需取代內建別名。請參閱[模型設定](https://code.claude.com/docs/zh-TW/model-config.md#add-a-custom-model-option) |

| `ANTHROPIC_DEFAULT_FABLE_MODEL` | `fable` 別名解析成的模型 ID，也是 Claude Code 在第三方提供者上為[自動模型備援](https://code.claude.com/docs/zh-TW/model-config.md#automatic-model-fallback)辨識為 Fable 模型的 ID。請參閱[模型設定](https://code.claude.com/docs/zh-TW/model-config.md#environment-variables) |
| `ANTHROPIC_DEFAULT_FABLE_MODEL_DESCRIPTION` | `/model` 選擇器中固定的 Fable 模型的顯示說明。未設定時，該列會顯示以 `Custom Fable model` 開頭的預設說明。請參閱[模型設定](https://code.claude.com/docs/zh-TW/model-config.md#customize-pinned-model-display-and-capabilities) |

## 子程序環境清除會移除哪些內容

當您將 [`CLAUDE_CODE_SUBPROCESS_ENV_SCRUB`](#variables) 設為 `1` 時，Claude Code 會從其啟動的子程序環境中移除憑證，例如 Bash 命令、hook 以及 stdio MCP 伺服器。這可減少提示詞注入攻擊所能讀取的內容。Claude Code 程序本身會保留這些憑證，以供其自身的 API 呼叫使用。

清除機制會依據變數名稱或其值的形式來辨識憑證，因此請將其作為一道防護層，搭配範圍狹窄的[權限規則](https://code.claude.com/docs/zh-TW/permissions.md)一起使用，而非當作唯一的控制手段。

下表說明清除機制對範例變數的處理方式：

| 範例變數 | 清除機制的處理方式 |
| :- | :- |
| `ANTHROPIC_API_KEY`、`AWS_SECRET_ACCESS_KEY` | 移除 |
| `NPM_TOKEN`、`DB_PASSWORD` | 移除，因為名稱看起來像憑證 |
| 包含密碼的 `DATABASE_URL` | 移除，因為值看起來像憑證 |
| 包含密碼的 `PIP_INDEX_URL` 或 `NPM_CONFIG_REGISTRY` | 保留 URL，但從中去除使用者名稱和密碼 |
| `CLAUDE_CONFIG_DIR` | 移除 |
| `GITHUB_TOKEN`、`GH_TOKEN`、`GH_ENTERPRISE_TOKEN`、`GITHUB_ENTERPRISE_TOKEN` | 保留原狀，讓 `gh` 以及呼叫 GitHub API 的指令碼能繼續運作 |
| `HTTP_PROXY`、`HTTPS_PROXY` | 保留原狀，包括 [URL 中的使用者名稱和密碼](https://code.claude.com/docs/zh-TW/network-config.md#basic-authentication)。[沙箱](https://code.claude.com/docs/zh-TW/sandboxing.md#network-isolation)可自行為沙箱中的命令設定這些變數 |
| `GIT_CONFIG_COUNT`、`GIT_CONFIG_KEY_<n>`、`GIT_CONFIG_VALUE_<n>` | 無論其內容為何，皆保留原狀 |
| 變數名稱和值看起來都不像憑證的機密 | 保留原狀 |

由於清除機制會保留 `GITHUB_TOKEN`，請僅授予 GitHub Actions 工作所需的最小 `permissions`。若要從沙箱中的 Bash 命令移除 GitHub token，請在 [`sandbox.credentials`](https://code.claude.com/docs/zh-TW/sandboxing#protect-credentials) 下新增一筆 `deny` 項目。

如果子程序需要其中某個會被移除的變數，請勿設定清除機制。

在 Linux 上，清除機制也會在隔離的 PID 命名空間中執行 Bash 子程序，使其無法透過 `/proc` 讀取主機程序的環境。其副作用是 `ps`、`pgrep` 和 `kill` 無法看到主機程序，也無法向其傳送訊號。

在 v2.1.251 之前，清除機制會移除 `ANTHROPIC_API_KEY` 和 `AWS_SECRET_ACCESS_KEY`，並保留表中其他範例變數不變。

## 需要擷取功能旗標的功能

Claude Code 會透過從 Anthropic 擷取的功能旗標來啟用部分功能。在下列工作階段中，Claude Code 會略過該擷取：

* 設定了 `DISABLE_GROWTHBOOK`、`DISABLE_TELEMETRY`、`DO_NOT_TRACK` 或 `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC` 的工作階段；[變數表](#variables)中每個變數的列會說明哪些值會關閉擷取
* 使用[第三方供應商](https://code.claude.com/docs/zh-TW/third-party-integrations.md)（例如 Amazon Bedrock、Claude Platform on AWS、Google Cloud 的 Agent Platform 或 Microsoft Foundry）的工作階段，除非嵌入 Claude Code 的主機平台設定了 `CLAUDE_CODE_PROVIDER_MANAGED_BY_HOST`
* [Claude apps 閘道](https://code.claude.com/docs/zh-TW/claude-apps-gateway)工作階段

關閉擷取時，您無法：

* 在設定了 `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC` 或 `DISABLE_GROWTHBOOK` 的情況下使用 [Remote Control](https://code.claude.com/docs/zh-TW/remote-control.md)。關於 `DISABLE_TELEMETRY` 和 `DO_NOT_TRACK`，請參閱 [Remote Control 需求](https://code.claude.com/docs/zh-TW/remote-control.md#requirements)
* 在 [Remote Control](https://code.claude.com/docs/zh-TW/remote-control.md#requirements) 無法使用時，[傳送訊息給此機器以外的工作階段](https://code.claude.com/docs/zh-TW/cross-session-messaging.md#message-sessions-on-other-machines)。關閉擷取時，此機器上工作階段之間的訊息傳送仍可運作
* 執行 [`claude import` 或 `/import` 命令](https://code.claude.com/docs/zh-TW/cli-reference#cli-commands)
* 執行 [`/skill-doctor`](https://code.claude.com/docs/zh-TW/skills#find-unused-skills)，或在 `/plugin` 的 **Stats** 分頁中開啟其報告
* 在 Pro、Max 和 Ultra 方案上執行 [`/restart`](https://code.claude.com/docs/zh-TW/commands)
* 將您的 claude.ai 帳戶所啟用的 [skills](https://code.claude.com/docs/zh-TW/skills.md#where-synced-skills-load) 和[外掛](https://code.claude.com/docs/zh-TW/plugins/loading.md#synced-plugins)同步到您的終端機工作階段
* 啟用 [You should know mod](https://code.claude.com/docs/zh-TW/interactive-mode.md#you-should-know-suggestions)
* 使用 [advisor 工具](https://code.claude.com/docs/zh-TW/advisor.md#requirements)
* 使用 [MCP tasks](https://code.claude.com/docs/zh-TW/mcp.md#mcp-tasks-that-run-on-the-server)
* 閱讀或回覆 [artifact 上的留言](https://code.claude.com/docs/zh-TW/artifacts.md#collect-comments-on-an-artifact)
* 讓 Claude 讀取[其他組織的公開 artifact](https://code.claude.com/docs/zh-TW/artifacts.md#read-an-artifact-shared-with-you)
* 在已安裝 Git Bash 的 Windows 上，為 claude.ai 和 Console 帳戶預設取得 [PowerShell 工具](https://code.claude.com/docs/zh-TW/tools-reference.md#powershell-tool)；除非您設定 `CLAUDE_CODE_USE_POWERSHELL_TOOL=1`，否則 Claude Code 會透過 Git Bash 執行 shell 命令。在未安裝 Git Bash 的 Windows 上，該工具會保持啟用
* 取得 [Claude 草擬的意見回饋](https://code.claude.com/docs/zh-TW/tools-reference.md#sendfeedback-tool-behavior)，Claude Code 是透過擷取的旗標來啟用此功能
* 讓 Claude [將大量貼上內容視為貼上的文字，而非輸入的文字](https://code.claude.com/docs/zh-TW/terminal-config.md#how-claude-treats-pasted-text)；`[Pasted text #N]` 預留位置背後的內容會未經標記地傳送給 Claude
* 讓 Claude Code [排除 API 會拒絕其輸入 schema 的 MCP 工具](https://code.claude.com/docs/zh-TW/mcp.md#tools-with-invalid-input-schemas)

### 安裝或升級後的第一個工作階段

在您安裝 Claude Code 後，或升級到新增某項功能的版本後的第一個工作階段中，[受旗標控管的功能](#features-that-need-feature-flag-fetching)可能不存在。當 Claude Code 在該工作階段中擷取其功能旗標時，會將其儲存在機器上，因此您在該機器上的下一個工作階段就會具備該功能。

在如下的設定中，第一個之後的工作階段也會在沒有新擷取旗標的情況下啟動：

* **每次執行都是乾淨的環境**：如果每次執行都在 CI 容器中啟動，或在任何沒有先前工作階段所儲存旗標的環境中啟動，則每次執行都是第一個工作階段
* **沒有 API 金鑰的閘道 token**：如果您使用 `ANTHROPIC_AUTH_TOKEN` 進行身分驗證且沒有 API 金鑰，而 `ANTHROPIC_BASE_URL` 指向 Anthropic 以外的主機（例如 [LLM 閘道](https://code.claude.com/docs/zh-TW/llm-gateway)），Claude Code 就沒有可用來擷取旗標的憑證
