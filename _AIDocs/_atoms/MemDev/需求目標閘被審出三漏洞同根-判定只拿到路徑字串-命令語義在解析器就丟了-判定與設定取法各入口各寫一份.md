## 知識

- [臨] 始末（v6 B 段合併候選經總控台 codex 審出 3 BLOCK＋1 WARN）：①沒樹時 `mv src pkg`（目的地還不存在）與 Write 新建沒副檔名的 `#!` 腳本漏過建樹閘 ②heredoc 本文裡的 `git commit` 範例觸發 commit_gate ③提問閘／批次／續接入口用不帶根的 `cfg_of(config)`，專案層開關失效 ④peer_offset 在鎖外算、鎖內寫，重疊掃描會倒退重送。修法：解析器帶出 cp／mv 來源（`wg_core.write_sources_from_tool`）＋ Write 內容，判定集中在 `wg_need_goal.writes_code`；commit 判定抽成 `_git_commits_to_run` 由 CommitOrder 與 commit_gate 共用；入口一律 `cfg_for_cwd(config, hook_cwd(...))`；整段掃描搬進 `update_locked`。
- [臨] 根因（四條同一個形狀：新問題重用舊介面，舊介面的輸入少了新問題要的資訊）：`write_paths_from_tool` 為 OverviewHub 設計，只回「寫到哪個路徑」（部位查表只要目的地），建樹閘拿它問「是不是改程式」→ 來源與內容在解析器就丟了；commit_gate 接線直接呼叫低階 `_git_commit_segments`，沒呼叫 CommitOrder 的「判定」（它先剝 heredoc），等於把判定複製了一份而且少一步；`cfg_of(config, root=None)` 的 root 是選填，省略時靜默只讀根層，入口各自取設定就各自忘帶；共用檔的「讀→算→寫」只把寫包在鎖裡。
- [臨] 運作邏輯斷點：PreToolUse 逐寫入目標呼叫 edit_gate(path) → is_code_path 只看副檔名與磁碟上的 shebang，目的地不存在或新檔還沒寫就判 False 放行。搬完之後 PostToolUse 的 stamp_edit 也只看路徑，目錄判 False，所以有樹時搬程式目錄不欠 (f1)、不要第四行（同根、待拍板）。
- [臨] 防再犯：①重用解析器結果回答新問題前，先列「這題要哪些輸入」對照解析器丟了什麼（來源、內容、heredoc、包裝）②共用的是「判定函式」不是它底下的小工具；兩處判同一件事就抽一支兩處呼叫 ③有「省略就靜默讀錯層」的選填參數，用 AST 案例禁止入口裸呼叫（verify_need_goal_points `test_need_goal_entries_resolve_config_by_cwd`）④共用檔游標類「讀→算→寫」整段放鎖裡，案例用 monkeypatch update_locked 在拿鎖前插入另一次完整掃描來重現交錯 ⑤規則變異照模組宣稱的每條規則列，沒紅就是案例缺。

## 行動

- 寫「是不是改程式／是不是 commit」類閘前，先檢查拿到的輸入有沒有被上游解析器削掉語義（來源、內容、heredoc）
- 新接線要和既有閘判同一件事 → 呼叫同一支判定函式，不直接拿它底下的 helper
- need_goal 設定在 hook 入口一律 cfg_for_cwd(config, hook_cwd(input_data, state))
- 共用狀態檔的游標在鎖內讀、算、寫，只允許前進
