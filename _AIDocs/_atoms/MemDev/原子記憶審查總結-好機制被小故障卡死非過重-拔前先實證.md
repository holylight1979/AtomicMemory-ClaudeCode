## 知識

- [臨] **核心判斷：好機制被小故障/陳年殘留卡死，非架構過重**。高強度審查自製記憶系統時常見病因：好機制被小故障/陳年殘留悄悄卡死、外圍為想像需求長枝葉，而非架構過重。正解＝誠實化 + 修剪，非推倒重來。
- [臨] **拔前先實證，避免誤刀**：死碼/「該拔」盤點的目標，逐一實證後常有相當比例改判不拔（別領域用/已 shim/復活基座/刻意保留的休眠軸）。機制存在≠實際會發生；斷「必爆/該拔」前先跑/查/追根源。**保留檔案本體 + 只停 wiring＝可逆復活基座**（config 改回即復原）。
- [臨] **always-load 是模範不是問題**：@import 鏈（IDENTITY+USER+MEMORY+rules/core）實務 ~2-2.5k tok（Anthropic 真 tokenizer 中文 ~1tok/字）。⚠ 系統兩內部估算器分歧大：flat len//4 偏低、CJK-aware 1.5tok/字 偏高（刻意保守供 budget）。校準 token/效能 doc 值時務必標明 tokenizer 口徑，兩估分歧時取真實開銷、勿把保守估當定值。
- [臨] **fail-open 被錯做成「不告知」＝最大信任債**：可觀測性鐵律——所有 fail-open 必「不阻斷但要告知」，降級/靜默失敗要浮出訊號（session_start 告警/stderr/收尾報告），不得無聲吞掉。反例：vector service 因缺 sys.path 靜默死數週無人知。
- [臨] **跨模型他評抓自評盲點**：第二意見模型（如 codex/GPT）在自評易漏處（handoff 自審升他審、完成證據缺漏）提供獨立視角；同理，行為漂移（如語言/版本殘留）用**程式化攔截勝過靠模型自律/instruction salience**。
- [臨] **併發執 P 靠檔案歸屬互斥**：多 session 共用工作樹時，各 session 只 stage 自己歸屬的檔案集（勿 git add -A），收尾 git status 變更集＝預期檔案集逐檔核對；平行 session 未提交檔明列避碰、不動。
- [臨] **重啟只換 stdio MCP、:3848 dashboard 靠孤兒清除**：改 server.js 需重啟 SOP（殺舊碼孤兒讓新實例重綁 :3848）；但平行 session 佔多實例、殺光會斷其 stdio MCP，且改動若無 live 消費者（純註解/孤兒 API）則不值破壞性 kill-all → 留待無平行 session 時 clean 重啟。
- [臨] **交付的 prompt/計畫是假說非真相**：prompt 可能與實碼不符（宣稱某機制已改、某表有某列）；動 doc/碼前先 grep 實碼對照，實碼與稱述不符以實碼為準、未證實先證再修、不照錯改。

## 行動

- 審查/重構自製記憶系統：先實證「機制實際會不會發生」再判拔留，斷『必爆/該拔』前跑/查/追根源；保留檔體+停 wiring 為可逆復活基座
- 校準 token/效能 doc 值：標明 tokenizer 口徑，兩估算器分歧時取真實開銷、勿把保守估當定值
- 所有 fail-open 必浮出降級訊號（告警/stderr/收尾報告），不得無聲吞掉
- 行為漂移用程式化攔截，不靠模型自律；動 doc/碼前 grep 實碼對照，prompt 不符以實碼為準
