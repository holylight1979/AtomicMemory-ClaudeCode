## 知識

- [臨] **核心結論**：22 子系統多鏡審 + codex 跨模型審後，骨架健康、方向正確。問題是「好機制被小故障 / 陳年殘留悄悄卡死 + 外圍為想像中的團隊 / 舊型 AI 長枝葉」，**非架構過重**。正解＝誠實化 + 修剪，非推倒重來。
- [臨] **拔前先實證，避免誤刀**：P2 死碼盤點「該拔」7 目標，逐檔實證後 5 個改判不拔（另一 session 領域 / 已 shim / per_turn 復活基座 / 刻意保留的休眠 OR 軸）——機制存在≠實際會發生；斷「必爆 / 該拔」前先跑 / 查 / 追根源。P5 保留 quick-extract.py 檔案本體＝復活基座（只停 hook wiring，config 改回 true 即復原）。
- [臨] **always-load 是模範不是問題**：@import 鏈（IDENTITY+USER+MEMORY+rules/core ≈5,553 字元）實務 ~2-2.5k tok（Anthropic 真 tokenizer 中文 ~1tok/字）。⚠ 系統兩內部估算器分歧大：flat len//4=1,387、CJK-aware 1.5tok/字=3,739（刻意保守供 budget）——舊 doc「3,200-5,400」取 CJK-aware 上界、非真實開銷。校準 doc 值時務必標明 tokenizer 口徑，勿把保守估當定值。
- [臨] **fail-open 被錯做成「不告知」＝最大信任債**：vector service 靜默死 26.7 天無人知（indexer.py 缺 sys.path）。可觀測性鐵律：所有 fail-open 必「不阻斷但要告知」，降級 / 靜默失敗要浮出訊號（session_start 告警 / stderr / 收尾報告），不得無聲吞掉。已補連續 no_flag 告警。
- [臨] **跨模型他評抓自評盲點**：codex（GPT）第二意見在自評易漏處（handoff 自審升他審、完成證據缺漏）提供獨立視角；lang_guard 亦同理——程式化攔截勝過靠模型自律 / instruction salience。
- [臨] **併發執 P 靠檔案歸屬互斥**：多 session 共用工作樹時，各 session 只 stage 自己歸屬的檔案集（勿 git add -A），收尾 git status 變更集＝預期檔案集逐檔核對；平行 session 未提交檔（如 skill-index / toolchain）明列避碰、不動。
- [臨] **重啟只換 stdio MCP、:3848 dashboard 靠孤兒清除**：改 server.js 需重啟 SOP（殺舊碼孤兒讓新實例重綁 :3848）；但平行 session 佔多實例、殺光會斷其 stdio MCP，且改動若無 live 消費者（純註解 / 孤兒 API）則不值破壞性 kill-all → 留待無平行 session 時 clean 重啟。
