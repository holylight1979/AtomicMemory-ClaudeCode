## 知識

- [臨] 「已不存在的程式檔不欠補案例」若靠解析每種搬檔寫法來記新路徑，codex 連四輪都找到下一種繞法（git mv → Rename-Item 具名＋位置參數 → 整個目錄改名 → 搬完又 commit 讓 status 變空）。收斂的做法是看結果：同根 git status（未追蹤、新增、改名、複製）與本 session 的提交都沒有新加進來的程式檔，才算刪除；否則照欠。同一面退回第二次就該改判定依據，不要繼續補解析器。
- [臨] commit 之後做反證（git checkout 退回舊版再還原）會被事件序記成「最後一次改碼」。帳本只有修改時間與 commit 回合時區分不出，要存可核對的內容基準：commit 時記本 session 改過的檔的內容雜湊＋當時不欠案例的程式檔；之後同根所有改過的檔內容都回到那一刻才豁免。快照要在記完同一條指令的寫入之後才拍（`sed -i a.py && git commit`）。
- [臨] 缺口（總控台 codex 審 041）：只比工作樹內容、不看暫存區 → 改碼 git add 後只還原工作樹就被豁免。任何「內容回到某狀態」的豁免都要同根相關檔 git status 乾淨（含暫存區），共用同一條件。
- [臨] 豁免只免 (d) 補案例，不延伸成「舊量測收據有效」；量尺閘照舊看所有改檔。刻意搬進 .gitignore 目錄、git stash -u 藏新檔、用 merge 帶進搬移，屬 WARN 級已知邊界。

## 行動

- 設計「某件事沒發生就豁免」的規則：先想能不能看結果狀態，而不是解析指令
- 內容比對型豁免一律連暫存區一起查
- 同一面被退回第二次就改判定依據
