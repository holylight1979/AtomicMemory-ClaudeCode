## 知識

- [臨] 兩層自動記憶：一般知識走品質閘全寫入、失敗加權深記。骨架永遠由 hook 自動寫（小模型填能填的），高 effort 時才加碼喚 Claude 深寫。三 stage：session_end flush（`extract-worker._session_end_writeback`）/ 失敗骨架（`extract-worker._failure_writeback`）/ Deep Post-Mortem Gate（`handlers/stop.py`）。**演化脈絡（落點路由 gap-fix、edit-count proxy 拔除、獨立預算）見 [DevHistory/auto-memory-writeback.md](../../DevHistory/auto-memory-writeback.md)。**
- [臨] Stage 1 session_end flush 落點路由（`_flush_route`）：專案 session（cwd 有 project root 且非 ~/.claude）→ scope=shared、落 `{project}/.claude/memory/shared/`（只該專案注入）；~/.claude / 無 root / 空 cwd → scope=global（防專案專屬知識污染 global core）。過品質閘、只清寫成功項、config `response_capture.session_end_flush.max_atoms`（預設 8）。auto-capture [臨] 草稿隔離落 `_drafts/auto-capture/`（`build_atom_content`+`write_raw`，被 sync-atom-index 排除 → 不入索引/不注入/不計數），防 content-as-filename 碎片污染 memory/ 根。見 [[auto-capture碎片sweep污染詞庫-defer根治]]
- [臨] Stage 2 失敗五區塊骨架：始末 / 根因 / 設計原理 / 運作邏輯 / 防再犯。`_build_failure_skeleton` 填始末、`_split_root_cause` 從「（根因: …）」尾段拆根因，餘三段留 `_FAILURE_TODO_MARK` 待補。`_failure_dedup_hit` 對新骨架始末行 + 舊「- [臨]」單行格式皆去重。
- [臨] Stage 3 Deep Post-Mortem Gate：`_should_deep_postmortem`（純判定）+ gate。觸發＝(effort：wisdom_retry_count>=2 ∨ fix_escalation_triggered) AND (真失敗：failing_tests 非空 ∨ evasion_flag ∨ not claims_done)。**effort 不採同檔 edit 次數**——未 failure-gate、對重度迭代開發本就超標（edit 次數 ≠ 失敗），必 AND 真失敗訊號才把「高 effort 成功」與「反覆修不好」分開（見 [[escalation-hook-在-edit-count-proxy-上-false-fire-的辨識無真實失敗迴圈時不盲從不編造]]）。一次性 `deep_postmortem_done`＝獨立預算（不與 Sync/Scan/TestFail 共用 `stop_gate_max_blocks`，否則會被先觸發的 gate 餓死）。config `deep_postmortem.enabled`。觸發即 output_block 指示 Claude 用 atom_write 補完整 post-mortem。
- [臨] Stop gate 注入機制＝output_block(reason)（wg_core：`{decision:block, reason}` + sys.exit），DPM gate 排在 correctness/sync gate 之後、以自身 one-shot flag 自限。
