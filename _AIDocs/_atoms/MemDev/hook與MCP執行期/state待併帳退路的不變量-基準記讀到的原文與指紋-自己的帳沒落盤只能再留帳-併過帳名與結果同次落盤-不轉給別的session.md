## 知識

- [臨] 拿不到 state 鎖時改留待併帳（只記跟基準比改了哪些鍵、改前、改後），下一支拿到鎖的行程併回；這條退路要守以下不變量。
- [臨] 寫回的基準記「讀那一刻的原文＋檔案指紋（mtime、大小）」；替別人併帳不能動這個基準。
- [臨] 留帳之後基準推進到這次的內容，同一支再寫只記之後的變動；自己的帳還沒全部落盤前，同一支 hook 只能再留帳，不准直接寫。
- [臨] 併過的帳名要跟合併結果同一次落盤（記在 state 裡），名單照「帳檔還在不在」修剪、不截固定筆數，刪不掉的帳下次跳過再刪、不套兩次；重建 state 時要把名單帶回去。
- [臨] 讀到檔不在＝空 state 基準，留的帳逐欄合併，不是「整份換掉」。
- [臨] 不要把帳轉給別的 session（例如合併轉址的目標）：基準不同，會算錯或整份蓋掉。各欄位怎麼併（含可歸零的計數）見三方合併那張卡。

## 行動

- 改待併帳或三方合併：先對照這幾條不變量寫交錯案例，再改碼
