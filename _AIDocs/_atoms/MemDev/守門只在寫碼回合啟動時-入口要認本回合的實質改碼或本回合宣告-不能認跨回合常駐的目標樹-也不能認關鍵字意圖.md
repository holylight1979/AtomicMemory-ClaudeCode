## 知識

- [臨] 判一個回合要不要跑 v6 守門，三層：① 本回合已用工具改程式檔（writes_code，含 .bat／.cmd 與判不出目標的寫入）最高位；② 還沒改碼前的入口是 LLM 本回合自己宣告（need_goal set／add／update 寫碼類樹）；③ 關鍵字意圖（classify_intent）只用來送提示與選卡，不當開關。
- [臨] 兩個會讓減量白做的錯法：「樹在就算」——目標樹跨回合常駐，整天掛著寫碼樹的 session 每回合都會被算成寫碼回合；「關鍵字就算」——使用者原話「要算的是啟動改 code 的行為、以及改 code 的工具，不然範圍會擴散」。判錯的代價：LLM 沒立樹就改碼，動手前守門晚到第一次改碼那刻，由 ① 補上。

## 行動

- 改 coding_turn 或任何「只在某類回合啟動」的判法前，先問：這個訊號會不會跨回合殘留？會就加「本回合」條件
