## 知識

- [臨] 使用者原話是「session 內的思考與參與討論，務必加派 codex」，我把它做成「CC 自己判斷叫不叫」的 skill，還加了排除條款「已查到答案只差使用者確認時不用」。乾淨無頭 session 實跑一題真實設計題：skill 有載入，AI 沒有叫，最後收在「要你決定的一件事」，等於排除條款給了不叫的理由；而它的結論正好帶著審查要抓的毛病。
- [臨] 判準：使用者說「務必」的流程，入場不能只靠 AI 讀 skill description 自己決定；要先把「哪類回合一定要叫」寫成使用者原話的範圍，再問使用者要用什麼去保證它發生。排除條款不可以覆蓋到「務必」的範圍。

## 行動

- 把使用者的「務必」轉成機制前：確認入場不是「AI 自己判斷」，排除條款不蓋到務必的範圍
- 新 skill 上線先用乾淨 session 驗「會不會自己叫」，再驗零件品質
