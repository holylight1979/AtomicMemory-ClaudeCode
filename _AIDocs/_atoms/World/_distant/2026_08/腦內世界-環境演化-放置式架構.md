## 知識

- [臨] 架構：world.html 為唯一推進引擎（開著就跑/關了暫停），免LLM 引擎(擴散/共識/dev累加/tier解鎖/鎖定/多風格/完工)＋LLM 僅2點(種子 envBrainstorm/定案 envDirection)；發展狀態鏡像於模組級 regionDev:Map、落盤 server `GET/POST /api/world-dev` → `workflow/world-dev.json`。
- [臨] ★零影響隔離鐵則：只**讀**生物個性，狀態只**寫** gitignore 的 world-dev.json，絕不碰 memory/ 樹、_atom_index.json、*.access.json、funnel/atom_write。結構性隔離＝獨立 API+獨立檔，server.js 既有碰記憶路徑一律不呼。驗收＝整段驅動後 `git status` 全空、memory 零 diff（這是核心驗收，非口頭保證）。
- [臨] envLlm fallback 鐵則：LLM(共用 chatBusy 序列鎖+ENV_LLM_MIN_GAP≈4s) 斷網/逾時/JSON 解析失敗一律 fallback＝純前端依個性投票選 family+目錄種子+罐頭台詞，**仍建 proposal/仍鎖定**永不阻塞。每區到 80% 約 2 次 LLM；fallback 命中可 0 次。fast 模式只加速免LLM 路徑，LLM 不加速（單張 3090 序列不成瓶頸）。
- [臨] crack 模型 JSON 解析：rdchat-direct 的 Gemma-4-31B-CRACK 會洩漏 `<|channel>thought<channel|>` 控制 token → 先 `cleanLine` 剝除再 `JSON.parse`，失敗用 `/\{[\s\S]*\}/` 抓第一個物件重試；回傳 family 須∈8 家族白名單否則 fallback。
- [臨] _visiting 接位移軸（守 reconcile-render 鐵律）：跨區串門子讓攜帶想法的生物 lerp 走向他區中心，**只動持久 el._x/_y、絕不改 c.region**，lerp 掛在 tick() 位移軸。覆轍同源：動畫/進行中暫態一律存持久 el / regionDev / 檔，絕不存每 5s 由 buildModel 重建的 model.c（存 c 會每 5s 彈回，見 [[reconcile-render-動畫狀態歸屬陷阱]]）。
- [臨] deterministic 渲染：`placeEnv` 用 seeded LCG(`hash32(region.key+"|"+element.id)`)＝禁 Math.random → 同 (region,element) 每次 render 必同位；同 pos 類用 element.id 字典序排，插入新元素不位移舊的。`el._envSig` 髒檢查 sig 沒變不碰 DOM。★建築垂直帶壓在房間上中段 0.12~0.55H：房間常比視窗高，原下段 0.58~0.92H 落視窗折線外+被底部生物擋 →「status 100% 卻看不到建築」的錯覺（建築其實都在、只是畫在視窗外）；別改回下段。驗證走 file:// 會被 Playwright 擋 → 改 `python -m http.server` 服 + **cache-buster query(?cb=) 強制重讀**（瀏覽器快取 world.html 會害你誤判沒生效）。
- [臨] 完工門檻＝每區首風格 rank1.dev≥80（次風格續長不影響）；活躍區＝該 region.list≥2（單/空生物區不發展、只留 tier-0 🔥 種子）。/loop 停止＝全部活躍區皆完工。fast 模式下近完工區數十秒即收斂。靜態伺服 :8899 須與 world.html 同層（catalog 走相對路徑、API 跨源打 :3848）。
- [臨] 活動驅動耦合（補強「RNG 與原子脫鉤」）：原 dev 累加純 RNG（env_chance/pair_chance）與原子行為脫鉤，只『跨區串門子』算行為驅動 → 使用者反映「推不動、只有串門子有遊戲性」。改後新增單一注入口 contributeEnv(el,量,原因)，每環節都接回原子：①同區兩原子對談每句注入 CHAT_DEV(3.5)×affinity，區內無提案則就地 seedProposal 播種（從零也靠對談長）②新原子活動 maybeBuild『蓋房子』低頻挑原子推『已定案、進行中』風格 bar、delta∈[-1,+2]、一旦開始最低 BUILD_FLOOR(1)、興趣檢定 random<affinity 才動手（🔨蓋/做壞了/先不蓋 三態氣泡）③el._envAffinity(0..1)＝每原子對發展環境的興趣，LLM 評定一次 + client-only 快取(不落盤、守零影響鐵則)、忙線/失敗走 affinityFallback 類別底值（architecture .9/workflow·decisions .8/toolchain·memory·atom .6/episodic .35）。RNG pair_chance 降為微量底噪(slow 0.05→0.025)＝活動為主＋閒置極慢爬。consensus＝真實參與的原子數；多風格仍受 STYLE2_GATE[60,80]+family 去重閘（不亂增生、循序長）。Playwright 實測：對談 seed→farm 提案 dev35.4/cons3、maybeBuild bar 守 floor、三態氣泡皆現、測後狀態還原。
- [臨] 活動驅動（使用者裁定「過度潦草」后收斂）：修「slow 卻很快、沒施工過程、看不到生物蓋房」三大缺口。①**dev 只靠可視的『蓋房子』推進**：engineTick 移除 RNG diffuse(pair_chance=0)；maybeBuild 挑一個進行中腦區 + affinity 加權選一隻原子 → 設 el._building 派它『走到工地』(stepBuild going→working→back、接在 tick() 位移軸)，到站才 applyBuild 推進：未完工風格 bar delta∈[-1,2] floor=已解鎖最高門檻(bar不低於已蓋的)、無風格但有提案→推進提案 dev(+PROP_BUILD_STEP)。②**對談不再加 dev**，contributeEnv 改為「只建立 consensus(記參與者)+無提案時播種」；define 仍需 consensus≥門檻(靠對談) + dev≥35(靠蓋)。這是關鍵：舊設計「對談加 dev」使熱鬧區(如 49 生物的 c--projects)人口越多越暴衝、slow 也 <10min；改為「全域蓋房子速率」控節後，節奏與人口無關(~20min/區 slow、Playwright 隔離實測)。③**施工可視**：collectEnvElements 在「有未完工風格 or 規劃提案」時加 🏗️吊車+🚧圍欄，dev→100 完工自動撤只剩成品地標。④順修稽核 bug：STYLE2_GATE 去上界(fast 單 tick 跨過窗口也能開第二風格)、regionDev 合併改「單調 max」(修舊分頁/idle 擋住 server 進度)、pruneProposals 不誤殺高進度提案、affinityCached(maybeBuild 選人不觸發 LLM 防灘爆並發池)。零影響鐵則仍守(只寫 regionDev→world-dev.json)。

## 行動

- 改 world-dev 系統前先確認：寫入只進 world-dev.json，驗收用 git status 證 memory 零 diff

- 動畫/進行中暫態存 el/regionDev/檔，絕不存 model.c
