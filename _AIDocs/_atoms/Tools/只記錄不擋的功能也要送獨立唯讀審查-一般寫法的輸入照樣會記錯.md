# 只記錄不擋的功能也要送獨立唯讀審查-一般寫法的輸入照樣會記錯

- Created-at: 2026-10-14

## 知識

- [臨] 實踩：一個「只記錄、不擋」的旗標（案例有沒有先紅後綠），自己寫的案例全綠，送 codex 唯讀審查仍抓出 3 個 BLOCK：長指令被截斷、指令裡先 cd 換目錄、路徑在引號裡含空白。都是一般寫法就會讓紀錄記錯，不是刻意構造的邊角。
- [臨] 判準：功能不擋人不代表錯了沒代價。紀錄會被後續的報告、對帳、晉升判定拿去用，記錯一樣帶歪結論；審查範圍看「輸出會不會被當事實引用」，不看「會不會擋」。
- [臨] 自寫案例容易只餵自己預想的輸入形狀（短指令、無引號、無 cd）；獨立審查者從上游真實資料的形狀（完整指令、工作目錄、各種引號）找反例，正好補自寫案例的盲區。

## 行動

- 寫完只記錄型的功能，照樣送一輪獨立唯讀審查；BLOCK 先重現成紅案例再修
- 自寫案例至少各放一個：超長輸入、含空白與引號的路徑、會改工作目錄的指令
