# v6.0 的代價：hook 全關對現況（題 B′ 各兩跑）

> 這份在說什麼：同一題寫程式任務，把 v6.0 的 hook（每次動作前後自動跑的守門與提醒程式）全部關掉，跟現在照常開著，各跑兩次，比多花多少 token、多等多久、換到哪幾條驗收條目、多出來的花在哪、哪些能交給開源免費模型。量測 2026-10-22，工作軌 track-v6-cost-measure（派工 001，裁定 #56、#60）。
> 讀數標記：**實測**＝帳上直接讀到的數；**推論**＝用規則換算、歸類或估計出來的數。

## 怎麼量的
- 題目：wave2 驗收題 B′（給 sales 專案加一個 by-product 子命令＋第二段開新 session 問「有什麼該注意的」）。受測模型 Opus 5.5，跑法與第五跑相同。
- 兩組：「全關」每次叫 claude 多帶一個設定把所有 hook 關掉；「現況」照常。CLAUDE.md、規則檔、記憶工具清單、模型設定兩組一樣，所以這裡量的是 **hook 與 hook 注入的代價**，不是整套記憶系統。
- 先用一句話的探針確認：全關時 transcript 沒有任何 hook 紀錄、資料根沒有任何留帳；同一支檢查在現況抓得到。
- 四跑交錯跑（全關→現況→全關→現況），每跑前重建乾淨的受測專案，四跑用同一份腳本快照。現況有一跑因 hook 被逾時砍掉而作廢重跑（附錄 C）。

## ⑤ 開源免費模型能不能替代
對照依據：選型報告實測，現役內網 gemma4:e4b 在「切入點判斷、有附判準卡」判對 78%、沒卡 52%；當 G15 文字評分裁判平衡準確率 0.64（亂猜 0.5）。也就是約兩成會判錯，只適合錯了也救得回來的工作。

- 填目標樹：更新進度與交付對照（④ 拆出約 44 萬）是照改動與收據寫的記帳，可交本地模型代寫、寫碼 AI 確認；寫樹根、加子目標（抓使用者真正要什麼）留給寫碼 AI。省回約 15% 是用這兩類呼叫的量估的。
- 定位三行：別人代寫等於沒綜觀；能省的是那 45 萬重讀——擋訊息裡的導讀卡與判準卡改成同一回合只送一次，不必換模型（另案）。
- 「省回」是指那幾次 Opus 呼叫不再發生，連帶它們重讀的上下文也省掉；換成本地模型的那部分要另付本地模型的時間（選型報告：內網 e4b 每題約 1 秒），而且約兩成會判錯，所以只挑錯了救得回來的記帳類。

## 讀數時要知道
- 牆鐘受同機負載影響：全關1 取樣時 CPU 最高 96%，現況重跑那次只有 8～20%（附錄 D）。所以秒數看大小，不要看小數點。
- 全關組的 AI 沒被要求寫目標樹、定位行，第一段第一回合只跑 7～12 輪；現況是 51～72 輪。代價大頭在這裡，不在 hook 程式本身（hook 本身只佔多等時間的約兩成）。
- 本題用無頭入口：第二意見（G9）在無頭模式不會觸發，表上只有它的 hook 執行時間；有觸發的題（C′）代價會更高。
- 現況第二段開場多一行 `[Realm] 已自動歸 local：<卡名>`（建環境帶了一張剛解除綁定的卡，第一段收尾被搬走），約 100 token，兩跑都有。

### F. 做法細節
- **hook 全關怎麼做**：hooks 只從使用者層設定（`~/.claude/settings.json`）來；`WG_CLAUDE_DIR` 換的是資料根，管不到 claude 讀哪份設定，所以在資料根放空設定不會生效。改成每次叫 claude 多帶 `--settings '{"disableAllHooks": true}'`（旗標層設定蓋過使用者層），live 設定不動。kit 的 `w2_run_all.py` 加 `--hooks-off` 旗標，回合紀錄記 `_meta.hooks`。
- **兩組不互相污染**：每跑前重建受測專案與資料根（含卡集清單）；四跑用同一份腳本快照（別軌在跑中改 live kit 不影響）；跑前確認受測專案的 auto-memory 空著；全關兩跑逐段核 hook 紀錄 0、留帳 0；live 的 settings、hooks、tools 雜湊前後相同，期間 live 只有記憶同步與兩份文件提交。
- **卡集**：跑中 live 新落 3 張講這組驗收本身或含洩題字樣的卡，快照一律排除（第一跑建環境時都還不存在），四跑帶的卡集一致。
- **歸類規則（④ 與 ② 的 token）**：每次模型呼叫（同一 message id 算一次）先看觸發它的是什麼——前面有擋訊息或收尾被擋，就整筆（輸入＋輸出）算給那個 hook；它在呼叫系統工具，就算給那個工具對應的項目；兩者都不是，就只算 hook 注入文字在這次呼叫裡被重讀的量。同一批平行工具裡有一個被擋，下一次呼叫就算回應它。兩組都照同一規則算，相減得多出量。
- **腳本**：[`b6_measure.py`](v6.0的代價-實測/b6_measure.py)（量測，尾行 `B6_MEASURE DONE`）、[`b6_verdicts.py`](v6.0的代價-實測/b6_verdicts.py)（8 張判分對照，尾行 `B6_VERDICTS DONE`）。

多出的 337% token 裡最大三塊是：AI 被提醒去填目標樹等系統工具（39%）、被擋重寫定位三行與重讀擋訊息（25%）、收尾被擋多跑的回合（17%，知識收割為主）；用免費模型能省回多出部分的約 33%。
