# 切入點自評：子代理共用說明（先讀完再動手）

## 背景（一段）
原子記憶系統（Claude Code 的 hooks＋記憶卡）有很多「程式停下來要 LLM 回一句判斷或宣告」的位置（＝切入點），例如 Stop 擋下要求寫「不做｜<事>：<理由>」。原設計者的觀點：程式只負責把 LLM 帶到那個位置、餵材料、問一句；LLM 那一刻判得準不準，取決於當下注入的卡（atom）。我們要逐點自評「任何 LLM 拿這些輸入判不判得準」，缺的判準卡列出來。

## 硬規矩
- 只讀不改：repo 是 worktree `C:\Users\holylight\.claude-wt\llm-entrypoint-selfreview`，所有讀取只用這個路徑。**不准讀或寫 `C:\Users\holylight\.claude\` 底下任何東西**，唯一例外是你的輸出目錄 `C:\Users\holylight\.claude\jobs\0bc6a843\tmp\`（只寫你自己那組的檔）。
- 不改 repo 任何檔、不跑 git 寫入指令、不跑 codex、不跑 pytest 全量、不呼叫 atom_write。
- 付費模型（Claude、Codex）不拿來當實測主力。實測主力＝內網免費模型 gemma4:e4b（192.168.199.130）。
- 每句標證據等級：〔實測〕跑過 gemma 拿到答案／〔讀碼〕看程式或文件得知（附 檔:行）／〔推論〕。

## 卡在什麼時候注入（已由主 session 讀碼確認，第④欄照這個查）
卡（atom）只在三個時點注入：(1) UserPromptSubmit：比對使用者原話（含同伴 session 訊息）的 trigger／BM25；(2) 派子代理時比對 Agent prompt；(3) OverviewHub：第一次碰某部位的檔時注入該部位的導讀卡。Stop 擋下、PreToolUse 拒絕那一刻**沒有**依擋訊息字樣注入卡的機制——除非你在發擋訊息的程式裡找到例外（找到就附 檔:行）。
所以第④欄寫兩件事：a) 那一刻實際注入幾張（通常 0，附讀碼根據）；b) worktree 的 `memory/**/*.md` 與 `_AIDocs/_atoms/**/*.md` 裡，Trigger 行對得上擋訊息關鍵字樣、跟這個判斷相關的卡（卡名＋命中的字）——這些是「有但送不到」的卡。用 Grep 搜 `Trigger:` 行。

## 真任務紀錄（第⑦欄評分要用）
只認 worktree 內這幾份：`_AIDocs/DevHistory/v6.0-寫程式碼的進化-2026-10/` 底下的 `第一波聯合驗收-結論.md`、`總控台裁定帳與誤判清冊.md`、`B5-需求目標效果驗收-結論.md`、`工作紀錄.md`、`G0-G16目標達成審.md`、`原設計者原話輯.md`。搜你負責的切入點字樣，看有沒有「真任務裡 LLM 在這個點判對／判錯」的紀錄。

## 每個切入點固定八欄（寫進你的 sections 檔）
```
### E<編號>　<切入點名>（<規則名或函式>；<G 或 T 編號>）
- **①餵什麼**：程式在那一刻餵 LLM 什麼（哪些欄位、大約多長、從哪來；附 檔:行）
- **②怎麼問**：擋訊息或提示原文，照抄（太長就抄關鍵段＋檔:行）
- **③期望判什麼**：LLM 該判斷的那件事，一句
- **④那一刻注入的卡**：a) 實際注入（通常 0，附根據）；b) 有但送不到的相關卡（卡名＋命中字）／無
- **⑤缺哪張卡／該退役哪張**：缺的判準是什麼（一句），或哪張卡過時該退役（卡名＋為什麼）
- **⑥任何 LLM 能否判準（實測）**：模型 gemma4:e4b、題目摘要、裸跑答案摘要＋判定、加卡後答案摘要＋判定、秒數、token
- **⑦介入自評 N／10**：判準三級——真任務裡判對過 7～10／只在案例（含 gemma 實測）裡判對 ≤6／沒驗或判錯過 ≤4；沒實測也沒真任務紀錄的最高 4
- **⑧該改輸入、改問法、還是改卡**：只選一個主因＋一句理由（不准提新閘；閘是最後選項，提了要寫為什麼卡教不會）
```

## 實測怎麼做（第⑥欄）
1. 每個切入點出 1 題（有餘力 2 題）：題目＝一個具體情境（你根據程式與真任務紀錄編的，要有明確的正確答案，最好帶一個「淺判斷會答錯」的陷阱）＋程式在那一刻實際會給的材料與擋訊息原文＋要 LLM 照格式回答。正確答案寫在你的 sections 檔，**不放進題目**。
2. 每題做兩個版本：`<id>-bare`（只有程式現況會給的材料）與 `<id>-card`（同題，前面加一段你提議的判準卡全文，格式照「## 知識」「## 行動」）。這是在驗「加卡能不能讓判斷變準」。
3. 題庫寫成 JSON：`C:\Users\holylight\.claude\jobs\0bc6a843\tmp\cases_<你的組>.json`，內容 `[{"id": "E07-bare", "prompt": "..."}, ...]`。
4. 跑：`python -X utf8 C:\Users\holylight\.claude\jobs\0bc6a843\tmp\llm_probe.py --cases <題庫> --out C:\Users\holylight\.claude\jobs\0bc6a843\tmp\results_<你的組>.jsonl`（預設 gemma4:e4b，內網；每題通常幾秒到一分鐘）。結果每行有 wall_s、prompt_tokens、answer_tokens、answer。
5. 自己對照正確答案判「判準／判錯／部分」，寫進第⑥欄（附秒數與 token）。gemma 答錯不是壞事，是證據。

## 卡的草稿（第⑤欄缺卡時）
寫進 `C:\Users\holylight\.claude\jobs\0bc6a843\tmp\cards_<你的組>.md`，每張：
```
#### 卡：<title（中文，句子式，說出判準本身）>
- 切入點：E<編號>
- domain：<Lv1 只能從這幾個選：版控｜工作流｜思考與決策｜驗證與實證｜設計通則｜行為契約｜CC與原子記憶契約｜文字與格式>
- triggers：<5～10 個，綁擋訊息的字樣，例「最該修」「不做｜」「拐彎判斷」>
- knowledge：<2～4 條，每條以 [臨] 開頭；寫判準＋一個反例；不寫版本敘事>
- actions：<1～3 條>
- 實測：加卡前後 gemma 答案有沒有變準（引用 results 的 id）
```
退役建議也寫在這檔，格式：`退役：<卡名>｜為什麼`。
