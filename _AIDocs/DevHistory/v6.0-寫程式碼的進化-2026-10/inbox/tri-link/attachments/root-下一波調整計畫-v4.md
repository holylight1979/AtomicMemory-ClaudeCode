# 下一波調整計畫：讓「用 CC＋原子記憶系統交 AI 寫程式」的人自動得到你要的那些東西（第 4 版：三邊輸入、三邊 Codex 審、兩專案四題回信全併；實作順序草案在第十二節，等你答第十一節三題才定）

> 給誰看：你。再來是接手做這波調整的根層 session。
> 這份在說什麼：上一波（三方討論、R4～R6）是「朝解決問題去驗」；這一波倒過來——把那一波**旁觀 AI 怎麼失手、怎麼才做對**吸收到的經驗，逐條變成記憶系統本身的機制（hook、MCP、atom 注入、分範圍萃取、品質變量），讓未來任何一個裝了 CC＋原子記憶系統的人、任何一個專案，AI 一接手就自然懂得怎麼思考判斷、怎麼深入、怎麼綜觀，不靠人提點。
> **範圍（你 2026-10-08 補述的原話拼的）**：本次改進**只限根基**——根層、專案層、公司層全域都能用的**帶變量規則**；**本次參與的兩個專案預設不再做任何進一步調整**（已做的擴欄、副本工具只當樣本與輸入）。根層負責吸收、理解、轉化，並定清楚未來根層與專案層各扮演什麼角色、根層要調什麼、開什麼變量給專案層、多專案的奇耙設定怎麼處理。兩個專案 session 是專案層視角；負責專案的程式人員受的開發教育不同，思路會不同，這是輸入的價值，不是要統一的東西。
> 讀法：每句後面標可靠度——【試過】【看程式知道】【推測】【大家同意】；「機制」欄寫的是提議，標「做了」的才是已存在。
> 名詞：**hook**＝CC 在每個動作前後自動跑的小程式；**MCP**＝CC 外掛的工具伺服器；**注入**＝把記憶卡片塞進 AI 的上下文；**萃取**＝從對話或程式裡把知識寫成卡片；**變量**＝腳本算得出的品質數字，或專案可覆蓋的設定值；**部位**＝專案裡一塊有自己邊界的東西，`overview-map.md` 一列一個；**導讀卡**＝每個部位一頁的「做什麼、上下游、動手前必問、已知病灶、驗法」；**ledger**＝驗證帳本，腳本每印一行 PASS／FAIL 就自動記一筆；**題組**＝固定輸入＋預核答案＋可重跑指令，量命中與誤報。

## 二、三邊共識的骨架（四樣基礎設施 × 五個過程數字 × 一層結果題組）

上一波靠人補了五張卡、一張表、三支檢查器才成立「有東西可看」【試過，SGI】；三邊各自寫完發現要補的不是更多規則，是四樣基礎設施【大家同意】：

| 基礎設施 | 一句白話 |
|---|---|
| ① 部位 profile 當一等公民 | `overview-map.md` 一列＝一個部位的檔案：卡、病灶文件、量尺、檢查器、讀路徑樣本、權威地圖、上下游、層、第四問；atom 加 `Part:` 欄（可多值） |
| ② 驗證紀錄有落點 | hook 自動收腳本哨兵進 ledger（根層固定落點）；專案既有的改動收據也算來源；收尾、審查者、下一 session 都看 ledger |
| ③ 教訓有歸宿 | 萃取時先問「下次會在哪個路徑再遇到」→ 有部位就進該部位**病灶文件**（根層給固定格式 `defects_schema`），卡只留一行指標；現況帳與清單一律文件 |

## 四、未來的角色分工

**根層（記憶系統本體）**
- 只做機制、格式、預設值、量尺、報表、閘，**並負責「產生與更新」的流程**（骨架、路由、健檢、回路）；專案只提供領域事實，不替機制補洞【Codex 根層：否則缺口又被專案補卡補表遮住】。不寫專案內容。
- 多專案差異靠變量吸收；但變量不是把沒設計好的執行、版本、作用域契約丟給使用者配置——每個變量要有預設可用、覆蓋有理由、歧義報錯【Codex 根層最懷疑第三件，採】。
- 每個機制出廠三件：verify 案、變量預設、一句「專案什麼情況該覆蓋」。
- 根層 session 日常＝看 scorecard 與回路、調預設、修閘；不派專案工。自己也走同一套（`_AIDocs/Architecture.md` 對應列＝導讀卡、三行放工具參數、哨兵進 ledger）；E2E 不碰專案 live log／ledger，寫進根層自己的導讀卡病灶段。

**專案層**
- 擁有並維護（提供事實）：profile 表、導讀卡、病灶文件、量尺與門檻、檢查器與 selftest 清單、實跑鏈、覆蓋值、題組、驗收規格。不改 hook／MCP。
- 專案 AI 未來每次改碼的自然流程（機制推著走）：碰部位（含文件與計畫檔）→ 判層 → 整卡／權威地圖＋候選池前 N 注入 → 定位三行放工具參數（含第二根因或「為什麼不存在」、或「待規格」）→ 改（產物路徑直接擋）→ 跑量法、檢查器、實跑鏈（先查 runtime_gate）→ 哨兵與收據自動進 ledger → 收尾帶證據級，「修好」「量了」分開對帳。
- 兩專案指出的「最容易回到修症狀」環節，機制怎麼接：跨 server 翻譯層只看到一半 handler（第四問）；存檔層沒查 SaveMode（第四問）；每輪只修當下炸的（同檔第二次 Edit 觸發）；框架無卡（無卡列注入上游病灶段）；紅字消失法（根因層兩問）；演出層補 if（第四問）；跑舊 DLL 誤判（熱更第四問）；建置紅燈改別人的檔（ledger 以本 session 動過的檔為準）；表控值直寫碼（`readonly_paths`＋規則）。

**公司層**
- 共用變量預設（svn、提交編碼、哨兵、fix 樣式）、共用工具卡、共用掃描器；M2 路由加 `org` 作用域（儲存、召回、隔離要定契約）；合併順序 **根層預設 < 公司層 < 專案層**。

## 八、部位 profile 的格式（`overview-map.md` 擴欄，不另立檔）
