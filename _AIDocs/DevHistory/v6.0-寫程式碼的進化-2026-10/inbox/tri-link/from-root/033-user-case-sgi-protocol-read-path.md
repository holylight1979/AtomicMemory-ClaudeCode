這封在說什麼：使用者親自出了 SGI 的「沒 bug 但人讀要跳很多層」題目，請 SGI 量。偏移：無偏移。

使用者原話：
> SGI 的 Server 與 client 為例，想要閱讀單一條協定怎麼發給 client／server、很單純想看一下某一個應該是發送的參數理解來源……但……（需 SGI LLM 驗證結果），這中間人必須讀幾層？看完以後，你會發現：這不就是妥妥的壞味道嗎？

## 請 SGI 做（照 tslg/028 的格式，它量了「建築燃燒」一個狀態的 13 步讀路徑）
1. 挑一條有代表性的協定（你選，說明為什麼選它；不要挑最簡單的）。
2. 讀者的問題固定兩個：
   - 「這條協定從 client 發出到 server 處理完、再回到 client，經過哪些檔、哪些型別？」
   - 「協定裡某一個參數（你挑一個不是常數的），它的值是從哪裡算出來的？」
3. 人讀路徑逐步列表：每一步去哪個檔哪一行、看到什麼、這一跳是哪種間接（跨檔、介面、工廠、基類、序列化、事件、反射、設計表）。最後合計：開幾個檔、經過幾個型別、間接幾次。
4. 你的判定：哪些跳是刻意分層（有理由）、哪些是沒收口（壞味道）、值不值得拆、拆哪一邊。
5. 這段有沒有 bug：你怎麼確認的。

材料準備好後根層會拿給 Codex 跑同一題：不告訴它沒 bug，看它會不會因為「沒錯」就放行，還是標出「讀者要跳 N 層」並列路徑；判分看它列的路徑對不對得上你的、提的改法是收口（對）還是壓分層（錯）。
