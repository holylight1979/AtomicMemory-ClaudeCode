## 二、解法（專案層我能做的先列；全部是提議，沒驗）

**專案層（記憶系統與文件範圍，不碰程式）**
1. 每個卡片 ≥15 張的範疇補一頁「部位導讀」卡，三段固定：這部位做什麼、上下游是誰、權威在哪／已知病灶（指向控制塔的 H 與踩坑卡）／最近驗證日期與怎麼驗。依卡片數順序：Server、合服、Client、Gameplay 四頁；CharDataBlob 56 張已退版，導讀只寫「退版原因與重啟讀法」一段指向 DevHistory README。
2. 每頁導讀填 `Depends: path:` 指向它描述的主要檔（Server → `MapServer/GameServer/GameServer.cs`、合服 → `ServerTools/Merge/Merge/Program.cs`…），健檢在檔消失時自動標 stale。這是「強制驗」最便宜的版本，只驗「指的東西還在」。
3. 把兩條住錯地方的教訓搬到該去的位置：「判資料存哪必先查 SaveMode＋DbServer 建表鏈」進控制塔 H-7 那一列與 Server 導讀的病灶段；`Log.Current` 那張卡今天已補 trigger（離線工具、測試程序、Assembly.LoadFrom）。
4. 給根層一張「路徑前綴 → 導讀卡」對照表，供第 5 點注入：`MapServer/Guild/`、`MapServer/Module/` → Server 導讀；`ServerTools/Merge/` → 合服導讀；`PlayerDbServer/`、`Shared/Proto/PlayerDbServer/` → CharData 退版導讀；`sgi_client/` → Client 導讀。
5. 三份當「定位第一行」來源的文件（`Server_Service_Directory.md`、`Business_Module_Directory.md`、控制塔）補「最後驗證」標記；控制塔已有日期，其他兩份沒有。

**根層（與 TSLG 第 4、5 點同一需求，不重提）**
AI 在一個 session 第一次編輯某前綴下的檔案時，整張注入該部位導讀並要求先寫定位三行；健檢對「範疇卡片 ≥N 張卻無導讀」出警告。

**沒有解的部分**
- 導讀內容對不對仍要人驗；`Depends:` 只驗「指的檔還在」。
- 根層 028 的 TSLG 案例一回放顯示「有沒有定位三行」沒差別，差別可能在「先讀完再動」。所以上面的解法要跟回放第二輪綁在一起驗：sgi 案例二回放時，B 組材料用「舊版文件＋新寫的 Server 導讀」，看它會不會先去查存檔模式。沒驗之前，這封全部是提議。
