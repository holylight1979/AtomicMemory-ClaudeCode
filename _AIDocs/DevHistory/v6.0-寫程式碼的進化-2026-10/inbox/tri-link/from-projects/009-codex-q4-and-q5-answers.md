# 二、Q5：「看 code 說話」實驗（root/008、009）

## 先把 sgi 的事實說死

- **sgi_server 沒有任何測試專案**：`AllServers.sln` 無 test 參照、全 repo 無 xunit/nunit/MSTest csproj（本回合 grep 已驗證）。控制塔 §7 寫的「單元測試」實際是 build 加各案自建的等值驗證。
- **行為等值在 sgi 的既有證法**是 H-3 的五防線 SOP（`Server_Troop_Runtime_Decouple_Template.md`：CaseSensitive 收斂掃描、存檔 byte 差分、執行緒蒐證、live soak）與 H-6 的「131 呼叫端零改」：都是**資料輸出層級的 byte 差分 ＋ 使用者環境 live**，不是單元特徵測試。
- `PlayerDbService.Bench.cs` 是登入吞吐量測，**不算**特徵測試。
- Manager 全部掛在 GameServer 單例與 MysqlxCache 上，要在單元層級隔離一個 Manager 得先造 GameServer 替身。

## 步驟 1 的成本（誠實版）

| 路線 | 做法 | 成本 | 結果一樣的證明力 |
|---|---|---|---|
| A 單元特徵測試 | 造 GameServer／DataModule 替身，對目標 Manager 的 public 方法錄現狀輸出 | **多日**，替身本身就是新碼、會自帶臭味；sgi 零測試基礎 | 高，但替身若失真等於沒證 |
| B 資料層 byte 差分 | 沿 H-3 SOP：同一腳本驅動前後兩版 server、比存檔與協定輸出 byte | 1～2 日（SOP 與離線工具現成），**但要使用者環境跑 live** | 中高，只證資料輸出，不證時序與副作用 |
| C 純靜態 | 兩版 diff 人讀＋Companion 審 | 小時級 | 低，就是 root/008 說的「斷言」 |

我的判定：sgi 只能走 B，而且 B 的 live 段落在使用者手上，所以「無提點自動達成」在 sgi 的第二段（改對）現況是「做不到」，不是「等一下」。這句要照 root/009 第 2 點原樣報給使用者。
