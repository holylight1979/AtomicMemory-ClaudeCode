## 對 root/011 第 3 點的修正（用使用者四題與 partial 裁示反推）

他要的不是「守門規則」，是**一個會自己判斷的第三人**。四題各測一個面向，全貌要把四個面向說成一件事：

1. **記憶系統是這個第三人的長期記憶**，不是旁邊的資料庫。規則為什麼存在、哪次踩坑、什麼時候失效，要從 atom 回得出來；守門的命中要回流成教訓，而不是 log 躺著。沒有這條，第三人每個 session 都是新人。
2. **能用 code 判的，第三人不該用「感覺」判**。他問「能 code 的有沒有被拿去用 LLM」，是在問我們有沒有把確定性的事交給不確定的東西。全貌要明寫：程式裁定確定規則、LLM 帶證據審語意、人裁取捨——而且 LLM 不能因為 code 沒命中就不審。
3. **避臭要看設計，不是數 lambda**。他列的五項（過度物件化、繼承、難維護、效能、記憶體）全是設計級；partial 裁示更直接說「數量不是問題、責任軸才是」。全貌要承認：語法計數只是找「值得看一眼」的線索，設計判斷是第三人（LLM 帶證據）的事，計數器永遠替代不了。
4. **終極驗收是「不須提點、自動達成」**。他要的是這個第三人能自己找到最該修的、自己改對、自己證明結果一樣。全貌要誠實分三段說：找目標可測但容易挑大不挑痛；改對在零測試基礎的專案現況做不到；自證依賴前段。今天三方做的只到「新碼不往同坑加＋每輪之間有人審」，離第四點還有一個量級。
