# B5：需求目標流程（need_goal）效果驗收——結論

> 這份是什麼：B5 用五題沒有預填答案的新任務，驗「每個需求先抓目標、關鍵處對照」的骨架有沒有真的讓 AI 做得更好。只寫結論，不寫題目答案、隱藏檢查與陷阱內容（重跑時會失效）。讀者：之後恢復 v6、要重跑 B5 的人。
> 2026-10-14 實測，調度總控台彙整觀察表，原設計者與 Codex 各自判分。

## 一、怎麼測
- 每題兩組同時跑：受測組 need_goal 開、對照組關（開關放在資料根設定，專案檔完全相同，受測者看不出差別）。
- 題句由原設計者在受測分頁親手打；總控台不送任何訊息給受測分頁（同伴訊息不算使用者原話）。
- 每題有隱藏檢查與一個盲陷阱；題三有中途糾正、題五有中途換手（/handoff → 新 session /continue）。
- 工具組（題目、答案、建置與收集腳本、上次的原始材料）只放本機 `workflow/inbox/b5-kit/`，不進 repo：裡面有答案，放進公開 repo 等於洩題。

## 二、五題結論
| 題 | 在驗什麼 | 結論 |
|---|---|---|
| q1 | 單檔小改動 | 流程生效：改程式前沒樹就擋、收尾拒掉過期收據、完整對照落檔，零誤擋。效果持平：題目太小，兩組一開始就全讀；受測組懂了但沒把子目標寫進樹 |
| q2 | 藏著三個子目標、碰到使用者真資料 | 受測組一次都沒被擋（讀檔前就先建樹，比 q1 進步），零誤擋。三個子目標兩組都顧到、結果同等；受測組仍只有一個節點 |
| q3 | 中途糾正 | 糾正句打下後 11 秒內動了樹，之後定位第四行都指到新節點（對照組沒有）。但改樹走的是「開新題」而不是「改寫樹根附理由」，舊目標沒標放棄；結果持平 |
| q4 | 純文件整併（知識類） | need_goal 對知識類零擋、零要求，符合「純文件不該擋」。受測組沒建樹，「知識類也要一棵輕樹＋收尾對照」沒做到。結果持平 |
| q5 | 跨 session 換手 | 目標樹跨 session 接走成功：續接單帶樹、新 session 匯入後沿用原節點與歷史、只做前一個 session 寫明還缺的兩件、用自己的收據收尾；但匯入要手動 `import_from`，不是讀到就自動。對照組續接單沒落地，新 session 靠 git diff 重建任務、等人回答近 5 分鐘。結果持平 |

**總評**：流程生效、零誤擋、效果與對照組持平（兩組隱藏檢查全過、盲陷阱都沒踩）。流程有接上的地方（q3 糾正後動樹、q5 換手接走樹）是對照組做不到的；但「讓結果變好」這五題還量不出來。

## 三、三條效果缺口（C 項規格輸入）
1. **子目標長不成節點**（q1～q3）：AI 懂了有哪些子目標，但樹上永遠只有一個節點。q5 修後 smoke 又看到同一族：使用者一句話要兩件事、說「這回合先做第一件」，樹根只寫第一件，第二件沒進樹——把「這回合範圍」當成「需求目標」。
2. **糾正時開新樹、舊樹不收**（q3）：工具上「改題」與「開新題」兩條路都開著，AI 挑了成本低的那條。
3. **知識類不建樹**（q4）：提示只有一次，AI 判斷純文件就不開樹。

這三條就是 checklist 第三節「恢復時從這裡開始」的第 1、2 步；做完再重跑 q2、q3、q4。
