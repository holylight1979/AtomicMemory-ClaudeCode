## Context
預計畫（`_AIDocs/DevHistory/v6.0-寫程式碼的進化-2026-10/預計畫-原子記憶系統根基調整.md`）已由原設計者認可：目標 G0～G16、核心模型（分片＋視角＋目的加權）、每目標補什麼怎麼驗、判層與角色、並行軌道。本計畫把它展開成可執行的步驟（三個 Explore agent 唯讀盤點＋三個 Plan agent 設計＋總控台裁決）。執行模型由原設計者定：**多個獨立 Claude Code session 併發實作，本 session 當總控台**；分段用「執P」：每段一個 session、驗證綠、上版、給下一段 prompt。

## 一、併發執行模型（總控台＝本 session）
- **工作 session**：每段一個，在自己的 git worktree `C:\Users\holylight\.claude-wt\<track>`（分支 `v6/<track>`，從 main 開）改碼、寫 verify、只跑目標 verify；不碰 live `~/.claude`、不 atom_write、不 commit main、不 push、不自己叫 codex。做完寄信 `~/.claude/workflow/v6-inbox/from-<track>/NNN-slug.md`。
- **總控台**：寫派工 prompt（六段）、掛 Monitor 收信、對帳、第二意見、merge 到 main、live 全量驗證、commit／push、共用檔與文件同步、atom 真寫、開關 worktree。
- **為什麼 worktree**：hooks 是 live python，直接改會在改到一半時打壞所有 session；worktree 讓 live 只在 merge 點變動。
- **三個盤點出的代價**（派工 prompt 都要寫）：①`wg_core.py:40` 把 live 的 `~/.claude/lib` insert(0)，worktree 內的 verify 可能測到 live lib → track-0 第一件事加 `WG_CLAUDE_DIR` 環境變數覆蓋，未設時行為不變；②worktree 被判專案層（有 .git／_AIDocs），MemDev 卡不注入、hook 會在 worktree 造 `.claude/`、Stop 閘會要 harvest → prompt 明列必讀絕對路徑、`items=[]` 回報、清 worktree 用 `--force`；③MCP 的 `paths.js` 與 `~/.claude.json` 指 live，js↔py 跨改只能 merge 後開新 session 驗。
- **檔案所有權**：同一檔只屬一段；共用檔（settings.json、workflow/config.json、.gitignore、version.json、_CHANGELOG、Architecture、TECH、_MAP、DocIndex、索引、MEMORY.md、根層表）只由總控台在合併時改。

## 四、總控台流程
**一次性準備**：建 `workflow/v6-inbox/{from,to}-<track>/`＋gitignore；`.gitignore` 加 `!.claude/overview-map.md`（在 `.claude/` 規則之後）；掛 Monitor（列 from-*/ 新檔）；`git worktree add C:\Users\holylight\.claude-wt\<track> -b v6/<track> main`；在該目錄開新 session 貼 prompt。
**每封 done 信**：①對帳（hash、檔集 ⊆ 所有權、無共用檔、無 `.claude/` 垃圾）→②退避 grep（零命中）→③`git -C <wt> merge main`（衝突只許在自家檔）→④在 worktree 複跑目標 verify 比對原文→⑤第二意見（M3 未就緒：總控台用 PowerShell 跑 `codex exec -m gpt-6-astra -s read-only -C <wt> --ephemeral --skip-git-repo-check -o <reply>`，前後 `git status` 比對；就緒後由專用審查 session 用 `second_opinion_start/result`；BLOCK 必親自重現才退回）→⑥live `git status --porcelain --untracked-files=no` 空→⑦`merge --no-ff v6/<track>`，記 ORIG_HEAD→⑧共用檔改動單獨 commit→⑨全量：`python -X utf8 run_verify.py`、`node tools/workflow-guardian-mcp/verify/smoke_mcp_stdio.js`、`python tools/install.py --verify`、`python tools/sync-memory-index.py --check`、`python hooks/verify/verify_lf_writes.py`→⑩改了 js 的段：開新 session 跑信中三句→⑪push→⑫`to-<track>/NNN-merged.md`，開依賴它的下一段→⑬清 worktree（`branch --merged` 確認→`worktree remove --force`→`branch -d`→`worktree prune`）。
**退回**：live 無其他 commit → `reset --hard ORIG_HEAD`；其間 vcs-sync 已提交記憶 → `revert -m 1 <merge>`；既有 verify 被改壞 → 退回該軌並例外允許它跑全量；兩軌各綠合起來紅 → 總控台開 `v6/fix-merge-<a>-<b>` 修介面；退回後通知各工作 session 重開（hook 是 live）。
**合併順序**：P1 三軌任意；P2 四軌全部寄信前不 merge 任一（避免 live hook 中途變動打到其他三個），或 merge 後立即通知重開；P3 等 a1、b、c；P4 總控台自己做。
