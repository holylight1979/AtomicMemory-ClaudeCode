## 結論先講

- **最急的是一個安全落差**：Codex 不在時接手的 headless 裁判（`claude -p`），文件說「工具面只留唯讀」，實測卻拿得到 `atom_write`／`atom_retire`、artifact 發佈與刪除、Excel 寫入、桌面操控、Playwright、`CronCreate`、`RemoteTrigger` 等，開場還連上 6 個 MCP server。改成「白名單三個唯讀工具＋不連 MCP」兩個旗標就收斂，已實測可行（P1）。
- **第二是量尺**：官方偵錯日誌現在每支 hook 指令都記實際耗時。實測即使 hook 在裁判模式下幾乎什麼都不做，每支 Python hook 光啟動就要 **330–480 ms**，`user-init.sh` 要 **1,021 ms**；這段時間我們自己的 hook 計時帳完全看不到。TECH §8「不採 OTEL」的三個前提，有兩個已被官方新欄位推翻一半（P2）。
- **plugin 整包封裝不建議**：常駐指示（CLAUDE.md `@import`、`rules/`）、`statusLine`、權限、git 同步的記憶資料都裝不進 plugin，MCP 工具名還會全部改名；有用的是兩個「小包裝」：skills 目錄 plugin 當 mod 的載體（P9）、臨時 plugin 當 skill 觸發評測的殼（P8）。
- 提案 11 張：A 1、B 6、C 2、D 2。

### P1. 裁判子 session 改用工具白名單、不連 MCP（現在的黑名單已漏光）
- 官方機制：`--tools`（只開列出的內建工具）、`--strict-mcp-config`（只用 `--mcp-config` 給的 server，不帶就一個都不連）、`--disallowedTools "mcp__*"`、`ENABLE_CLAUDEAI_MCP_SERVERS=false`／`disableClaudeAiConnectors`（不載 claude.ai 帳號帶來的連接器）（頁：[cli-reference](../../../ClaudeCodeInternals/Docs/06-reference/cli-reference.md) CLI 旗標表、[mcp](../../../ClaudeCodeInternals/Docs/02-build/mcp.md)「停用 claude.ai connectors」）。版本：現行文件；本機 2.1.311 實測可用。
- 現況：[`tools/codex-companion/judge_backend.py`](../../../../tools/codex-companion/judge_backend.py) `run_claude_judge` 起 `claude -p --model sonnet --permission-mode bypassPermissions --disallowed-tools "Bash,Write,Edit,NotebookEdit,Task,WebFetch,WebSearch"`，docstring 寫「工具面只留唯讀……裁判不得改動受審的東西」。使用者設定照常載入，所以 MCP server 與 claude.ai 連接器全部跟著進來。
  - 探針 1 實測 `init.tools` 含：`mcp__workflow-guardian__atom_write／atom_move／atom_retire／atom_edit_meta／atom_promote`、`mcp__claude-artifacts__publish_version／delete_artifact`、`mcp__claude_ai_Claude_Docs__create／update／delete`、`mcp__excel__excel_write_to_sheet`、`mcp__MCPControl__computer`、`mcp__playwright__browser_run_code_unsafe`、`CronCreate`、`RemoteTrigger`、`Workflow`、`SendMessage`、`EnterWorktree`、`Skill`；`init.mcp_servers` 6 個全部 connected。`Bash`、`PowerShell`、`Agent` 沒出現（黑名單這幾項有效）。
- 落差／機會：黑名單跟不上官方工具集的成長（claude.ai 連接器、排程、Workflow 都是後來才有的）。受審材料（diff、程式碼）裡若夾帶指令，裁判有能力寫記憶卡、發佈網頁、操作桌面。原生白名單一條旗標就把工具面收成三個，順便省掉 6 個 MCP server 的啟動。
- 做法（直接換用原生）：`run_claude_judge` 的指令把 `--disallowed-tools …` 換成 `--tools "Read,Grep,Glob"`＋`--strict-mcp-config`，env 加 `ENABLE_CLAUDEAI_MCP_SERVERS=false`；`--disallowedTools "mcp__*"` 可留作保險。`CLAUDE_COMPANION_JUDGE` 與 [`hooks/dispatcher.py`](../../../../hooks/dispatcher.py) 的 `JUDGE_HANDLERS` 不動（裁判的寫碼查核帳仍靠它）。只剩唯讀工具後，`--permission-mode bypassPermissions` 可一併拿掉（選做）。
- 代價與風險：若裁判提示詞依賴 `ToolSearch`／`Skill` 等其他工具會失去它們（現行裁判材料走 stdin、只需讀檔，推論不受影響）。Windows：Glob／Grep 本來就在 Windows 預設集內，明列無副作用。版本：無新門檻。可觀測性不變。
- 驗法：探針 3 已實測：`init.tools` = `Glob, Grep, Read`、`mcp_servers` 空、回覆正常（`duration_ms=2582`）。落地後跑 [`tools/codex-companion/verify/verify_judge_backend.py`](../../../../tools/codex-companion/verify/verify_judge_backend.py)，再加一個案例斷言指令列含 `--tools` 與 `--strict-mcp-config`；需要時重跑探針 3 比對工具清單。
- 分級：**C**（官方工具集變大，讓我們的黑名單失效）

### P2. 用官方偵錯日誌量每支 hook 的真實耗時（含 Python 啟動），並更新「不採 OTEL」的理由
- 官方機制：
  - 偵錯日誌（`claude --debug-file <path>`，或 `--debug` 寫到 `~/.claude/debug/<id>.txt`）每支指令 hook 結束留一行 `Hooks: <事件>:<比對值> [<指令>] finished with status 0 (<N>ms)`，需 **v2.1.296+**（頁：[hooks](../../../ClaudeCodeInternals/Docs/06-reference/hooks.md)「偵錯 hooks」）。同一事件的符合 hook **平行執行**（同頁：「事件觸發時，其所有符合的 hook 會平行執行」），所以事件牆鐘≈最慢那支。
  - OTel（OpenTelemetry，官方的遙測匯出格式）事件 `claude_code.hook_execution_complete` 有 `total_duration_ms`；**v2.1.280+** 加了 `additional_context_chars`、`stdout_chars`、`num_outputs_persisted`（hook 輸出超過 10,000 字元被改存成檔案的次數）（頁：[monitoring-usage](../../../ClaudeCodeInternals/Docs/04-administration/monitoring-usage.md)「Hook 執行完成事件」）。
- 現況：[`hooks/wg_hook_timing.py`](../../../../hooks/wg_hook_timing.py) 只在寫碼守門開時記 dispatcher 內部分段（`Logs/guard-hook_timing.jsonl`），從 Python 已經跑起來之後才開始算；[TECH §8](../../../../TECH.md) 寫「為什麼不採 OTEL：官方 export 沒有 per-hook 延遲、api_request 無法把注入 token 稅歸因到個別來源，且需常駐 collector」；[TECH §11.2](../../../../TECH.md) 只量主 hook 牆鐘。
  - 探針 2 實測（裁判模式：dispatcher 讀完 stdin 就早退，所以這是「底價」）：SessionStart 四支 474／480／479／**1,021** ms（最慢的是經 `run-bash-hidden.py` 轉跑的 `user-init.sh`）；UserPromptSubmit 兩支 332／383 ms；Stop 三支 369／386／482 ms。
- 落差／機會：每支 Python hook 單是起直譯器＋`runpy`＋import 就約 0.33–0.48 秒，每次 Bash 工具呼叫前後各一個事件、每個事件 2～3 支，這段時間我們的計時帳看不到，也就無從判斷「合併 hook 指令」值不值得做。TECH §8 第一個前提（沒有 per-hook 延遲）已不成立；第二個（注入歸因）官方現在有「每個 hook 回了多少字元」，只差細到每張卡；第三個（要常駐 collector）可以讓已常駐的 `:3848` 收 OTLP http/json 解掉，但那是第二步。
- 做法（接上新能力）：
  1. 加一支唯讀量尺（放 `tools/`）：讀指定的偵錯日誌，依「事件＋指令」分組列中位數與最大值，尾行 `HOOK_WALLCLOCK DONE events=<n> slowest_ms=<n>`。量法兩種：互動 session 偶爾用 `claude --debug-file` 開；或固定的 `claude -p --debug-file` 極短探針（同探針 2，可放進週健檢）。
  2. 改寫 TECH §8「為什麼不採 OTEL」那段，寫成現況：哪兩項官方已補、哪項仍缺、目前改用偵錯日誌的理由。
  3. 量到的數字交給 hooks 面向判斷（同事件多支指令合併成一支、改 exec 形式 `args` 省一層 shell）——不在本檔範圍。
- 代價與風險：零 token；`--debug` 日誌會變大（受 `cleanupPeriodDays` 清掃）；偵錯日誌行格式不是正式契約，量尺遇到認不出的行要出訊號、不可靜默跳過。多機：每台都要 ≥2.1.296。OTel 路線若走，`OTEL_LOG_*` 內容旗標一律不開（避免提示詞與工具內容外送），並記取 Codex 那次 OTEL 日誌暴量的教訓。
- 驗法：重跑探針 2 應得到同量級數字；同一場 session 守門開時，拿量尺結果對 `guard-hook_timing.jsonl` 的同事件分段，差值就是「行程啟動＋import」成本；量尺本身用一份固定的假日誌當案例。
- 分級：**B**（新能力補可觀測缺口；內含一處 TECH 文件更正）

### P3. 家目錄的 `AGENTS.md`（寫給 Codex 的）被 Claude Code 當專案指示載入
- 官方機制：v2.1.277 起 Claude Code 直接讀 `AGENTS.md`，由內建 mod `cc-plugin-agents-md` 負責（v2.1.285 前 ID 是 `agents-md@builtin`）；預設規則是「工作目錄或其上方沒有 `CLAUDE.md`／`CLAUDE.local.md` 時讀 `AGENTS.md`」，而且 **`~/.claude/CLAUDE.md` 不計入**；可用 `/config` 的「專案指示」或 `pluginConfigs."cc-plugin-agents-md@builtin".options.instructionFiles`（只認使用者層、`--settings`、受管層）調整（頁：[memory](../../../ClaudeCodeInternals/Docs/01-getting-started/memory.md)「AGENTS.md」「選擇要載入的指示檔案」、[mods overview](../../../ClaudeCodeInternals/Docs/03-plugins/plugins__mods__overview.md)「內建於 Claude Code 的 Mods」；TIMELINE v2.1.277）。
- 現況：[`_現況對帳` §2.3](../../../ClaudeCodeInternals/Docs/_現況對帳-原子記憶系統用到的CC機制.md) 已記「家目錄 `C:/Users/holylight/AGENTS.md`（給 Codex 用）在 cwd 位於家目錄底下時，會被當成上層專案指令載入」；本 session 的 context 也看得到它被標成 project instructions。內容是 Codex 版的舊說明（「通用工作流引擎（原子記憶 V4.1）」「專業規則已模組化至 `.Codex/rules/`」），開頭 `@IDENTITY.md @USER.md @memory/MEMORY.md` 是相對家目錄的匯入，家目錄沒有這些檔（匯入是否靜默失敗未逐一驗證）。
- 落差／機會：每場 `~/.claude` session（以及任何放在家目錄底下、沒有自己 CLAUDE.md 的專案）都多一段過時、跟 `rules/core.md` 敘述矛盾的指示。token 不多，問題在指示被汙染。
- 做法（改寫法避衝突）：先確認 Codex 還需不需要家目錄這一份（查 [`skills/codex/`](../../../../skills/codex/) 的同步包與 [`tools/codex-call.py`](../../../../tools/codex-call.py) 是否依賴）。不需要 → 請使用者把它移出家目錄（檔案不在 repo，是使用者自己的檔）；需要 → 在版控的 [`settings.json`](../../../../settings.json) 設 `pluginConfigs."cc-plugin-agents-md@builtin".options.instructionFiles = "claude-md"`。推薦前者，因為後者會讓所有「只有 AGENTS.md」的專案也讀不到。
- 代價與風險：後者的副作用如上；前者零代價。Windows 無特別限制。
- 驗法：在 `~/.claude` 開新 session，開場不再出現 `AGENTS.md loaded` 一行；`/context` 的記憶檔清單沒有 `C:/Users/holylight/AGENTS.md`。
- 分級：**C**（官方開始讀 AGENTS.md，踩到我們留給 Codex 的檔）

### P4. 把官方三件健檢接進週健檢與改版後流程：`/skill-doctor`、`/doctor prompt-audit`、`/context`
- 官方機制：

- 做法（接上新能力）：
  1. 週健檢加一步 `claude -p "/skill-doctor"`，文字存進 `workflow/health-reports/`，從沒被叫過的模型可叫 skill 進黃燈。
  2. Claude Code 大版本升級後（或每季）手動跑一次 `/doctor prompt-audit`，發現寫進 `memory/_staging/`，不自動套用；改之前對照 [`memory/_meta/always-load-contracts.json`](../../../../memory/_meta/always-load-contracts.json)（必載句子不准被它刪）。
  3. TECH §11.1 的估算表每次大改版用 `/context` 實數刷新一次，表頭註明量測版本。
- 代價與風險：`/skill-doctor` 需要「功能旗標擷取」（直連 Anthropic 時預設有）；`prompt-audit` 會花一次模型審查，且可能建議改掉使用者刻意的寫法（繁中、命令句），所以只當建議。`-p` 跑 `/skill-doctor` 仍會觸發整套 hook（一般 session 的成本）。

### P5. 自寫 MCP server 加上 server `instructions`，給沒有 hook 的客戶端指路
- 官方機制：MCP server 的 `instructions` 在 session 開始時就載入，**即使工具被工具搜尋延遲也一樣**（「只有工具名稱和伺服器指令在工作階段開始時載入」）；上限 **4,096** 字元（v2.1.296 起，之前 2,048），經工具搜尋載入的工具描述上限 16,384（v2.1.295 起）；工具搜尋現行預設＝全部延遲；`_meta["anthropic/alwaysLoad"]` 可要求預載（頁：[mcp](../../../ClaudeCodeInternals/Docs/02-build/mcp.md)「使用 MCP 工具搜尋進行擴展」「針對 MCP 伺服器作者的工具搜尋」；TIMELINE v2.1.296、v2.1.295）。
- 現況：[`tools/workflow-guardian-mcp/lib/mcp.js`](../../../../tools/workflow-guardian-mcp/lib/mcp.js) `initialize` 只回 `protocolVersion: "2025-11-25"`、`capabilities: { tools }`、`serverInfo`，沒有 `instructions`（[`_現況對帳` §3.2](../../../ClaudeCodeInternals/Docs/_現況對帳-原子記憶系統用到的CC機制.md)、對帳表 #25）。實測 9 個工具描述 154–794 字元（都在上限內），`atom_write` 的 schema 9,504 字元。本 session 裡這 9 個工具是延遲載入的。[TECH §5.8](../../../../TECH.md)「其他 AI 客戶端輕量安裝」：Codex／Gemini CLI／Antigravity 只接 MCP，「沒有 hooks 就沒有每句話自動帶入記憶，要主動說查記憶」。
- 落差／機會：唯一一條「任何 MCP 客戶端都會在開場收到」的常駐管道沒用上。Claude Code 這邊 `rules/core.md` 已寫了寫入規矩，但企劃／美術用的其他客戶端只看得到工具描述。
- 做法（接上新能力）：在 `lib/mcp.js` 的 `initialize` 回應加 `instructions`（建議 ≤800 字元，關鍵詞放最前：問到過去決策、踩坑、公司工具時先 `memory_search`；寫入只走 `atom_write`；scope 一句話）。用 `initialize` 請求帶來的 `clientInfo.name` 判斷：客戶端是 Claude Code 就不送（它已有 `rules/core.md`，避免每場重複約 200 tok），其他客戶端才送。不設 `alwaysLoad`。
- 代價與風險：其他客戶端每場多 ≤800 字元常駐；Codex／Gemini 是否真的讀 `instructions`：未查證。Claude Code 端零成本。
- 驗法：用 stdin 對 `node server.js` 送兩次 `initialize`（`clientInfo.name` 分別是 `claude-code` 與 `codex`），斷言只有後者帶 `instructions`；在 Codex 裡不提工具名、只問「公司記憶裡有沒有 X」，看它是否自己叫 `memory_search`。
- 分級：**B**

### P6. MCP 註冊改由官方 CLI 寫，SessionStart 不再每場解析並改寫 `~/.claude.json`
- 官方機制：`claude mcp add-json <name> '<json>' --scope user`、`claude mcp add --scope user`（由 Claude Code 自己寫 `~/.claude.json`）；範圍優先序 local＞project＞user＞plugin＞claude.ai 連接器，同名不跨範圍合併（頁：[mcp](../../../ClaudeCodeInternals/Docs/02-build/mcp.md)「MCP 安裝範圍」「從 JSON 配置新增 MCP servers」）。
- 現況：[`hooks/ensure-mcp.py`](../../../../hooks/ensure-mcp.py) `fast_path` 每場 SessionStart 跑：找 node、讀 [`mcp-servers.template.json`](../../../../mcp-servers.template.json)、整份載入 `~/.claude.json`（本機現在 127 KB），缺整塊或 template `_version` 較新就用 `_save_json` 整檔重寫（沒拿 Claude Code 的鎖）；另外背景 npm 安裝與 7 天更新檢查（對帳表 #16、[TECH §9.3](../../../../TECH.md)）。探針 2 實測這支 hook 每場 480 ms（與其他 SessionStart hook 平行，不在最長路徑上，但每場都多一個行程）。
- 落差／機會：原生 CLI 能安全註冊；我們每場重解析別人的設定檔，真要寫入時還可能跟 Claude Code 啟動時自己的寫入互相覆蓋（只在首裝或 template 升版時寫，機率低但不是零）。
- 做法（直接換用原生）：註冊移到 [`tools/install.py`](../../../../tools/install.py)（首裝與升級流程），用 `claude mcp add-json … --scope user` 寫三個 server；SessionStart 只留便宜的檢查：比 template `_version` 與 `workflow/` 裡的一個標記檔，不同才在背景跑重新註冊並出 advisory，不在 hook 內解析 `~/.claude.json`。npm 背景安裝與更新那段照舊。`install.py --verify` 的 `verify_mcp` 改用 `claude mcp get` 或保留讀檔皆可。
- 代價與風險：多機時 template 升版靠 git pull 帶到，標記檔比對要能觸發重新註冊，否則新機器會漏；hook 內不要同步呼叫 `claude` CLI（它本身啟動要 1～2 秒）。
- 驗法：用 `CLAUDE_CONFIG_DIR` 指到暫存目錄跑一次安裝，`claude mcp list` 三個 server 都是 Connected；之後偵錯日誌裡 ensure-mcp 那行消失或降到百毫秒以下；`python tools/install.py --verify` 的「MCP 註冊」項維持綠。
- 分級：**A**（原生已有，修剪自製）

### P7. 明訂 `cleanupPeriodDays`，讓逐字稿保留期配合卡片來源回看
- 官方機制：`cleanupPeriodDays` 預設 30、最小 1、設 0 驗證失敗；背景清掃會無訊息刪逐字稿；OTel `claude_code.retention_sweep`（v2.1.227+）可看刪了多少（頁：[settings-reference](../../../ClaudeCodeInternals/Docs/05-configuration/settings-reference.md)「cleanupPeriodDays」、[monitoring-usage](../../../ClaudeCodeInternals/Docs/04-administration/monitoring-usage.md)「保留清理事件」）。另 v2.1.300 起本機逐字稿會記每次 API 請求的系統提示、工具與參數，檔案變大（[changelog](../../../ClaudeCodeInternals/Docs/01-getting-started/changelog.md)）。
- 現況：[`settings.json`](../../../../settings.json) 沒設此鍵（[`_現況對帳` §2.1](../../../ClaudeCodeInternals/Docs/_現況對帳-原子記憶系統用到的CC機制.md)「沒用到的鍵」）；[`tools/atom-provenance-backfill.py`](../../../../tools/atom-provenance-backfill.py) 檔頭寫「已清（約 30 天）」並固定措辭「原對話已逾保留期」；[`lib/provenance.py`](../../../../lib/provenance.py) 分 live／quote_only／unrecoverable 三態；`atom-source` skill 靠逐字稿撈原句。磁碟：`~/.claude/projects` 2.0 GB、121 個資料夾，近 7 天新增約 147 MB。
- 落差／機會：卡片「這句話誰說的」能回看多久，現在由一個沒人設定的預設值決定。
- 做法（接上新能力）：在版控的 `settings.json` 設 `cleanupPeriodDays: 90`（理由：涵蓋晉升觀察期與季度回顧；以近 7 天速率估多佔約 1～2 GB）；`atom-provenance-backfill.py` 的「約 30 天」說明改成讀實際設定值（文字層面）。
- 代價與風險：磁碟；逐字稿是明文，保留越久、裡面的敏感資訊在磁碟上越久（與 secret 機制的精神要對齊，使用者可選更短）；多機經 git 同步一致生效。
- 驗法：一週後對一張 31～90 天前建立的卡跑 `atom_source`，應回 `live` 而不是 `unrecoverable`；`find ~/.claude/projects -name "*.jsonl" -mtime +30` 不再歸零；週健檢記錄 projects 目錄大小。
- 分級：**B**

### P8. skill 觸發回歸改用 `claude plugin eval` 實跑；自訂 frontmatter 鍵搬進 `metadata`
- 官方機制：`claude plugin eval`（**v2.1.269+**）：每個案例在一次性家目錄裡起隔離的 `claude -p`，只載受測 plugin，不讀使用者的 hooks、CLAUDE.md、記憶；grader（評分規則）六種，其中 `tool_used` 設 `tool: Skill`＋`input_match` 判「有沒有叫到這個 skill」，負例用 `min: 0, max: 0` 並標 `arm: both`；`--ablation none` 只跑一組、成本減半，`--runs`、`--max-cost-usd`、`--json`，退出碼 0／1／2 可接 CI；目標可以是 plugin 目錄或 `name@skills-dir`（頁：[plugin-evals](../../../ClaudeCodeInternals/Docs/03-plugins/plugin-evals.md)；[skills](../../../ClaudeCodeInternals/Docs/02-build/skills.md)「Skill 未觸發」直接建議用它量觸發率）。frontmatter 的 `metadata` 是官方給「自己工具讀的鍵值」的位置，不認得的鍵一律靜默忽略（頁：[skills](../../../ClaudeCodeInternals/Docs/02-build/skills.md)「Frontmatter 參考」）。
- 現況：8 個 skill 有 `evals/triggers.json`（各 5 個該觸發＋5 個不該觸發），但沒有任何程式真的去跑——[`skills/skill-creator/scripts/audit-skill.py`](../../../../skills/skill-creator/scripts/audit-skill.py) 只檢查檔在不在、題數夠不夠；12 個 skill 帶自訂鍵 `triggers`／`pattern`，只有 audit-skill 與 new-skill 讀（[`skills/skill-creator/SKILL.md`](../../../../skills/skill-creator/SKILL.md) 自己寫「harness 不讀」）；對帳表 #18。memory-eval（[`tools/memory-eval/`](../../../../tools/memory-eval/)）測的是記憶檢索、離線零成本，不在此列，維持原樣。
- 落差／機會：觸發精準度「有出題、沒人考試」；原生評測框架現成，而且它的隔離環境正好只測「光靠 description 會不會觸發」。
- 做法（接上新能力＋改寫法避衝突）：
  1. 在 skill-creator 的 scripts 加轉換器：替單一 skill 在暫存目錄生一個臨時 plugin（複製 SKILL.md 與附件到 `skills/<name>/`、補 `.claude-plugin/plugin.json`），把 `triggers.json` 每題轉成 `evals/<case>/prompt.md`＋grader；跑 `claude plugin eval <暫存目錄> --ablation none --runs 1 --trust-plugin --no-publish --json <out> --max-cost-usd <上限>`。臨時 plugin 內 skill 名會帶前綴 `<plugin>:<name>`，`input_match` 要容許。
  2. 12 個 SKILL.md 的 `triggers`／`pattern` 搬到 `metadata:` 底下，audit-skill／new-skill 改讀新位置——避免日後官方若定義同名欄位時語意相撞。
- 代價與風險：用量：8 個 skill × 10 題 × 1 次 ≈ 80 次短 headless 執行（`tool_used` 是確定性評分，不另花評審模型）；超過兩分鐘，要先列給使用者點名才跑。用 claude.ai 訂閱登入時報告預設會發佈成私人 artifact，所以一定帶 `--no-publish`。需要 git ≥2.31。隔離環境沒有我們的 UPS 注入，測到的是 description 本身的觸發力，不代表真實 session 的總觸發率。
- 驗法：先只跑 `token` 一個 skill（10 題），確認 5 正例觸發、5 負例不觸發、退出碼 0；改 description 後重跑比較；搬 `metadata` 後再跑 `claude plugin validate ~/.claude/skills` 與 audit-skill 全綠。
- 分級：**B**

### P9. 用 mod 在終端裡顯示「這回合送了哪些記憶」，放在 skills 目錄 plugin 裡免安裝
- 官方機制：
  - mod（模組）＝帶 JS 事件處理程式、在 Claude Code 行程內執行的 plugin（**v2.1.287+**；VS Code 擴充功能要 2.1.299+ 才畫得出來）。可用的事件與 API：`turn.complete`（回合結束）、`$.ui.log(text)`（逐字稿裡一條暗線，**Claude 不讀取**）、`Pane`／`AbovePrompt` 面板與橫帶、`$.fs.read`、`$.http.fetch`、`turn.step`（每次請求的快取讀寫 token）；限制：hook 10 秒、fetch 30 秒（頁：[mods overview](../../../ClaudeCodeInternals/Docs/03-plugins/plugins__mods__overview.md)、[mods reference](../../../ClaudeCodeInternals/Docs/03-plugins/plugins__mods__reference.md)、[mods api](../../../ClaudeCodeInternals/Docs/03-plugins/plugins__mods__api.md)、[mods interface](../../../ClaudeCodeInternals/Docs/03-plugins/plugins__mods__interface.md)）。
  - skills 目錄 plugin：`~/.claude/skills/<dir>/.claude-plugin/plugin.json` 存在就每場自動載入、就地載入不複製、不用 marketplace（頁：[plugins create](../../../ClaudeCodeInternals/Docs/03-plugins/plugins__create.md)「讓外掛程式在每個工作階段中載入」、[plugins loading](../../../ClaudeCodeInternals/Docs/03-plugins/plugins__loading.md)）。
  - 內建防護 `sec-default`：機器有受管設定、或用 Team／Enterprise 登入時載入，使用者 mod 在 `classic.*`、`prompt.context／section／compose／attachment`、`skill.prompt`、`session.compact` 上的 hook 不會執行（頁：[mods admin](../../../ClaudeCodeInternals/Docs/03-plugins/plugins__mods__admin.md)「了解使用者 mod 的哪些 hook 不會執行」）。
- 現況：可視化是 `:3848` Dashboard 與 `/aec/hud`（瀏覽器頁，由 MCP 的 [`server.js`](../../../../tools/workflow-guardian-mcp/server.js) 提供，有 `/api/sessions`、`/api/health`、`/api/vector-status` 等 JSON 端點）＋ [`tools/statusline.py`](../../../../tools/statusline.py)；每回合注入結果在 `Logs/injection-turns.jsonl`（欄位 `used_tokens`、`limit`、`out_chars`、`delivered`）；[`_現況對帳` §3.3](../../../ClaudeCodeInternals/Docs/_現況對帳-原子記憶系統用到的CC機制.md)「mods 無」、對帳表 #20。
- 落差／機會：「這一句送了幾張卡、用掉多少預算」目前要開瀏覽器或翻 jsonl；mod 能在每則回答下面畫一行，零 token（呼應 TECH §8 原則：給人看的資訊放常駐可見面）。Dashboard 依附 MCP 行程，還有孤兒佔埠的老問題，終端內一行更貼身。
- 做法（接上新能力）：新增 `~/.claude/skills/wg-hud/`（`plugin.json`＋`hooks/hooks.json` 的 `modules`＋`register.js`，**不放 SKILL.md**，所以 [`tools/skill-index.py`](../../../../tools/skill-index.py) 掃 `skills/*/SKILL.md` 的計數不受影響）：`turn.complete` 時讀 `injection-turns.jsonl` 本 session 最後一筆，用 `$.ui.log` 印「記憶：送 4 卡 · 1142/1200 tok」；選做一個 `/wg` 命令開 Pane，抓 `:3848/api/sessions`、`/api/health`。只讀不寫、不碰注入。（選做延伸：`/console` 用 plugin monitor 的 `when: "on-skill-invoke:<skill>"` 盯派工信箱，取代「Bash 背景短 sleep 當鬧鐘」——屬多 session 面向，僅提示。）
- 代價與風險：要寫 JS（repo 已有 Node 寫的 MCP，有現成手感）；每台機器 ≥2.1.287，較舊的只是不載入、不出錯；Anthropic 有遠端開關可關掉已安裝 mod（關掉就退回現況，屬 fail-open）；mod 不受沙箱，但這是自己的程式。本 mod 用到的事件不在防護封鎖清單內，Team／Enterprise 登入下也照跑（使用者帳號方案未查，`/status` 可看）。Desktop 的 WSL session 不載 plugin。
- 驗法：`claude plugin validate ~/.claude/skills/wg-hud` 的 `hooks:` 只列 `turn.complete`、`calls:` 只列 `fs.read`／`ui.log`（有 Pane 再加 `http.fetch`／`ui.*`）；`claude plugin test` 用 stub 跑一次 `turn.complete`；實際 session 送一句話後回答下出現暗線，`/context` 不增加。
- 分級：**B**

### P10. 把原子記憶系統整包打包成 plugin——利弊與做不到的部分
- 官方機制：plugin 可包 skills、agents、hooks（含 mod）、MCP、LSP、monitors、`bin/`、輸出樣式、主題；`${CLAUDE_PLUGIN_ROOT}` 指向每版不同的快取目錄（不准在裡面存狀態）、`${CLAUDE_PLUGIN_DATA}` 跨版保留但卸載即刪（除非 `--keep-data`）；載入三階段（設定宣告 `enabledPlugins` → 磁碟 `~/.claude/plugins/` → session 載入，改了要 `/reload-plugins`，v2.1.69+）；`enabledPlugins` 六層來源 `--add-dir`＜user＜project＜local＜flag＜managed；元件不得逃出 plugin 根目錄、快取副本不含根目錄外的檔案；plugin 根目錄的 `CLAUDE.md` 不載入；plugin 的 `settings.json` 只認 `agent`、`subagentStatusLine`；plugin MCP 工具名變成 `mcp__plugin_<plugin>_<server>__<tool>`；設定檔 hooks 與 plugin hooks 同時存在會各跑一次；依賴自動安裝只支援有鎖定檔的 Node registry 套件；存放在 repo 的 plugin 要過信任、且不載 monitors；relevance 推薦（`cwd`／`cli`／`filesRead`／`manifestDeps` 訊號）要管理員在受管設定開 `pluginSuggestionMarketplaces`（頁：[plugins overview](../../../ClaudeCodeInternals/Docs/03-plugins/plugins__overview.md)、[components](../../../ClaudeCodeInternals/Docs/03-plugins/plugins__components.md)、[loading](../../../ClaudeCodeInternals/Docs/03-plugins/plugins__loading.md)、[create](../../../ClaudeCodeInternals/Docs/03-plugins/plugins__create.md)、[dependencies](../../../ClaudeCodeInternals/Docs/03-plugins/plugins__dependencies.md)、[relevance](../../../ClaudeCodeInternals/Docs/03-plugins/plugins__relevance.md)、[org](../../../ClaudeCodeInternals/Docs/03-plugins/plugins__org.md)）。
- 現況：git clone `~/.claude`＋[`tools/install.py`](../../../../tools/install.py) `merge_settings` 合併 hooks；`ensure-mcp.py` 註冊 MCP；[`hooks/user-init.sh`](../../../../hooks/user-init.sh) 依帳號產 `USER.md`；公司層靠 `/org` 接 org repo；非 Claude Code 客戶端走 [`tools/ai-client-setup.py`](../../../../tools/ai-client-setup.py)；`~/.claude` 本身就是 git repo，設定、hooks、skills、rules 全部進版控（[`_現況對帳` §2.2](../../../ClaudeCodeInternals/Docs/_現況對帳-原子記憶系統用到的CC機制.md)、對帳表 #17）。
- 做不到或代價過高的部分：

  | 部件 | 能放進 plugin？ | 原因 |
  |---|---|---|
  | `CLAUDE.md` 的 `@import`（IDENTITY／USER／MEMORY 索引）、`rules/core.md`、`rules/` 的 `paths:` 條件載入 | 不能 | plugin 沒有常駐指示元件、根目錄 CLAUDE.md 不載入；只能改用 SessionStart 注入，失去 `paths:` 條件載入與壓縮後原生重載 |
  | `statusLine`、`permissions.allow`、`language`、`model`／effort | 不能 | plugin 預設設定只認 `agent`、`subagentStatusLine` |
  | `lib/`、`tools/` 共用程式 | 只能整包放進 plugin 根目錄 | 元件不得逃出根目錄、快取不含根目錄外的檔案 → plugin 幾乎等於整個 repo |
  | MCP server | 能，但改名 | 工具名變 `mcp__plugin_<p>_workflow-guardian__*`，PreToolUse／PostToolUse matcher、`permissions.allow`、skill 內文、dispatcher 裡的工具名判斷全要改 |
  | hooks（11 個事件） | 能 | 路徑隨版本換；遷移期與 `settings.json` 的 hooks 並存會跑兩次，必須一次切換 |
  | `memory/`、`workflow/` state、`Logs/` | 不該 | 記憶靠 git 多機同步；`CLAUDE_PLUGIN_DATA` 不進版控、卸載即刪 |
  | Python 套件（lancedb、sentence-transformers）、Ollama | 不能自動 | 自動安裝只管 Node；Python 環境要自己用 SessionStart 建，Ollama 是系統服務 |
  | `USER-<帳號>.md`、公司層 org repo | 不適合 | 屬個人／公司資料，不是程式 |

- 落差／機會：plugin 帶來的好處（版本化更新、`/reload-plugins` 不必 Reload Window、技能名前綴、一行安裝）對「單人、多機、核心是常駐指示＋git 同步資料」的系統很小，換來的是大規模改名與遷移風險。專案層部分：沒裝本系統的隊友若要讀專案記憶，用專案自己的 `<project>/.claude/skills/` 放一個指向 `.claude/memory/MEMORY.md` 的 skill 就夠，不需要 plugin（是否會跟本系統的注入重複：未驗證，待確認）。可取的是兩個小包裝，已拆成 P8（臨時 plugin 當評測殼）、P9（skills 目錄 plugin 當 mod 載體）。
- 做法：現在不做。再議條件：出現多位不 clone `~/.claude`、卻需要 hook 級注入的使用者；或官方給 plugin 加上常駐指示（rules）元件。
- 代價與風險：見上表。
- 驗法（若再議）：先做 `claude --plugin-dir` 原型並跑 `claude plugin validate --strict`；用 `--settings '{"disableAllHooks":true}'` 關掉設定檔 hooks，A/B 比對注入結果與 memory-eval 分數一致。
- 分級：**D**

### P11. Agent SDK 對「記憶服務化」的接點（記錄，不動工）
- 官方機制：SDK 預設照 CLI 載入 `~/.claude`（CLAUDE.md、rules、skills、settings 裡的 hooks），`settingSources: []` 才隔離；自動記憶不受 `settingSources` 管，要 `autoMemoryEnabled:false` 或 `CLAUDE_CODE_DISABLE_AUTO_MEMORY`；程式化 hook callback（Python 沒有 SessionStart／SessionEnd；`onFailure: "block"` v2.1.317）；`sessionStore` 把逐字稿鏡像到自己的儲存；TS 的 `getContextUsage()` 拿到與 `/context` 相同的精確數字；文件要求第三方產品用 API 金鑰（頁：[agent-sdk claude-code-features](../../../ClaudeCodeInternals/Docs/07-agent-sdk/agent-sdk__claude-code-features.md)、[session-storage](../../../ClaudeCodeInternals/Docs/07-agent-sdk/agent-sdk__session-storage.md)、[hooks](../../../ClaudeCodeInternals/Docs/07-agent-sdk/agent-sdk__hooks.md)、[typescript](../../../ClaudeCodeInternals/Docs/07-agent-sdk/agent-sdk__typescript.md)、[overview](../../../ClaudeCodeInternals/Docs/07-agent-sdk/agent-sdk__overview.md)）。
- 現況：headless 只走 CLI `claude -p`（裁判、`tools/auto-continue/auto_continue.py`（v6.1 已刪）、console-spawn `--method print`），沒用 SDK；[`_AIDocs/Vision/_INDEX.md`](../../../Vision/_INDEX.md) 定調「原子記憶系統是海馬迴，JARVIS 是大腦」。
- 落差／機會：將來若用 SDK 寫編排者，因為預設會載 `~/.claude`，我們的注入 hook 會自動跟著生效，不需要為 SDK 另寫接頭；`sessionStore` 能把各機逐字稿集中，補 P7 只能單機回看的限制；`getContextUsage()` 是常駐成本的精確量尺。
- 做法：現在不做，記為 Vision 編排核心起步時的接點。
- 代價與風險：認證（文件要求 API 金鑰；自用腳本能否沿用訂閱登入：未查證）、新增 Node／Python 套件依賴；P2、P4 已用 CLI 補上量測需求。
- 驗法：（啟動時）用 `settingSources` 省略與 `[]` 各跑一次同提示，比對 `additionalContext` 是否出現 `[Guardian:` 前綴。

## 不建議做的

1. **用 mod 的 `prompt.submit`／`prompt.section` 接管記憶注入或刪系統提示段落**：檢索邏輯在 Python＋向量服務，mod 還是要另起行程或打 HTTP，省不到時間；Team／Enterprise 登入時內建防護會略過 `prompt.section`／`prompt.context`；v2.1.318 才剛改過 `prompt.submit` 附加內容的落點，API 還在變。
2. **替 `atom_write`／`memory_search` 設 `alwaysLoad` 預載**：`atom_write` 的 schema 就有 9,504 字元，預載等於每回合常駐約數千 token；用 P5 的 `instructions` 指路即可。
3. **給 MCP server 加 elicitation（中途彈表單問人）、resources、prompts**：背景工作軌與 `-p` 沒有人能回答表單，而且違反「判斷交 LLM」；atom 本來就是能直接 Read 的檔，命令已由 skills 提供，加了只是多一套入口。
4. **用 relevance 訊號、受管設定、私有 marketplace 推公司層**：relevance 要管理員在受管設定開 `pluginSuggestionMarketplaces`；機器一旦有受管設定，內建防護就會載入，mod 的多個事件與 `classic.*` 都會被略過，也不符合目前的單人環境。
5. **用 `claude purge` 清 worktree 殘留**：本機 `~/.claude.json` 有 67 筆 `.claude-wt` 信任紀錄、對應目錄都已不存在，但 `purge` 會連逐字稿一起刪，`atom-source` 回看就斷了；要清只刪那幾個鍵。
