## 一句話結論

官方這半年把三件我們自己做的事做成了原生（跨 session 傳訊與命名、worktree、續跑上限），同時改了三個我們賴以為前提的行為（子代理預設背景、hook 輸出 10,000 字元上限、壓縮後 SessionStart(compact) 會跑）。**最急的不是新功能，是這三個前提失效造成的「記憶悄悄沒送到／沒記到帳」**，全部都能一兩天內修完並用逐字稿統計驗證。

## 要先跑探針再決定的（分析者標「推論」）

- 閒置 session 收到訊息會不會自動開回合、`notify_when_idle` 可不可用 → 決定要不要撤「空手不能結束回合」與「背景 sleep 當鬧鐘」規則（[02-P3](02-多session與自動化.md)）。
- `/rewind`、「Summarize from／up to here」倒退對話後我們的 state 不退（[02-P13](02-多session與自動化.md)）。
- `/cd` 是否觸發 `CwdChanged`、`claudeMdExcludes` 能否排除 `AGENTS.md`、`/doctor prompt-audit` 能否在 `-p` 下跑（[01-P16](01-hooks注入與context.md)、[01-P11](01-hooks注入與context.md)、[01-P18](01-hooks注入與context.md)）。
- `claude -p` 將預設 `--bare`（官方預告、未定版本）：無頭裁判會因不讀登入而靜默退回啟發式、無頭驗收不跑 hook 卻顯示通過 → 先把依賴寫明、加版本偵測（[02-P6](02-多session與自動化.md)）。

## 不建議做的（三份分析一致）

- 用 agent／prompt 型 hook 取代 Codex 第二意見與驗收裁判：同步擋住流程、只能用 Claude。
- 用 agent teams 取代 `/console` 多軌：實驗性、隊友不隔離 worktree、`-p` 生不出隊友。
- 用 mod 接管記憶注入或刪系統提示段落：檢索邏輯在 Python＋向量服務，mod 還是得另起行程，只是多一層。
- 把整個原子記憶系統打包成 plugin：常駐指令、statusLine、permissions、git 同步的記憶資料都進不了 plugin，MCP 工具名全變（[03-P10](03-封裝散佈評測觀測.md) 有做不到清單）。
- 用 PreCompact 擋自動壓縮保住注入、重開 idleCompaction、`updatedToolOutput` 壓工具輸出、`alwaysLoad` 預載 MCP 工具、`claude purge` 清殘留（會連逐字稿一起刪）、Windows 排程搬到 routines／Desktop 排程、channels 推信箱、SDK `sessionStore` 解 transcript 保留。

## 建議的動工順序

1. **一個 session 做完第一批 1～4**（hooks 兩支改法＋裁判旗標＋settings 一鍵），每案都有逐字稿統計可自動驗：`no_output` 比例、`Output too large` 筆數、壓縮後 SessionStart 帶卡比例、裁判 `init.tools` 清單。
2. **第二個 session 做修剪 9～12**（auto memory 關、--name、--worktree、信箱改 SendMessage），同時改 MultiSessionCollaboration 與相關卡片；先跑「要先跑探針」那四題。
3. **第三批照價值逐案做**，18 與 21 零開發先上；22 看磁碟決定。
4. 每批完成後更新 [現況對帳表](../../../ClaudeCodeInternals/Docs/_現況對帳-原子記憶系統用到的CC機制.md) §1 與 §6，讓它持續當對帳基準；官方文件每月 `python ~/.claude/tools/cc_docs_harvest.py fetch` 重抓一次，比 `_manifest.json` 的 lastmod 找變動頁。
