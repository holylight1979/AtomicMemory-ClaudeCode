## 名詞

| 名詞 | 白話 |
|---|---|
| CC | Claude Code |
| 卡片（atom） | 一則記憶：一個決定、一個坑、一個習慣 |
| 注入 | 系統把相關卡片塞進 AI 這一回合看得到的內容 |
| hook | CC 在固定時機自動跑的小程式（送出一句話、用完工具、回合結束、壓縮）；本系統的注入與把關都靠它 |
| UPS | UserPromptSubmit，使用者送出一句話時跑的 hook，「每句話帶卡片」就在這裡 |
| SessionStart | 開場時跑的 hook；壓縮之後 CC 也會再跑一次，時機標 `compact` |
| 子代理 | 主對話派去做一件子任務的另一個 AI；CC 現在預設讓它在背景跑。這版的分析與施工多半由子代理做 |
| 壓縮 | 對話快滿時，CC 把舊對話濃縮成摘要；摘要以外的內容（包括已送的卡片內文）會不見 |
| 收尾閘 | 回合結束前的檢查（測試沒綠、說修好卻沒驗……），沒過就擋下要 AI 處理 |
| 效用帳 | 記「送出去的卡，這回合有沒有被用上」 |
| 量尺 | 唯讀的統計腳本：從對話紀錄算出某件事實際發生幾次，只給數字不判對錯 |
| 對話紀錄（逐字稿） | CC 存在 `~/.claude/projects/` 的每場對話原文，一場一個 `.jsonl` 檔 |
| 交接單 | 給下一個 session 接手用的說明檔；壓縮前系統會自動寫一份 |
| 工作軌／總控台 | `/console` 多開模式：你只跟總控台說話，它把工作分給多個並行的工作 session，一軌做一件事 |
| worktree／主檢出 | worktree：同一個 git repo 另開一份工作目錄加一條分支；主檢出：repo 原本那份工作目錄 |
| 無頭 | `claude -p` 這種不開畫面、跑完就結束的用法 |
| 裁判 | 驗收或第二意見時，系統另外起一個無頭 AI 來判斷「有沒有做到」 |
| Codex | OpenAI 的命令列 AI，本系統拿它當第二意見 |
| MCP | AI 接外部工具的標準介面；本系統的 MCP server 提供 `memory_search`（查卡）、`atom_write`（寫卡）等工具 |
| 快取 | CC 把已送過的對話存在伺服器端，再送一次便宜很多；閒置太久就失效，要整份重送 |
| 探針 | 為了確認某個行為，特地跑一次的極小實驗 |
| 規則名 | 本系統每條有名字的規則（例 `NON_HUMAN_PROMPT_NO_INJECT`），登錄在 `hooks/wg_release_rules.py`，說明在 `TECH/release-rules.md` |

驗證狀態欄的寫法：

| 寫法 | 意思 |
|---|---|
| 離線案例綠 | 這項的驗證檔（用假資料跑的自動測試）發行前單獨重跑全過；整組全量沒跑 |
| 真 session 已見 | 發行後真的對話裡已經有這項的紀錄 |
| 待實跑 | 照設計會這樣、案例也過了，但還沒在真的對話裡看到過 |
| 不需驗 | 只改文件、只改設定，或整支拆掉 |
| 沒做 | 這版沒動，原因見最後一節 |

效果欄：「實測」＝有量到的數字（附條件）；「設計上可達」＝照設計推得出來，還沒量到。
