> 發布：2026-11-04｜上一版：v6.0 寫程式碼的進化（2026-10-12，[`../v6.0-寫程式碼的進化-2026-10/`](../v6.0-寫程式碼的進化-2026-10/README.md)）
> 本文寫給人看。每項改了哪些檔、規則名、驗證檔在 [`技術對照.md`](技術對照.md)（寫給 AI 讀）；運作細節以 [`TECH.md`](../../../TECH.md) 與實碼為準。

## 一句話

Claude Code（下稱 CC）這半年改了幾個本系統當作前提的行為，也把幾件我們自己做的事做成了原生功能。這一版補回因此沒送到的記憶，把重複造的輪子換成原生，讓「每句話自動帶卡片」更準，並附上量尺，之後可以持續對帳。

## 本文用到的名詞

| 名詞 | 白話 |
|---|---|
| 卡片（atom） | 一則記憶：一個決定、一個坑、一個習慣 |
| 注入 | 系統把相關卡片塞進 AI 這一回合看得到的內容 |
| context | AI 這一回合看得到的全部內容；越大越貴 |
| hook | CC 在固定時機自動跑的小程式（例如你送出一句話、AI 用完工具、回合結束、壓縮）；本系統的注入與把關都靠它 |
| 子代理 | 主對話派去做一件子任務的另一個 AI；CC 現在預設讓它在背景跑 |
| 壓縮 | 對話快塞滿時，CC 把舊對話濃縮成摘要；摘要以外的內容（包括已送的卡片內文）會不見 |
| 收尾閘 | 回合結束前的檢查（測試沒綠、說修好卻沒驗……），沒過就擋下要 AI 處理 |
| 效用帳 | 記「送出去的卡，這回合有沒有被用上」；之後要讓沒用的卡降低出場優先序，靠這本帳 |
| 量尺 | 唯讀的統計腳本：從對話紀錄算出某件事實際發生幾次，只給數字不判對錯 |
| 交接單 | 給下一個 session 接手用的說明檔；`/handoff` 寫的是手寫版，壓縮前系統會自動寫一份 |
| 總控台／工作軌 | `/console` 多開模式：你只跟總控台說話，它把工作分給多個並行的工作 session，一軌做一件事 |
| worktree | 同一個 git repo 另開一份工作目錄加一條分支，讓並行的軌互不干擾 |
| 主檢出 | repo 原本那份工作目錄（不是 worktree） |
| 無頭 | `claude -p` 這種不開畫面、跑完就結束的用法 |
| 裁判 | 驗收或第二意見時，系統另外起一個無頭 AI 來判斷「有沒有做到」 |
| MCP | AI 接外部工具的標準介面；本系統的 MCP server 提供 `memory_search`（查卡）、`atom_write`（寫卡）等工具 |
| 快取 | CC 把已送過的對話存在伺服器端，再送一次便宜很多；閒置太久就失效，要整份重送 |

## 為什麼有這一版

2026-11-04 把 CC 官方文件 228 頁全部抓回本地、建了索引（`_AIDocs/ClaudeCodeInternals/Docs/`），逐項對照本系統用到的 CC 機制，整理出 46 個改進案，排成三批：

1. **相容修正**：官方行為變了，我們的記憶正在沒送到、沒記到帳，而且沒有任何訊號。
2. **修剪**：官方已經有了，拆掉自己做的。
3. **進化**：用官方新能力補我們的缺口。

計畫全文見 [`00-總整與建議優先序.md`](analysis/00-總整與建議優先序.md)；每項的處置見[現況對帳表 §6](../../ClaudeCodeInternals/Docs/_現況對帳-原子記憶系統用到的CC機制.md)。

## 第一批：相容修正（記憶在漏，沒有訊號）

| 事 | 之前 | 現在 |
|---|---|---|
| 子代理有沒有用上卡片 | 子代理改成預設在背景跑之後，主對話派出時只拿到「已派出」，拿不到結果；30 筆效用帳全標「沒有輸出」，等於沒記 | 等子代理收尾時，把它最後一則回覆填回去再結帳；還沒回來的標「等待中」，不算沒用 |
| hook 一次送太多字 | 官方規定 hook 單筆超過 10,000 字元，就換成「檔案路徑＋前 2,000 字預覽」，AI 不會去讀；近 400 份對話紀錄裡被換掉 36 次 | 系統自己在 9,000 字元截斷，尾行附全文存檔的路徑，並留帳 |
| 壓縮後的卡片內文 | 要等壓縮後下一批工具跑完才補送。18 次壓縮裡，壓縮後第一時間送到 0 次，後來補上的也只有 6 次 | 改在壓縮當下 CC 會跑的開場事件（SessionStart，時機標 `compact`）直接送。這 18 次裡有 17 次那個事件有跑，所以照設計 17/18 能在第一時間送到；舊路留作備援 |
| 誤判「換了專案」 | 壓縮或重開時，工作目錄的寫法不同（`c:\` 對 `C:\`，或停在子目錄），系統就以為換了專案、重建狀態，連壓縮前的卡片名單一起丟掉。17 次壓縮裡有 14 次這樣 | 只看真正的專案根，不看大小寫與子目錄 |
| 裁判的權限 | 原本用「禁止清單」，官方一出新工具就漏：裁判仍能寫卡片、發佈網頁、操作桌面 | 改成「允許清單」，只留讀檔與搜尋三件（Read／Grep／Glob），也不連任何 MCP 工具 |
| 跨 session 傳訊被扣住 | 「略過權限」與「會問權限」兩類 session 互傳時，官方預設扣住等你核准；VS Code 顯示不出核准框，5 分鐘後作廢 | 設定 `crossSessionInbound: "accept"`，直接收 |
| 收尾閘太早跑 | 回合其實只是在等背景子代理或監看程式，收尾閘卻當成「做完了」來擋 | CC 現在會告訴我們還有哪些背景工作；有的話，收尾檢查延到背景回報那次再跑。同一件連延 5 次就照擋，不會永遠不檢查（測試沒綠的檢查照常不延） |
| 家目錄的 AGENTS.md | 寫給 Codex（OpenAI 的命令列 AI，本系統拿它當第二意見）的 `~/AGENTS.md`，被 CC 當成 `~/.claude` 的專案指令載入；內容還是舊版（V4.1），跟現行規則矛盾 | 改成兩行指路；CC 端用 `claudeMdExcludes` 設定不載它 |
| 文件更正 | 文件寫「SessionEnd 只有 1.5 秒」 | 官方現行：個別 hook 設了逾時可以到 60 秒，我們設的 30 秒本來就有效。行為不變，只改文件 |
| 抓網頁前先探路 | 每次 WebFetch（CC 抓網頁的工具）前，一支 hook 先用 curl 探網址；擋下時理由還寫錯欄位 | 拆掉，交給 WebFetch 自己處理逾時 |

## 第二批：修剪（原生已有，拆掉自製）

| 拆什麼 | 換成什麼 | 你會失去什麼 |
|---|---|---|
| CC 原生 auto memory（CC 自帶的記事本），加上我們放進去、指向卡片索引的指路檔，和擋它寫入的檢查 | 設定 `autoMemoryEnabled: false` 直接關；指路檔與產生它的程式退役 | 沒有。近 150 場 AI 從沒讀過那份指路檔。每場還少掉約 500 token「用 Write 寫記憶」的提示，不再跟「寫卡一律走 atom_write」打架。卡片、注入、搜尋照常 |
| 工作軌的名字會變（VS Code Reload 後全部重編），傳訊前要先點名 | 開軌時用 `claude --bg --name <軌名>`：名字就是傳訊地址，Reload 也不變；兩個總控台分頁由你各打一次 `/rename` | 沒有 |
| 手動建 worktree，再手改 `~/.claude.json` 補信任 | `--worktree <軌名>` 交給 CC 自己建；`worktree.baseRef: "head"` 讓它從本機最新 commit 分出去（不設會從遠端分，漏掉還沒推的 commit） | 沒有 |
| Claude 對 Claude 的檔案信箱（root-link、tri-link、to-opus／to-fable 資料夾） | CC 原生的 session 間傳訊工具 SendMessage。實測閒置的 session 收到信 0.04 秒就進對話，而且自己開新回合 | 沒有。`/mailbox`（共用資料夾信箱）保留，給跨人、跨模型、要留案卷的情況用 |
| 實驗性的 auto-continue（自動續跑） | CC 原生 `/goal <完成條件>`：每回合結束判一次達成了沒，沒達成就自動再跑 | 沒有 |
| ensure-mcp（開場檢查 MCP 有沒有登記的程式）每場自己改寫 `~/.claude.json` 來登記 MCP | 改呼叫官方指令 `claude mcp add-json`；缺登記照樣自動補回 | 沒有。少掉跟 CC 同時寫那個檔、互相蓋掉的風險 |
| skill（一包可以被叫用的指令說明）檔頭的自訂欄位 `triggers`、`pattern`（CC 不讀） | 原生欄位 `when_to_use`，觸發詞會出現在 CC 的 skill 清單裡；`pattern` 搬進 `metadata` | 沒有。12 個 skill 與 skill-creator 的範本、稽核腳本一起改 |
| 對話紀錄保留天數（官方預設 30 天） | `cleanupPeriodDays: 14` | 只有一件：超過 14 天的卡，問「這張卡哪來的」時查不回原對話的前後文，只剩落卡時留的那句原話。健檢與萃取都在 7 天內讀完，不受影響。卡片本身永久保存 |

## 第三批：進化（用新能力補缺口）

| 事 | 你得到什麼 |
|---|---|
| 非真人的訊息不帶卡片 | 背景任務的完成通知、其他 session 傳來的信，也會觸發「每句話帶卡片」。這次量到非真人回合吃掉 2,399 張卡，佔注入的 63%。現在整則沒有你打的字就不送卡（把關與記帳照跑）；夾著你打的字，就只拿你打的字去查 |
| `/continue` 依交接單挑卡 | 之前 `/continue` 那一回合，系統只看得到「/continue」這幾個字，挑不到相關的卡。現在把交接單前段（最多 30 行、1,500 字）一起拿去查 |
| 子代理補送卡片 | 不經 Agent 工具派出的子代理（設了 `context: fork`、會在獨立子代理裡跑的 skill，以及 CC 的多步驟腳本工具 Workflow），之前拿不到卡；現在在子代理啟動時補送 |
| Codex 審查立刻叫醒 | 背景的 Codex 第二意見，之前要等你下一句話才看得到。現在有該處理的發現，就立刻把 AI 叫回來（CC 的 `asyncRewake`：背景 hook 跑完可以叫醒 AI）；最多等 270 秒，超過就照舊下一則帶回 |
| 規則有沒有真的載入 | CC 每次載入 CLAUDE.md 或 rules（開場、碰到特定檔、壓縮後）都記一行，週健檢會列出。「以為有載」從此查得到 |
| API 錯誤中斷的回合 | 回合因 API 錯誤結束時，收尾檢查不會跑；現在會留帳，並把這回合排除在效用帳外，不會誤算成「卡沒用」 |
| 壓縮摘要寫進交接單 | 壓縮時 CC 寫的對話摘要，自動填進這一輪自動交接單的「壓縮前脈絡」段，並標明它是推論，動工前要對照檔案核實 |
| 重開舊 session 的提醒 | 重開閒置很久的 session、快取多半已失效、而且要重送 10 萬 token 以上時，提醒一行「要省就開新 session」 |
| 同檔預警附上對方名字 | 兩個 session 改到同一個檔時的預警，現在附上對方 session 的名字，並提示可以用 SendMessage 找對方協調 |
| 背景工作軌算「沒人能回答」 | 背景工作軌被收尾閘擋滿時，跟子代理一樣放行並留帳，不再卡著等一個沒人會答的提問（之前有軌因此卡了 12 小時） |
| 給不是 CC 的 AI 工具指路 | Codex、Gemini 這類沒有 hook 的工具連上本系統的 MCP 時，開場會收到一段說明：怎麼查、怎麼寫、卡片在哪。CC 自己不送（已經有 hook 與規則）。`memory_search` 改成開場就載入，CC 不必先搜尋工具才能用 |
| 週健檢多一節「官方健檢」 | 列出 `/skill-doctor`（skill 數、佔 context 最多的前五個、從沒被叫過的）與 `/context`（每場固定成本）的摘要；`/doctor prompt-audit`（審指令檔有沒有過時或矛盾）無頭跑超過 170 秒還沒完，只列一行請你手動跑 |
| 四支量尺 | 量注入沒命中時 AI 有沒有自己補搜、把 AI 搜過的詞列成觸發詞候選、量壓縮後卡片是誰送的、量每支 hook 真正花的時間（含 Python 啟動）。怎麼跑見下方「量尺怎麼跑」 |
| CC 官方文件本地版 | `tools/cc_docs_harvest.py` 把 228 頁抓回來建索引，每月重抓一次就能比出官方改了哪些頁 |

### 這次量到的數字

- 近 150 場：hook 注入 13,146 次，AI 主動 `memory_search` 224 次。
- 注入 0 張卡的回合佔 15%；這些回合裡 AI 自己補搜的只有 1.2%。
- 每支 Python hook 光是啟動就要 330～480 ms；開場的主 hook（SessionStart）全程 9.1 秒（用無頭方式實跑一次量到的，互動 session 還沒量）。
- 閒置的 session 收到其他 session 的信，0.04 秒內進對話。

## 你會體驗到的變化

標「待實跑」的：照設計會這樣、離線案例也過了，但還沒在真的 session 看到過（見「驗證狀況」）。

- **開工作軌（`/console 開工`）**：總控台在主檢出跑 `claude --bg --name <軌名> --worktree <軌名>`。工作 session 在背景跑，不佔分頁，終端機打 `claude agents` 看得到；名字就是軌名。worktree 會在 `<主檢出>/.claude/worktrees/<軌名>`，分支叫 `worktree-<軌名>`。前提是那個主檢出已經被 CC 信任過，見下方「要你動手的」第 1 條；沒信任過，開軌會失敗並退回給你手貼開工句。兩個總控台分頁開好後，請各打一次 `/rename 對人總控台`、`/rename 調度總控台`。
- **信箱**：Claude 之間不再寫檔案信箱，改用 SendMessage。等回信時 AI 可以直接結束回合，收到信會自己醒來。`/mailbox` 照舊給跨人用。
- **auto memory**：已關。`/memory` 會顯示 Auto-memory off；卡片、注入、搜尋全部照常。新開的 session 才生效（待實跑）。
- **週健檢報告**：多一節「官方健檢」，另加一行「規則／索引載入」次數。
- **可能看到的新提示行**：
  - `[Guardian:ResumeCache]`：重開舊 session、快取多半失效、要重送很多 token 時出現（待實跑）。
  - `[Guardian:Truncated]`：某次 hook 輸出超過 9,000 字元被截斷，後面附全文檔路徑（待實跑）。
  - 同檔預警多了對方 session 的名字（待實跑）。
  - Codex 第二意見有發現時，AI 會在你沒說話的情況下被叫醒處理（待實跑）。
  - 壓縮之後，自動交接單多一段「壓縮前脈絡」（待實跑）。
- **背景工作中收尾**：AI 在等背景子代理時結束回合，不會再被收尾檢查提早擋下。

## 要你動手的

1. **每個要用 `/console 開工` 的 repo，在主檢出開終端機跑一次 `claude`，接受信任提示。** `~/.claude` 已經做過。
2. **重開 Claude Code。** auto memory 關閉、MCP 給其他 AI 工具的說明、`memory_search` 開場載入、MCP 顯示的版本號 6.1.0，都要新的 session 或 MCP 重連後才生效。
3. **終端機打 `claude` 找不到時**：CC 原生安裝的 `claude` 在 `~/.local/bin/`（Windows 是 `C:\Users\<帳號>\.local\bin\claude.exe`）。可以用完整路徑跑，或把那個資料夾加進 PATH。週健檢會自己去那裡找；開軌腳本用的是 VS Code 擴充內附的那支，不受影響。
4. **用安裝器接管過的電腦，升級後要自己補一個設定。** 怎麼分辨：`git -C ~/.claude ls-files -v settings.json` 開頭是 `S`，就是安裝時把你原有設定合併進來的那種。這種電腦跑 `python ~/.claude/tools/install.py --upgrade` 時，這一版新加的頂層設定裡有四個會自動補上：`autoMemoryEnabled`（auto memory 關）、`crossSessionInbound`（跨 session 傳訊直接收）、`cleanupPeriodDays`（對話紀錄保留 14 天）、`worktree`（從本機最新 commit 分出）。你原本沒設的才補，自己設過的照你的。第五個 `claudeMdExcludes` 裡有本機帳號路徑，不會帶過去。開頭是 `H` 的（開發機，`settings.json` 直接跟版控走）pull 就會拿到，不用補。要補的話，在那台的 `~/.claude/settings.json` 最外層加上這一行（路徑換成那台的帳號）：

```json
"claudeMdExcludes": ["C:/Users/<帳號>/AGENTS.md"],
```

## 沒做的與原因

| 沒做什麼 | 原因 |
|---|---|
| 在真的 session 裡跑一遍壓縮、背景子代理收尾、Codex 叫醒 | 要等日常使用時自然發生，程式沒辦法一次驗完；下方「驗證狀況」列了每項怎麼確認 |
| 8 個 skill 的觸發回歸整組實跑（`claude plugin eval`，這些 `evals/triggers.json` 從沒跑過） | 約 80 次短的無頭執行，超過兩分鐘，要你點名才跑 |
| 用 CC 的 agent teams（多隊友協作）取代 `/console` | 不採：功能還在實驗階段、隊友之間不隔離 worktree、無頭模式生不出隊友 |
| 把整個原子記憶系統打包成 CC plugin | 不採：常駐指令、狀態列、權限設定、git 同步的記憶資料都裝不進 plugin，而且 MCP 工具名會全部改掉 |
| 收尾閘的提醒改走官方 Stop 附註欄 | 不做：原生那個欄位會讓 AI 多跑一回合，代價等於擋一次；提醒照舊只留帳 |
| 在終端畫一行「這回合送了哪些卡」 | 這批沒排進來，留在計畫表 |
| `/doctor prompt-audit` 排進週健檢自動跑 | 它要叫模型審查，無頭跑超過 170 秒還沒完；只在報告列一行請你手動跑 |
| 依效用帳把沒用的卡降級 | 要等子代理效用帳修好後累積一段數據，才有依據 |
| `/rewind` 倒退對話後系統狀態跟著退；官方預告 `claude -p` 將預設 `--bare`（不讀登入與 hook），要先加版本偵測 | 這版沒做，留在計畫表的「要先跑探針」段 |
| 升級時把 `claudeMdExcludes` 帶到其他電腦 | 值裡有本機帳號路徑，帶過去是錯的；其他四個新設定安裝器會補（你沒設的才補），這一個用上面「要你動手的」第 4 條手補 |

## 驗證狀況

- **離線案例**：發行前重跑本版新增的 11 支、改過的 14 支相關驗證檔，全部綠（清單在[技術對照](技術對照.md#驗證檔)）。整組全量沒跑。
- **已在真的 session 看到的**：發行當天那場 session 用的就是新設定。截至寫這份文件，下面這幾支新 hook 已經有實際紀錄：
  - 規則載入：`Logs/instructions-loaded.jsonl` 14 筆。
  - 子代理啟動判定：`Logs/guard-subagent_start.jsonl` 2 筆。
  - 收尾延後：`Logs/guard-stop_background.jsonl` 15 筆，含一次延滿 5 次照擋。
  - 非真人不帶卡：`Logs/guard-ups_inject.jsonl` 3 筆，都是背景任務通知。
- **還要等實跑確認的**：

| 項目 | 怎麼確認 |
|---|---|
| 壓縮後第一時間送卡 | 真的壓縮過幾次後跑 `compact-reinject-report.py`，看 ratio 是否接近 17/18 |
| 不再誤判換專案 | 壓縮或重開後，不再出現「專案根變更」重建 |
| 子代理效用帳 | 背景子代理收尾後，它那筆注入紀錄從「已派出」變成「完成」 |
| Codex 叫醒 | 一次有發現的 Codex 審查，AI 在你沒說話時被叫醒 |
| auto memory 關閉 | 新 session 的系統提示裡沒有「# Memory」段，`/memory` 顯示 Auto-memory off |
| 給其他 AI 工具的說明 | 用 Codex 或 Gemini 實際連一次 MCP |
| API 錯誤留帳 | 遇到一次 API 錯誤後，`Logs/guard-stop_failure.jsonl` 有紀錄 |
| 非真人回合佔比下降 | 過幾天重跑 `injection-miss-report.py`，跟 63% 比 |
