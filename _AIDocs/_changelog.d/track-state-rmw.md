## 2026-10-23 平行工具呼叫的 hook 不再互相蓋掉 session state：讀檔、改檔紀錄不再掉
- **AI 寫程式時會看到的**：同一則回覆平行讀好幾個部位檔，每一筆讀檔都記得到，定位閘照擋訊息補完就放行，不再「照做了還被擋」、斷路器不再因此停手；平行改好幾個檔（含共用 session_id 的子代理），modified_files 每一筆都在、序號不重號，收尾閘看得到全部改動。
- **根因**：每支 hook 行程「讀 state → 加上自己那筆 → 整份寫回」，鎖只包寫檔那一下、讀那一步沒上鎖；平行的 hook 各自讀到同一份舊 state，最後寫的蓋掉其他人加的那筆。鎖拿不到時還會退回無鎖寫，換檔失敗只印一行就丟。
- **規則 STATE_RMW_LOCKED**（子規則 STATE_PENDING_MERGED）：dispatcher 進 handler 前開 hook 模式，handler 第一次讀某個 session 的 state 就拿它的鎖、握到 handler 結束，讀 → 改 → 寫整段在鎖裡、序號在鎖裡配。等鎖最多等到 hook 上限的一半（起點＝行程建立）；等不到不無鎖寫、不整份覆蓋：照讀沒上鎖的那份讓閘照判，寫回改留待併帳 `state-<sid>.<時間>-<pid>.pending`（只記跟這支行程基準比的變動；同一支再寫只記之後的），stderr 與 `Logs/guard-state_lock.jsonl` 留訊號；換檔失敗也改留待併帳。下一支拿到鎖的行程照欄位分型併回（集合取聯集、modified_files 逐筆併、累加計數兩邊都沒歸零才相加、回合與序號取大、時間取新、分版本整組新的勝、整組綁定與判不出的留磁碟那份並記下），併過的帳名跟合併結果同一次寫進 state（`_state_pending_applied`，帳檔還在就留著），刪不掉的下次跳過再刪，不會套兩次；自己留過的帳沒全部落盤前，同一支再寫也只留帳；轉址 stub 上的帳併進 stub 自己、不碰目標並浮訊號。讀到檔不在＝讀到空 state（留的帳逐欄合併、不當整份換掉）；fallback 重建的 state 不蓋掉鎖裡已存在的檔。沒進 hook 模式的寫者寫回時拿鎖，鎖裡發現檔跟自己的基準比被換過照同一套三方合併。
- **改了什麼**（軌 track-state-rmw）：`hooks/wg_core.py` state 讀寫段（`read_state_status`、`write_state`、`begin_state_rmw`／`end_state_rmw`、鎖、待併帳、`_merge_state`／`_MERGE_TYPES`；`_find_active_sibling_state` 挑中的那份鎖後重讀、重驗資格；`_ensure_state` fallback 收到轉址 stub 時跟到目標）、`hooks/dispatcher.py`（開／關 hook 模式、等鎖期限）、`hooks/handlers/post_tool_use.py`（過時註解）、`hooks/handlers/_shared.py`（待併帳 7 天清）、`hooks/wg_release_rules.py`（RULES 登錄）。文件：TECH.md §3.1 state 讀寫一段、§7.8 一列與條數。
- **驗證**：新案例 `hooks/verify/verify_state_parallel_rmw.py`（29 案：真 hook 子行程並行 4 支 Read、4 支 Write、兩行程各 30 次讀改寫、拿不到鎖留帳再併回；待併帳的各種交錯；合併分型）；拿改前的碼跑 4 個並行案全紅（讀檔 4 筆剩 1、改檔 4 筆剩 1 且序號都是 1、兩行程讀改寫一方整批掉），改後連跑兩次全綠。`verify_state_write_concurrency.py` 改成新契約（拿不到鎖不無鎖寫、換不掉留待併帳）。目標 verify 37 支全綠。量測 `hooks/verify/probe_state_parallel_perf.py`（各 3 輪）：平行 4／10 支 PostToolUse，改前掉 9/12、22～24/30 筆，改後 0 筆；最慢一支 4 支 0.57 秒、10 支 1.15 秒（改前 0.46／0.70 秒；上限 5 秒）；別人握鎖 1.8 秒時 10 支最慢 2.35 秒、照排隊；握 3.5 秒時全部在期限留帳、最慢 2.72 秒結束，下一支併回後 0 筆掉。無頭實跑一題（同一則回覆：Bash 註解交定位行＋平行 4 個 Read，再改部位檔）：定位閘第 2 次放行（`part_files_read 2`、`reads_after_inject 4`），沒警報。codex 四輪：第一輪 5 個 BLOCK、第二輪 4 個、第三輪 3 個，全在拿不到鎖的退路（併帳偷換基準、多次留帳重算、刪不掉重套、計數合成負數、讀不到被當整份換掉、轉址 stub、自己的帳沒落盤就直接寫），每條先補會紅案例再修；「把 stub 的帳轉給目標」整段拿掉。
