## 2026-10-23 用 Bash 內嵌 python／heredoc 改檔，收尾三道閘照樣看得到改動
- **AI 寫程式時會看到的**：只用 `python -c "…"`、`python - <<'EOF' … EOF` 這類判不出寫入目標的指令改程式，收尾照樣被要求補驗證案例（對帳）、照數程式檔要第二意見、沒提交照樣提醒同步；指令以非零結束（只送 PostToolUseFailure）也一樣。
- **根因**：Bash／PowerShell 的寫入目標判不出時（`write_paths_from_tool` 回 `UNKNOWN:…`），hook 只記一筆 `unknown_writes`，`modified_files` 不記；收尾的對帳、第二意見、同步提醒都只看 `modified_files`，整個 session 改了幾支程式都看不到，跑完留下沒提交的改動也沒人提醒（量測補題第一版：改 3 支程式加 2 支測試，三道都沒擋，留 6 個沒提交的改動）。指令非零結束時 Claude Code 只送 PostToolUseFailure，那條路連 `unknown_writes` 都不記。
- **規則 UNKNOWN_WRITE_RECOVERED**：判不出目標的指令跑完後，從版控狀態補出它真的改了哪些檔、記進 `modified_files`（`via=vcs_status`）。「真的改了」＝git status／svn status 列為改動或未納管，而且 mtime 落在這次指令開始時間減 0.05 秒到現在加 2 秒之間：快照前就髒、這次沒動的檔不算，使用者或別的 session 在這條指令開始前的改動也不算；本 session 已經記過、內容雜湊跟上次一樣（或太大沒雜湊而 mtime 沒晚於上次記下的時間）的不算、不刷回合。開始時間＝transcript 裡這筆 tool_use 的時戳；同一則回覆平行送出的第一個工具跑完時這則紀錄常還沒落盤，就用已落盤的最後一筆紀錄的時間。整棵 status 超過 1.2 秒 → 只查指令文字裡點名、存在的檔（幾個根合用 0.8 秒），同 session 之後這個根直接只查點名的。不在 git／svn、找不到開始時間、查詢失敗 → 照舊只記未知寫入，那一筆寫明補不到的原因。
  - 為什麼不用「session 開頭拍一份 status 快照、之後比」：兩次查詢之間別人的改動（使用者在 IDE 改、別的 session）全會被算成這條指令改的；用這條指令自己的開始時間當界線，只收它跑的那段時間內被寫過的檔。也不用改 PreToolUse 與 SessionStart。
