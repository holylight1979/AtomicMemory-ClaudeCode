## 2026-10-22 寫卡的衝突／去重宣告不再退件循環
- **AI 寫卡時會看到的**：`atom_write` 被退件後照訊息改一次就收，不會再被第二次退。
  - **衝突宣告**：要宣告的名單是這次向量前幾名，不隨本地模型的標籤翻面；知識段不改就重送，名單不變。多寫不在名單的卡會略過、不算錯；不同層有同名卡時寫成 `<layer>:<卡名>`，各判一次。AI 已宣告某張是衝突、但重送時本地模型沒標（或本地模型全部判不出）→ 照宣告落待審，不寫進 shared；這時宣告不全不要求補，但同一張兩種判法照樣不收。守門總開關關時不要求宣告，照門檻判：穩定 CONTRADICT → 待審報告，EXTEND≥0.85 → 整張卡改落 `shared/_pending_review` 草稿（同名草稿已在就拒寫，不覆寫）。同名的衝突報告還沒審又衝突一次 → 另起 `<slug>.<n>.conflict.md`（獨占建立，兩個 MCP 行程同時寫也不互蓋），兩份都列在 `/conflict pending`；核准 `<slug>` 只收掉 `<slug>.conflict.md`，後來那份照樣待審。
  - **去重宣告**：`of` 不在這次前 3 名、但在這次比對的層裡存在 → 收；沒有相似候選但宣告 `same`／`supersedes` → 照宣告併入／取代（那張卡找不到就拒寫說明，不另建新卡）；`different` 照常寫。併入的舊卡已滿 → 訊息直接給「壓縮舊卡（mode=replace）或把這次的內容改寫進文件」兩條路。
- **改了什麼**：`tools/memory-conflict-detector.py`：`_apply_declaration` 名單改用向量前幾名（同名卡用 ref）、沒候選（或本地模型全部 ERROR）時附理由的 conflict 宣告照宣告 contradict、`_v6_on` 接守門總開關；`vector_search` 改讀 config 的 `vector_search.service_port`（沒設才 3849）。`tools/memory-write-gate.py`：`resolve_dedupe`（候選之外到比對層查同名卡，用向量索引同一套 `discover_layers`／`discover_atoms`；supersedes 遇到跨層同名就拒）、沒候選照宣告走、append 超預算訊息。`tools/workflow-guardian-mcp/lib/atom-tools.js`：開關關時 extend_overlap 改道待審草稿、同名 `.conflict.md` 另起檔名不覆寫、退件訊息、註解改中性；`lib/mcp.js` 的 dedupe／conflict 參數說明。`tools/workflow-guardian-mcp/verify/smoke_mcp_stdio.js` 自帶暫存資料根、明帶 `WG_V6=1`，並對帳啟動紀錄不落正式資料根。
- **驗證**：新案例 `hooks/verify/verify_mcp_write_gate.py`（含兩條流程級：退一次、照訊息改一次就收）；既有 `verify_g6_rules_to_llm`、`verify_conflict_write_gate`、`verify_conflict_evidence`、`verify_memory_write_gate_dedupe`、`verify_atom_write_dedupe.js`、`verify_atom_write_judgments.js` 對齊新行為；換回改前的碼跑會紅。合進 main 後要 Reload Window，MCP 才會載到新的 js。
