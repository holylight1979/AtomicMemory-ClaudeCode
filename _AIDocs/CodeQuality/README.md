# CodeQuality：C# 遊戲程式碼品質彙整

這個資料夾放「寫碼與審碼時要避開什麼、要做成什麼樣」的彙整。LLM 寫碼或審碼前，先看總彙整。

| 檔 | 是什麼 | 什麼時候讀 |
|---|---|---|
| `總彙整-主題子題與關注權重.md` | 14 個主題、99 個子題的單層索引。每個子題有一句可數認法、嚴重性、本機踩過、LLM 常犯、權重 0～6、指向來源檔 | 每次寫碼或審碼先讀第 1 節；命中主題再讀第 2 節 |
| `總彙整.json` | 同一份子題表的機器版（id、signal、severity、granularity、local_evidence、llm_prone、weight、refs） | 要用程式篩權重、做檢查清單時 |
| `全面CSharpServer危險彙整.md` | C# 伺服器的危險狀態與壞味道全集：執行緒、async、GC、網路、資料庫、序列化、部署 | 寫或審伺服器碼時 |
| `全面CSharp遊戲Client危險彙整.md` | Unity 客戶端的危險狀態與壞味道全集：生命週期、偽 null、每幀配置、資源、UI、熱更、IL2CPP | 寫或審 Unity 客戶端碼時 |
| `全面CSharp遊戲開發通用危險彙整.md` | 客戶端與伺服器共通：玩法架構、網路同步、資料表、存檔、數值經濟、隨機、時間、LLM 產碼、驗證 | 碰到遊戲邏輯、存檔、經濟、時間時 |
| `全面CSharp遊戲開發可讀性與優良設計彙整.md` | 正面清單：怎樣算好、怎麼量；末尾有給 LLM 的 30 行索引 | 要決定「寫成什麼樣」時 |

另有兩份上游不在本資料夾：`../Research/code-smells/`（513 條壞味道的定義與判準，是各彙整「既有」欄的指向對象）、記憶庫根層的 `memory/Failures/`（本機踩過的流程與判斷卡）。

## 讀的順序
1. 總彙整第 1 節：用一句可數認法對照手上的程式碼或 diff，找出命中的主題。
2. 總彙整第 2 節：看該主題的子題表，權重高的先處理。
3. 照「指向」欄去讀來源檔的原條目，特別看「何時不算」再報。
4. 第一次接觸整批資料夾時，先讀可讀性彙整的 30 行索引，再讀通用，再依角色讀 Client 或 Server。

## 總彙整怎麼用
- 權重 ＝ 嚴重性（致命 3／嚴重 2／中 1／低 0）＋本機踩過（+2）＋LLM 常犯（+1）。它排的是關注順序，不是判決。
- 指向欄的縮寫：`SV` Server、`CL` Client、`GN` 通用、`RD` 可讀性；`01`～`09` 是 Research/code-smells 的分支檔。
