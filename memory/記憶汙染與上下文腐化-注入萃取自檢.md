## 知識

- [臨] 大型專案多 session 接續下「焦點模糊、回應偏門、範圍縮小卻更耗時、讀原生內容後扭曲避重」= 已命名現象群「上下文腐化 context rot」+「記憶治理失敗（memory governance failure）」，非單純 token 多。對策非省 token，而是 selective forgetting + relevance gating + 最小高訊號集——避免汙染 > 省 token。
- 以下為病徵→術語對應（Drew Breunig 4 失效模式）：

| 病徵 | 術語 | 機制 |
|---|---|---|
| 讀原生內容後扭曲避重 | Context Poisoning | 錯誤進 context 被反覆引用成假地基 |
| 焦點糊·範圍縮·更耗時 | Context Distraction | 過度聚焦 context、忽略訓練能力 |
| 回應越走越偏門 | Context Confusion | 多餘內容被拿去生成低品質回應 |
| 多 session 矛盾累積 | Context Clash | 新舊資訊互相打架 |

- [臨] 學門分層：Context Engineering（塞什麼進視窗，Anthropic「最小高訊號 token 集」）/ Agent Memory Management·Memory Governance（長期記憶庫的形成·檢索·遺忘·汙染·漂移治理，本系統屬此）/ 人類根理論 Cognitive Load Theory（extraneous load=無關材料拖垮處理）。
- [臨] 既有 anti-pollution DNA：decisions.md 已把 ReadHits 降純曝光、不參與晉升（防純注入頻率劣化品質）；Task 2 hook 順此延伸。全貌見 _AIDocs/context-memory-governance.md。

## 行動

- 開大型/多 session 任務或感覺偏離時，自檢四問：① 這條 context 是高訊號還是 distractor？② 有無被前面的錯誤/摘要 poison？③ 有無與現有資訊 clash？④ 範圍是否在縮小（distraction）？
- 設計/改記憶系統注入·萃取 hook：注入做 relevance gate + 最小集裁切（ups_inject/ups_search）；萃取做 poisoning gate—來源實證/信心（memory-write-gate）；衰減做過期低效用主動隔離（selective forgetting）。
- 萃取寫 atom 前先過『這是實證還是幻覺/臆測』，防 context poisoning 進庫被反覆注入。
