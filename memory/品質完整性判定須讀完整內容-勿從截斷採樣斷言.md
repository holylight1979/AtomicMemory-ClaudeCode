## 知識

- [臨] **始末**（2026-06-30，記憶系統去蕪設計）：寫去蕪 runner 時只餵 `excerpt=body[:200]` 給分類器、自己也只看 excerpt → 斷言「draft 不是垃圾、is_real 不需要自動去蕪」。user 反問「你看過完整內容嗎?」並貼出一份截斷 draft（半詞 `Deser`、反引號未閉合）→ 讀完整 + 全量確定性掃描後實證：142 draft 中 40% 是截斷損壞或近重複（GM Blocker 5 份、RebuildBlobAsync 4 份）。正確做法＝斷言品質/完整性/重複前，讀完整內容或跑全量確定性掃描。
- [臨] **根因**：把「分類用的輸入視圖」（`excerpt[:200]`，為 token 經濟而截斷，對餵分類器是對的）**誤用為「品質判定的證據」**——兩者是不同問題。失效恰好住在採樣視窗之外：截斷發生在 200 字後、重複在 excerpt 看似各自獨立 → 對採樣視圖**結構性不可見**。
- [臨] **設計原理（為何誘人）**：`excerpt[:200]` 對「餵分類器」是合理省 token 設計；錯在拿同一截斷視圖去回答「這是不是垃圾/截斷/重複」這個需要完整產物＋跨產物比對的不同問題。局部（分類）成立 ≠ 可推及（品質）。
- [臨] **運作邏輯斷點**：「是不是垃圾/截斷/重複」需要 (a) 完整內容判截斷 (b) 跨產物相似度判重複；採樣的「單產物前 200 字」管線兩者都看不到，所以無論掃幾條都得出「沒垃圾」的假結論。
- [臨] **防再犯**：斷言任何產物的品質/完整性/重複/「沒問題」前，**讀完整內容或跑全量確定性掃描**，不從截斷/採樣/單一視窗斷言；確定性結構偵測（截斷訊號、文本相似度）比 LLM 主觀評分可靠。本條是 [[feedback-未實證先別斷言-從根源驗證-先證再修-反退避反冗長]] 的具體實例（『未實證先別斷言』→『別從有損樣本斷言』），與 [[cognitive-patterns]] 過度概化同根。

## 行動

- 斷言產物品質/完整性/重複前，讀完整內容或全量確定性掃描，不從截斷/採樣視窗斷言
- 判品質用確定性結構訊號（截斷/相似度）優先於 LLM 主觀評分
