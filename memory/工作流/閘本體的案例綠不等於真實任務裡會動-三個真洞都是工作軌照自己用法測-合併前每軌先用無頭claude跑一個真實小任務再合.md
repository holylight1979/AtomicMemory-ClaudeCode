## 知識

- [臨] 實證：三條閘軌都交了十幾到六十支案例全綠、Codex 審過，聯合驗收三題仍抓出三個真洞，全是「案例綠、真實任務裡沒動」：commit 閘只測過 Bash 單行、沒測 Claude 在 Windows 實際常用的 PowerShell 多行訊息加 pathspec；目標樹跨 session 假設前一個 session 會留接續單；意圖分類沒想到回合裡會夾同伴訊息。共同根因：工作軌照自己的用法寫測試，沒照使用者的用法跑一次；單元測試越多越容易以為沒事。後果是完工時程算不準：洞要到驗收才浮出來。
- [臨] 改法：每條閘軌合併前，總控台用無頭 `claude -p`（乾淨資料根、`--resume` 續接）對它跑一個真實小任務，看它在真實交付裡有沒有動，再合；抓到的洞當場開小軌修，不累積到驗收結論。驗收自己讀太多材料會視野縮小，判分由乾淨 context 的 agent（跟主持者不同模型）與 Codex 各自獨立做——本次 AI 自己新寫的 lambda 沒被點名這個洞就是獨立判分者抓到的。

## 行動

- 收閘本體的交付：案例綠只是門檻，合併前必跑一個真實小任務（用使用者實際的工具與寫法）
- 驗收判分不自己做：開乾淨 context agent（不同模型）與 Codex 各判一次，只比對分歧
