## 知識

- [臨] 幾十萬字的文件分段交多個 agent 改寫：寫一份共同規格檔（不准刪事實、標題編號不動、反引號內容逐字留、排版規則），每段一個 agent 讀原稿快照、寫到暫存檔，主控組裝。跨段與跨檔連結 agent 只寫佔位符（例 APPX:4.1、MAIN:4.1、DOC:名），由後製程式依組裝後的真標題算錨點；讓 agent 自己算錨點會錯。
- [臨] 驗「沒掉資訊」不靠 agent 自報（它們都說沒逐字比對）：拿原稿的反引號內容、大寫規則名、HTML 計數標記、帶單位的數字、「」引語逐一在新文件裡找，找不到的逐條人工判。表格內的 `\|` 搬出表格後變 `|` 要當同一個。這樣比 agent 回報可靠，也抓得到改寫者新增的推論數字。
- [臨] 共用工作樹還有別的 session 在跑時，改寫用開場快照當底，放回前先比 HEAD 與快照，確認別人沒改同一個檔；提交只 stage 自己的檔。

## 行動

- 大文件改寫先寫共同規格檔與佔位符連結格式，再分段派 agent
- 組裝後跑反引號／規則名／標記／數字／引語五類比對，缺的逐條查
- 放回 repo 前 diff HEAD 對開場快照
