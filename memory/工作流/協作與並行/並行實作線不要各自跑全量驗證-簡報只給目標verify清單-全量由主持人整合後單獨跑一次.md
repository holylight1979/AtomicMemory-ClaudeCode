## 知識

- [臨] 實踩（2026-10-01，三線並行實作）：三份派工簡報都寫「最後跑 `run_verify.py --json`」，結果三份約 12 分鐘的全量同時跑、互相拖慢，一份被 10 分鐘上限砍掉；各線反覆回「等全量」的中途狀態，主持人白等。
- [臨] 正解：簡報明寫「只跑目標 verify 清單、**不跑全量**」；全量由主持人在整合後單獨跑一次，跑的期間不改程式、不做別的 git 操作（git／svn 端到端測試在並行 git 活動下會偶發單案紅）。已派出的線可用 SendMessage 叫停全量、要它立即依格式回報。
- [臨] 多線會碰同一個設定檔／入口檔時，簡報要寫「只動自己那幾行、Edit 前重讀、用文字插入不整檔重寫」並指定誰最後合併；線與線之間的介面透傳（例 A 線加參數、B 線的入口要透傳）留給主持人收尾，避免兩線互等。另：線內驗證紅了先用乾淨的 HEAD worktree 重跑同一支，分辨「既有紅」與「本次造成」。

## 行動

- 派並行實作線：簡報列目標 verify 檔名，明寫不跑全量、不 commit、不改文件
- 整合後主持人單獨跑一次全量，期間不動程式與 git
- 全量有紅：先在 HEAD worktree 重跑判定是否既有
