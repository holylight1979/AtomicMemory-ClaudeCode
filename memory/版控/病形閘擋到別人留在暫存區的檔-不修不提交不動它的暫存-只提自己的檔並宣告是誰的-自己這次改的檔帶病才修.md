## 知識

- [臨] 被病形閘擋，先查事實再分類：這個 session 我用 Edit／Write 改過的檔＝我的；session 開始時就已經在暫存區、我沒改過的＝別人的。只看這個事實分，不看檔名或病名。
- [臨] 我的檔帶病 → 修掉再提交；判斷過確實該這樣寫就在那一行加註解 `smell-ok: <為什麼>`。不准把自己的檔移出暫存或排除來躲。別人的檔帶病 → 不修、不 restore（不動它的暫存），只提交自己的檔：`git commit -- <我的檔…>`。
- [臨] 「宣告是誰的」指的是收尾報告裡講明：哪個檔是 session 開始前就留在暫存區的別人改動、不屬這次需求、病留給它的主人修。不是指令裡寫宣告行。
- [臨] 兩類都有就分開處理。例：a.py 我改的（帶病）、b.py 別人的（帶病）→ 修 a.py，`git commit -- a.py <我其他的檔>`，收尾報告寫 b.py 是誰的、為什麼沒動。擋訊息「把 ✗ 那幾行改掉再 commit」只適用於我的檔；舊碼原樣搬動、改名、合併進來的別人分支也不修，原樣再送一次。
- [臨] 病形閘同一回合同一個 repo 只擋一次，再送就放行並留帳；沒修就提交的病要寫進收尾報告「AI 自己做主」那類，說明為什麼沒修。

## 行動

- 逐檔問：這次我改過它嗎？改過 → 修或 smell-ok；沒改過 → git commit -- <我的檔> 只提自己的，收尾報告講明它是誰的
