## 知識

- [臨] 交辦寫「某閘擋了 N 輪、要加 X 來解」時，動手前做兩件事：①拿實跑紀錄（transcript、守門帳）實際數一次那個問題出現幾次；②找有沒有既有機制已經在處理同一件事。
- [臨] 實例：交辦說收尾一再被「沒測試收據／沒案例」擋，要加先提示；實數五跑擋 0 次——早就有「第一次改程式就先問驗證範圍」的既有提示，AI 照做了。
- [臨] 前提不成立時，交付就是「已不成立＋證據」，不做；硬做只會多一段注入、沒有任何收益。

## 行動

- 接到「問題發生了 N 次」型交辦，先用實跑紀錄數，數字對上才動手
- 同時查同一時點有沒有既有提示或閘在講同一件事
- 前提不成立 → 回報「不成立＋數據出處」並結案，不順手做
