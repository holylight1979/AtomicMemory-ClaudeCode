## 知識

- [臨] 實例：閱讀路徑掃描器（呼叫圖量「人讀要跳幾層」）的『全確定』數字號稱可信下限，但連續三輪正式審都找到白名單外的邊被判確定。根因是確定是預設值——邊沒被標不確定就算確定，任何新解析路或舊路漏一個條件都會默默變確定。改成：每條邊帶 rule（白名單條號），只有一個 certify 入口能填，各條白名單一個正向判斷式；之後審查找到的問題全部變成『證據收不齊』，再也沒有繞過入口的。
- [臨] 正向證明之後又被退兩輪，原因是入口內接受了不足或指錯的證據。逐例補漏會一直被新反例追著跑；改用『證據家族規則』一次封整類才收斂：①找目標與證明穩定共用同一次作用域查找（遵守 global／nonlocal，結果是哪個作用域的哪個綁定，不是布林值）②建構變數的資格用『之後每次出現都只是方法呼叫接收者』正向證明，不列舉各種存走寫法 ③類別／型別證據只認綁定鏈解析到專案內，同名搜尋只給候選、外部 import 不連同名專案類別 ④目標本身（方法在類別上的綁定）也要證明沒被改寫。
- [臨] 規則寫死的同時要寫明防線邊界（exec／eval、setattr 帶變數名、globals()[…]、metaclass、import 副作用、反射），邊界外不追、不當退件理由，審查才不會無止境加嚴。
- [臨] 收緊規則時要防『誠實寫法被降級』：例 try/except ImportError 雙寫 import 指向同一目標是正常寫法，判穩定要比對每次綁定的最終目標，只在目標不同、外部或解析不了時才判不穩定。驗證要兩向：能不能被繞過，誠實寫法能不能如實被認成確定。

## 行動

- 設計『可信下限』計數：確定只由單一入口依白名單正向給條號，其他路一律不確定
- 同一面被退第二次：改寫成封整類的證據家族規則，不再逐例補
- 規則定稿時同步寫防線邊界，並用兩向審查（繞過／誠實寫法誤降級）
