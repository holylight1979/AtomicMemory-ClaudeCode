# 有上限的候選池挑法-量少又關鍵的先放-量大的類別放後面-照字面順序做要拿真資料驗目的

## 知識

- [臨] 池子有上限、要照類別先後填時，先放「量少且就是目的本身」的那類，量可能很大的類別（同目錄、同前綴、全掃）放後面：否則大類別先把上限吃光，關鍵的項目排不進去。實例：C# 查找池上限 1500，照規格字面「同目錄優先、再放繼承指到的檔」，萬檔專案裡改到的檔若在產生碼大目錄，同目錄就吃光 1500，接不到的基底 16 → 17（沒改善）；繼承鏈改成優先後 16 → 0。
- [臨] 挑法要決定不了是誰的預算時，用「目的指標」實跑前後對照（例：接不到的基底數），不用「池有沒有填滿」當替身；池是挑出來的就要把「看到的數是下限」傳下去，不據此下「只有一個」這類結論。

## 行動

- 設計有上限的挑選順序：先估每類可能多大，量大的類別放後面
- 照別人給的順序做完，用真實資料量目的指標前後對照；沒改善就回報字面與目的的落差並改順序
