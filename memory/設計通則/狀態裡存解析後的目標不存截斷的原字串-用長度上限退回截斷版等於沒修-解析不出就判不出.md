# 狀態裡存解析後的目標不存截斷的原字串-用長度上限退回截斷版等於沒修-解析不出就判不出

- Scope: global
- Author: holylight
- Source: 2026-10-23 斷路器與紅測閘修補實測
- Confidence: [臨]
- Trigger: 存狀態, 截斷字串, 長度上限, 重新解析, 解析後的目標, 存原字串, 判涵蓋
- Created-at: 2026-10-22

## 知識

- [臨] 要留著之後拿來比對的狀態，存「解析後的目標」，不要存截斷過的原字串；超過長度上限就退回存截斷版，等於沒修。
- [臨] 實例：紅測只存指令前 200 字，之後判「重跑有沒有涵蓋」時重新解析截斷字串，`2>&1` 被切剩的 `2` 被當成目錄，什麼重跑都涵蓋不到。
- [臨] 正解：存解析後的形狀（每段測試子命令＋點名的檔／目錄／節點／篩選＋前面的 cd），跟長度無關；解析不出就判「判不出」，不拿字串片段當路徑。

## 行動

- 設計要存起來事後比對的狀態時，先問存的是解析結果還是原字串
- 看到「超過上限就截斷」的退路，檢查之後是不是會重新解析那段截斷字串
