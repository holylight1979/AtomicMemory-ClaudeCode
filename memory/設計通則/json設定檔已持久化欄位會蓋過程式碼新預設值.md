## 知識

- [臨] 凡是「程式碼寫預設值 → 序列化整包存 JSON → 下次啟動反序列化」的設定，一旦使用者跑過一次舊版，該欄位就已用舊值落地。之後改程式碼預設值對既有安裝完全無效，反序列化會用檔案裡的舊值覆蓋。
- [臨] 最容易踩的是「集合型預設值」（黑名單／白名單／樣式清單）：改碼加減一項後自測是新環境所以正常，使用者端卻毫無變化，會誤判成「改的地方不對」而反覆改碼。
- [臨] 判定方式：改完預設值後直接打開實際設定檔（如 %APPDATA%/<app>/*.json）看該欄位的真實值，不要只看程式碼。
- [臨] 正解二選一：①載入後加一段遷移碼（偵測到舊值就改寫並存檔，並輸出訊息說明已遷移）②改預設值時同步清掉設定檔中該欄位（必須在程式關閉狀態下改，否則執行中的實例存檔會蓋回去）。
- [臨] 實例（MudClient-withAI 2026-08-18）：把 AI 指令禁令清單的程式碼預設值清空後，執行中的 client 仍持續擋掉 set，因為 mud-settings.json 的 Ai.ForbiddenCommands 還留著舊清單。

## 行動

- 改任何「有存進設定檔」的預設值時，同時處理既有設定檔（遷移碼或手動清欄位），不要只改程式碼
- 驗證要看實際設定檔內容，不是看程式碼預設值
- 改設定檔前先關掉程式，避免執行中的實例存檔覆蓋
