# 放行或豁免要綁使用者看過的那幾件-鍵用規則加完整對象-之後又改了檔就失效

- Scope: global
- Author: holylight
- Source: 2026-10-22 stop-gates 減量實測
- Confidence: [臨]
- Trigger: 放行, 豁免, 放行鍵, 同一件判定, 擋訊息摘要, 放行失效, 紅測放行, 失敗節點, 使用者看過的項目
- Created-at: 2026-10-22
- Related: feedback-閘門反覆擋同一件事時要修判定的根因-不要一再請使用者放行

## 知識

- [臨] 拿擋訊息的摘要字串當「同一件」的鍵（檔名只列前四個、紅測只列前三支），新問題會躲在舊放行底下；鍵要用「規則＋完整對象」（紅測＝指令＋全部失敗節點）。
- [臨] 只記擋訊息列給使用者看過的那幾件；放行之後又改了檔，整份放行失效；沒有結構化條目的段（例如判定錯誤）要自己算一件。

## 行動

- 設計放行記錄時，鍵用規則名＋完整對象，不用擋訊息顯示用的截斷摘要
- 放行後偵測到新的檔案改動，就讓整份放行失效
