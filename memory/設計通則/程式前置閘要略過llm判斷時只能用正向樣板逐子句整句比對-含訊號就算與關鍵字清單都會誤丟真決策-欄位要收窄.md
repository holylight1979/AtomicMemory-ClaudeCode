## 知識

- [臨] 情境：在送 LLM 判斷之前加一道「便宜的程式前置閘」，命中就不送 LLM（例：攔掉一次性派工句不送使用者決策萃取）。程式閘的錯誤方向是「誤丟」：一旦攔下，真決策就再也沒機會被 LLM 看到；漏攔只是多花一次 LLM。所以閘只能在「確定整則都是要攔的那種」時才攔，確定不了一律交 LLM。
- [臨] 實踩的五種誤丟寫法（同一面被退件五輪才收斂）：① 「句子含派工訊號就算派工句」：『第一步用 EnterWorktree…，所有 repo 的 commit message 一律繁體中文』整則被攔；② 靠長期／決策關鍵字清單豁免：清單永遠補不完（『我決定』『統一用』都漏過）；③ 換行沒算句界：分行寫的決策併進派工句；④ 欄位收太寬：路徑欄位 `[^\s，。；]*` 把『C:\wt\x、所有專案一律禁止刪除備份』整串吃成路徑，fullmatch 擋不住；⑤ 自由括號欄位 `（[^（）]{0,30}）`：『你是工作 session track-x（所有專案一律用 UTF-8）』被攔。
- [臨] 收斂的做法：把整則切成子句（句號、逗號、分號、換行；頓號不切；括號內不切），每個子句都必須 fullmatch 一組正向樣板（樣板取自實際開過的句子），任何子句對不上就整則交 LLM；樣板裡的欄位只收窄字元集（路徑、名稱、分支只收 ASCII），自由說明改成固定完整句型清單；不用負向關鍵字清單。代價是陌生寫法（中文路徑、新的說明句）認不出、交 LLM，這是安全的一邊。
- [臨] 驗法：每個樣板欄位都要有一個『欄位後面頓號或直接接一句決策』的反例斷言交 LLM；再加一個『經入口（前置閘排隊）到 worker』的案，確認真決策有送到 LLM。
- [臨] 欄位收窄的代價是「漏攒」：開工句樣板的路徑、名稱欄位只收 ASCII，原設計者的一般句型「接手「<中文名稱>」的根層總控端。先讀 <中文檔名的接續單> 全文」就判不出，對 Quote 回填來說漏攒＝把開工句填成使用者原話，清了還會被回填填回來。放寬的做法：只對那一種子句放寬那一個欄位（名稱限全形引號內、路徑用 \w 但不收空白與標點），仍整句 fullmatch；用真卡上的 Quote 原文當會紅案例，再補「角色句後接決策、引號開頭、問句、先讀沒路徑、全文後接決策」五個反例。

## 行動

- 寫『命中就略過 LLM』的程式閘前先問：誤丟和漏攔哪個貴？誤丟貴就只做正向整句比對，確定不了交 LLM
- 樣板欄位用窄字元集、說明句用固定清單；每個欄位補一個吞決策的反例
- 不要用『含訊號就算』或關鍵字豁免清單決定略過
