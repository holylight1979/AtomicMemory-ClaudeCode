## 知識

- [臨] 原設計者定的行為（回答「搬整個程式目錄該不該欠驗證案例」）：不是欠不欠案例的問題。①要擴大搜尋，確保腳本內沒有對特定路徑做絕對或相對的寫死，有就跟著修碼；②不論有無修路徑，驗證是針對該語言特性做抽樣驗證，不必硬性全量欠驗，主要確保功能依然正常；例：C# 要注意 .csproj 與 .sln 的編譯檔案囊括範圍，搬了位置不能變成無法編譯。
- [臨] 落地分工：閘加一條有名規則「搬程式目錄」，欠的是「路徑引用掃描收據＋抽樣驗證收據」；掃描舊路徑字串由程式做，抽哪些驗與語言特性交 LLM 判斷。
- [臨] 程式換位置的另一種情況：在暫用工作樹裡寫的腳本寫死了那棵工作樹的絕對路徑，合進主線、工作樹拆掉後，主線上的腳本直接跑就 import 失敗。路徑照腳本自己的位置推（`Path(__file__).resolve().parent…`），不寫死任何工作樹的絕對路徑。

## 行動

- 搬程式目錄或腳本：先全庫 grep 舊路徑（絕對與相對），命中就修；再依語言特性抽樣跑功能（C# 先確認 csproj／sln 囊括、能編譯）
