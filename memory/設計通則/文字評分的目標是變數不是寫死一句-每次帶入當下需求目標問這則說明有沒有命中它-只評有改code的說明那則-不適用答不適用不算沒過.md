## 知識

- [臨] 原設計者：「所謂的目標，套用在 v6 框架下並不是訂死一個，而是要針對當下的目標，具備靈活塞變數的彈性」。例：目標「去除冗餘、重構特定類別與 cs、檔案允許延展」→ R1 第一句要講冗餘去了多少、哪些重構完；R2 要說延展出的檔哪些要他看；R7 證據是重構前後等值。裁判先給目標句再逐條問「針對這個目標過不過」；沒目標不評。
- [臨] 只評「有改 code 事實＋說明做了什麼」那一則；純對話不評（他看到一則安排順序的回報被判 2/7 說「雞肋」：2、3 他看得懂、4／6／7 根本不適用）；不適用的條目答「不適用」不算沒過。

## 行動

- 設計任何 LLM 裁判規格：目標欄留佔位符，評分時從目標樹或本回合原話填入
- 評分觸發條件對準原話情境（寫碼後的說明），不每則都評
