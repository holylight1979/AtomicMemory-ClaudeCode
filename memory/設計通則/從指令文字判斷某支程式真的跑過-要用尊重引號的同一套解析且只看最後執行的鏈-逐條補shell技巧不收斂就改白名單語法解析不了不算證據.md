## 知識

- [臨] 情境：閘要從「執行過的指令字串」判斷某把尺（表上的指令）有沒有真的跑、哨兵行是不是它印的。子字串比對會被 `echo '…量尺…'` 冒充；不管引號就按 ; && | 切段，引號裡的量尺會被切成「指令」，而且量尺端若整串比、收據端切段，`… && echo X DONE` 這種串接式量尺原樣跑也永遠對不上（誠實流程被永久卡死）。量尺與收據必須經同一套解析。
- [臨] 解析後仍有整組繞法，都是「在一般 shell 語法裡印假哨兵行」：`假哨兵 || 量尺`（量尺沒執行）、`$( … false && 量尺)`、heredoc／區塊註解／純字串裡寫量尺、`python -h 量尺`（不執行腳本）、`| tail <<< 假哨兵` 或 `| tail 舊.log`、`pytest -k 某案`／`--collect-only` 冒充整體驗證、收據只存前 200 字讓尾端假哨兵變成「量尺在最後」。逐條補只會引出下一種寫法；同一面退回第二次就改規則。
- [臨] 定死的規則：白名單語法（單一指令與 && || | ; 換行串起的鏈、單雙引號、重導向、行首 # 註解、行首環境指定）；白名單外語法一出現（命令替換、反引號、子 shell、script block、here-string、eval／iex／source／`bash -c`／控制結構、單獨 &、引號沒閉合）整條不算證據（fail-closed），擋訊息寫是哪種語法；量尺鏈前只准開頭／;／換行／&&，之後只准只會刪行的過濾；收據存完整指令。誠實流程就是照表上原字串跑，用不到那些語法。
- [臨] 「哨兵行是哪個指令印的」從文字原理上判不出來：只要有一個非 echo 指令提到改的檔（例 `cat tests/test_a.py && echo X_CHECK PASS`），就仍會被認成「驗到了」。這類邊界要寫進防線說明，不要宣稱封死。
