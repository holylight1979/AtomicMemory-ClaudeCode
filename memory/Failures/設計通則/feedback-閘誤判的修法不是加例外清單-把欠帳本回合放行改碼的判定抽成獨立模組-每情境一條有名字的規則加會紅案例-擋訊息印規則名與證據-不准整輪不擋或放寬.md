## 知識

- [臨] 使用者原話（七個工作分頁一天內被寫碼查核閘誤擋幾十次後）：「擋驗證的功能本身不是錯，所以也不是隨便亂放行或乾脆整輪不擋；應該是要做出精準的判斷與充分的證據（現在看起來機制邏輯本身不周嚴且粗糙判定，建議是要有一支獨立腳本檔來處理各種可能的需求。這大批改碼或許剛好能將種種狀況進行精確的放行定義。」
- [臨] 落地規則：①修誤判不是加例外清單，是把「欠不欠帳、算不算本回合、算不算放行、算不算改碼」抽成一支獨立模組（純函數：輸入 state＋transcript 片段＋git 事實，輸出判定＋證據清單），各 hook 只呼叫不散落判斷；②每種情境（誠實流程、繞過、worktree 移除、路徑寫法差異、同伴訊息、轉述句、檔已不存在、不在 git 根…）＝一條有名字的規則＋一個會紅的案例，擋訊息印命中規則名與證據；③不准「整輪不擋」或「放寬」當解法；④多處被擋時先把（閘名／擋訊息原文／在做什麼／為何誤判／證據：state＋guard log 行＋transcript turn）彙整成清冊按根因分組，一次修，不零星修。與「閘門反覆擋同一件事時要修判定的根因」那張卡互補：那張說要修根因，這張說修成什麼形狀。

## 行動

- 收到閘誤判：先回報彙整，改法寫成「規則名＋會紅案例＋證據印出」，不寫例外清單
- 設計或審任何會擋的關卡：判定要能印出「命中哪條規則、憑什麼證據」
