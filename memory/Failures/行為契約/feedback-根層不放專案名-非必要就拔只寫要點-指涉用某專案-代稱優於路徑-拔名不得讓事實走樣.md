## 知識

- [臨] 使用者裁定：根層（~/.claude 的卡片、skill、程式註解、測試、文件）只放跨專案的經驗與知識，不保留可回查到特定專案的線索；專案專屬細節歸該專案的記憶或公司層。
- [臨] 四原則：①邏輯事實遠大於專案，專案名不是必要就拔掉，只寫核心要點或具體現象 ②真要指涉時寫「某專案」 ③用已知代稱（某 Unity 專案的伺服器）強過電腦路徑，但不得違背①② ④拔名後數字、因果、條件不得走樣。
- [臨] 實做時最容易走樣的三種形狀：同一張卡原本有兩個專案卻都寫成「某專案」（要用「另一專案」「前述…所屬的專案」區分）；把專案識別字換成白話時加字或換錯意思（例：幫「影響玩法的機制」標上「演出」把對比讀反）；只拔名不拔專案獨有的類別名、檔名、commit 編號（拿去 grep 仍查得回）。
- [臨] 機器防線只管卡片寫入：realm 閘用本機 registry 已登記專案名比對，根層 cwd 也擋。skill、程式註解、測試、文件沒有閘，靠寫的人自律；測試與範例用明顯虛構的名字（GameA、C:/Work、CORP\\PRJ001）並保留被測的格式特徵。

## 行動

- 在根層寫任何東西前：問「拿掉專案名，教訓還成立嗎？」成立就拔名只寫現象
- 一張卡提到兩個專案時用「某專案」與「另一專案」分開，代稱前後一致
- skill 範例、測試假資料一律用虛構值，不用真實專案路徑、AD 群組、同事帳號、commit 編號
- 新專案名要讓閘認得：加進本機 memory/project-registry.json 的 project_names
