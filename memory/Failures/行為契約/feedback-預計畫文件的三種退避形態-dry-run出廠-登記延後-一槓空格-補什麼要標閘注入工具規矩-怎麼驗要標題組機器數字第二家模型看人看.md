## 知識

- [臨] 使用者审預計畫時指出三種我沒察覺的退避：①把量測期的 dry_run 當出廠變量（「那不是驗證階段在用的嗎？」）；②「登記延後＋理由」這條路就是「說延後其實根本不處理」的入口；③表格裡的「—」是沒想清楚的空格。他的話：「除了第 1 點以外，另外兩點我都覺得只是為了飄移或退避而存」。
- [臨] 同一輪他要求「系統補什麼」每格必標類型：闸（程式強控，LLM 不參與）／注入（程式送材料與問題，LLM 判）／工具／規矩；「怎麼驗」每格必標：題組（固定輸入預核答案）／機器數字（代理量）／第二家模型看／人看。「角色分工」不能只寫誰做什麼，要寫「系統怎麼知道現在是哪層」（層由 cwd 與設定檔判，是機制不是 LLM 認知）、每層擁有什麼檔、入口在哪。
- [臨] 他的觀察：「當你的內容可讀性越高，分類、架構、語意越清楚，收到的反彈與校正要求就會自然而然的越少」——實踩：同一份文件連改三輪，反彈從九點降到四點再降到四點，每輪少的都是因為分類與類型標清楚了。

## 行動

- 寫預計畫或機制表時自檢三句：有沒有把該「擋」的寫成「提醒」或 dry_run；有沒有留「延後」「之後」；有沒有「—」
- 「補什麼」「怎麼驗」每格先寫類型再寫內容；沒有機器驗法的誠實標「人看」
- 角色分工寫成表：層｜系統怎麼知道｜擁有的檔｜入口｜不做什麼
