## 知識

- [臨] 使用者指正（原話：「有點慢，我又看不到進度…你自己看看能不能多開併行」「除非必須等階段、先後執行有差、大量衝突，不然就再繼續多開」）：總控台把 G15 工具、小洞修、checklist、驗收題 A′ 都排在契約軌之後，實際互不衝突；一次開五條後半天做完一天的量。慢的主因是總控台串行等交付，不是軌本身慢。
- [臨] 做法：每收一件交付或每則回報前問「還有哪些待辦跟在跑的檔不重的、不用等階段的」，有就開；只有三種理由不開（等階段數據、先後有差、改同一批檔會衝突）並寫出來。背景 session 上限滿了就 stop 待命的（重起只要幾十秒），不要等。回報時附 `claude attach <id>` 讓人看得到進度。

## 行動

- 每次收件／回報前：列待辦 → 標哪些跟在跑的不衝突 → 當回合開軌
- 不開的要寫出三種理由之一；上限滿就 stop 待命 session
