## 知識

- [臨] 使用者指正：亂碼只要會影響運作、或人讀導向會影響閱讀，就直接修，不該等使用者拍板。我曾把「config _doc 亂碼要不要重寫」當收尾單一決策點連問三輪——這是純維護動作，可逆、無業務取捨，屬反退避契約「當場做掉」範圍。
- [臨] 同場另一課：那段「亂碼」根本不存在——檔內 UTF-8 正常，是我用 python print 在 cp950 主控台印 dict 時自己解碼成亂碼。斷言檔案亂碼前必先用 sed/cat 或 PYTHONIOENCODING=utf-8 對照，別拿主控台顯示當證據。
- [臨] 使用者指正（同日）：共用設定（進版控、多機共用）與人讀文件不該出現帶磁碟代號的絕對路徑（例 `C:` 開頭的 default_root）——在 README 直接寫出它等於把設計缺陷暴露給讀者。正解：設定寫 `~/` 家目錄相對路徑（讀端 expanduser），人讀文件寫「家目錄下的 X」或乾脆不寫路徑（AI 會問）。文件裡出現絕對路徑時先查腳本怎麼解析，再決定改設定還是改措辭。

## 行動

- 發現亂碼／錯字／壞連結這類純維護缺陷：先用 UTF-8 讀工具実證存在，存在就當場修，不列為決策點
- 共用 config 或人讀文件要寫路徑時：磁碟代號開頭的一律改 `~/` 或不寫，並確認讀端有 expanduser
