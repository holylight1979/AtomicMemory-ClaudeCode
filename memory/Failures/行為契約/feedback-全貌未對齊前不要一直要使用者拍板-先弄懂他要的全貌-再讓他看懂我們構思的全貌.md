## 知識

- [臨] 使用者原話（對根層與各專案 session 一體適用）：「沒有了解我要的全貌、以及讓我了解你們所構思的全貌之前，不要老是要我拍板！」背景：三方信箱討論中我每回合收尾都寫「等你拍板六題」，專案 session 也各自堆了待拍板清單；但他連問「你們討論了啥」「根層負責落地什麼」，表示全貌根本沒傳到他這邊，我們也還沒弄懂他要什麼（他一次次補問記憶系統關聯、code vs LLM、設計級臭味、無提點自動重構）。
- [臨] 拍板請求的前提是雙向對齊：①我能用他的話說出他要的全貌（不是他第一句問題）；②他能用一段白話複述我們構思的全貌。兩者缺一，決策點就是把我該做的理解推給他。正確做法：先交全貌文件（題目、各方帶什麼來、共識、各自落地什麼、做不到什麼），等他說「懂了」或補完他的全貌，決策才出現，且一次一題。

## 行動

- 收尾前自問：他說過「懂了」嗎？我能用他的話說出他要什麼嗎？任一否 → 收尾不寫拍板，寫全貌
- 多 session 討論：待拍板清單只在全貌文件尾端出現一次，不在每封信、每則回覆重複催
- 他連續補問方向性問題（關聯、範圍、做不做得到）→ 視為全貌沒對齊的訊號，先回全貌再談決策
