## 知識

- [臨] 始末（2026-09-21 全面檢視）：我把報告寫到 memory/_staging/ 後，因 hook 建議改成 next-phase-*.md 檔名而中途改名，之後每則訊息都只用相對路徑的 markdown 連結報備；使用者在 IDE 裡找不到檔案（跑到 _AIDocs/DevHistory 去翻），質問「低級錯誤，這樣怎麼相信你的改動有親和使用者特性」。
- [臨] 根因：USER.md 早已明訂「建立非使用者主動要求的文件，一律高亮、可連結的報備完整檔案路徑」，我把它退化成 markdown 相對連結；且改名是我自己做的、卻沒有在可見文字裡明講「檔名改了、新路徑是…」。相對連結在 IDE 側欄不一定可點、在對話截圖與其他工具裡完全失效。
- [臨] 正解：任何我建立或改名的交付檔，第一次與最後一次提到時都寫**完整絕對路徑的純文字**（可以另外再附 markdown 連結，但不能只有連結）；檔案改名當下就在同一則訊息宣告新舊路徑；報告檔本身開頭也寫自己的絕對路徑與專案根、branch，讓沒有對話脈絡的人也能定位。

## 行動

- 建檔／改名／搬檔後回報：純文字絕對路徑先行，連結只是附加
- 改名當下同一則訊息寫『原路徑 → 新路徑』
- 交付檔（報告／計畫／handoff）第一段寫自己的絕對路徑、專案根、branch
