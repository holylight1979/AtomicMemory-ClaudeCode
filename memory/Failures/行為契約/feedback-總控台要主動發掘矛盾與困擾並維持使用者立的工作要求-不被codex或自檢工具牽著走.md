# feedback-總控台要主動發掘矛盾與困擾並維持使用者立的工作要求-不被codex或自檢工具牽著走

- Trigger: 總控台, 被牽著走, codex 審查, 自檢工具, 主動發掘, 矛盾, 困擾, 工作要求, 品質維持, 裁定
- Created-at: 2026-10-13

## 知識

- [臨] 使用者原話：「你要維持住我告訴你的這些工作要求與品質，並且要主動去發掘出矛盾或困擾之處，不要只是單純被 Codex 牽著鼻子走」。背景：對人總控台一整天的行為大多是「codex 報告或自檢工具指一條→我裁一條」，文件被逐條補成飄移、閘誤擋被當成要配合的流程、該推就推變成請示。审查者只會對它被問的面找漏洞；目標對不對、流程有沒有自相矛盾、使用者在哪裡被磍到，沒人會替總控台看。
- [臨] 做法：每次收到審查或自檢結果，先問三題再裁——①這條服務原話輯哪一條目標？指不出就進維護軌或不理；②它跟已定規則或其他軌的做法有沒有矛盾？有就先解矛盾再裁；③使用者現在被什麼磍到（重複提問、看不懂的名字、幾十條廢話）？那才是第一優先。每回合收尾前自己掃一次「今天有沒有哪條規則被重複踩、哪兩條規則互打」，有就主動提，不等工具指。

## 行動

- 收到審查條目：先對原話輯目標、再查與既有規則的矛盾，再裁
- 每回合收尾前自問：使用者被什麼磍到、哪兩條規則互打；有就主動提出處理
- 審查者沒問的面（目標飄移、流程自相矛盾）由總控台自己看
