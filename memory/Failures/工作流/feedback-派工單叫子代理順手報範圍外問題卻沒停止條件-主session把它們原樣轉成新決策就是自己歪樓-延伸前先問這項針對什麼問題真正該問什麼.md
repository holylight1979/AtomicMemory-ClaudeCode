## 知識

- [臨] 使用者原話：「這一輪之後沒有再度延展的了」「如果這一批要做的…發現還是有「無可避免、必須延展的後續」那就優先提出來檢視該項目的設定到底是針對了什麼問題，真正應該問的是什麼、該做的到底是什麼」「自我檢討看看、是哪裡歪樓了」。
- [臨] 歪樓機制：派工單寫「範圍外看到的問題也報（重大／快且有效）」卻沒停止條件，每個子代理都附一串旁支發現；主 session 原樣轉成「要你決定的」、再派工、又附新的一串，一輪變三輪，沒有一件是使用者一開始要的。跟「叫 Codex 找洞沒停止條件」同型。
- [臨] 同場另三型：前提沒查就包裝成決策（開場提示是自己程式缺陷的症狀，却當成遠端壞了）；只看一個總數就建議關掉舊機制，沒查新舊時機重不重疊；先驗零件再驗整體，還照同一題的答案調了兩輪提示。
- [臨] 判準：範圍外的發現只在「會讓使用者這次要的事做錯」時才提（同根的相鄰問題照舊順手修）；其餘不轉成決策。要延伸之前，先寫這項原本針對什麼問題、真正該問的是什麼、該做的是什麼。

## 行動

- 寫派工單：範圍外只報「會讓這次要的事做錯」的，其餘不報不列
- 收子代理回報：不把旁支發現轉成使用者要決定的事
- 要提延伸前先寫：針對什麼問題、真正該問什麼、該做什麼
- 驗證先驗整體是否服務使用者的問題，再驗零件
