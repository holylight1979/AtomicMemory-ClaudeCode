## 知識

- [臨] 使用者原話「不是有該驗的要驗嗎？」：我在全貌文件列了「還沒證：穩定度、真實提交 diff」，然後寫「根層等真實 diff」就停下來等專案送樣本。其實兩項我自己當場就能測：穩定度是把同一題重跑兩次；真實 diff 從自己 repo 的 git log 取一筆 commit 就有。結果一跑就挖出自家工具的真缺陷。
- [臨] 規則：自己列的「還沒證」清單裡，任何一條在本機、本 repo、沙箱就能取樣的，不等、不寄信要樣本，當場跑。「等對方」只留給真的只有對方有的東西。

## 行動

- 寫下「還沒證」前先問：我現在能不能自己取樣？能就不列，直接跑
- 穩定度＝同題重跑≥三次；真實樣本＝自己 repo 的 commit
