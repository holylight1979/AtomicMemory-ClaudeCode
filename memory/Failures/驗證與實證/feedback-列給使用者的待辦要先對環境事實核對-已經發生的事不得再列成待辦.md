## 知識

- [臨] 同一場兩次拿「記得的狀態」當「現在的狀態」被使用者糾正：① 我依 TECH.md 的「當前部署為單人」建議「找第二個人實測」，使用者回「某專案已有 2～3 位成員、另一專案更多」——看一眼專案記憶目錄的 personal 子夾與 Author 統計就知道；② 我連續兩次把「重啟 Claude Code」列成使用者待辦，使用者回「我已經重啟啦」——當時新 MCP 工具與新 skill 早已載入，證據就在我自己的工具清單裡。
- [臨] 規則：寫「需你動手」或交接檔的手動事項前，逐條找一個當下可觀測的訊號驗證它還沒發生（工具是否已載入、檔案是否還在、程序 pid 是否換了）；對「現況」的斷言以實際目錄與版控紀錄為準，文件裡的「當前」描述會過時，查到不符就順手改文件。

## 行動

- 收尾列使用者待辦前，每條自問：我現在有什麼證據證明它還沒做？
- 建議「先做 X 實測」前先查 X 是不是早就在跑（看目錄、Author、版控作者）
- 文件現況描述與實際不符 → 當場更正文件
