## 知識

- [臨] 使用者原話：「發現問題，要想辦法從根源解決；無法解決也要記下來 LLM 有這種問題、日後要持續追蹤解法。」背景：三方守門討論的回放實驗連被抓到三次洩題，我只寫「下次注意」。
- [臨] 三型洩題（LLM 自己設計實驗時必然會犯）：①出題者把答案寫進「待審的回覆」（同一個腦子出題又寫回覆，埋的問題會從回覆文字漏出）；②材料指到真工作副本，審查者讀到修正後的文件、記憶卡片、svn log，甚至 Codex 自己的持久記憶；③提示詞本身催被測的行為（問「你先讀了哪個檔」就是在逼它先讀碼，對照組不再是對照）。
- [臨] 根治：前兩型用 `tools/replay-guard.py` 擋——跑前檢查提示詞不含封存答案關鍵字、不指到暫存目錄以外、Codex 記憶無案例字樣；跑後只看紀錄裡的指令行，有讀出界就 FAIL。實測對三次真洩題材料全抓到、六個乾淨案全放行。第三型程式擋不了：緩解是每個實驗必帶「最素提示」對照組（只說要交什麼，不說怎麼做），並請另一個模型審提示詞有沒有催行為；最素提示在三方回放裡表現最好。未解，持續追蹤。

## 行動

- 設計任何讓 LLM 審或診斷的實驗：出題者與跑題者分開；材料全部匙出到暫存目錄；跑前跑後都過 replay-guard；必帶最素提示對照組
- 發現實驗汙染：先問能不能用程式擋，能就寫進工具；不能就寫進 atom 標未解，不寫「下次注意」
