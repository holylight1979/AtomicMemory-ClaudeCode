## 知識

- [臨] 始末：補 README「哪些東西自動上版控」時，我把 vcs-sync 的 pathspec 表、觸發時機、push 守門、拉取只併純記憶、下個 session 生效等機制逐條寫進去（約 25 行）。使用者連續三次指正：人必讀文件（README／Install）內多出來的、過時的、技術導向的內容都要剔除；太抽象或要多拐兩個彎才懂的說明要斟酌位置；版控段落「細節太多餘，寫使用者在系統輔助下快速、直接體驴到的就好」。最終同一段收成三點：卡片自己上、程式碼等你說「上GIT」且不偷推、多機衝突自動合。
- [臨] 判準：人讀文件每一句問「使用者會看到／會做／會被影響嗎？」——會才留；機制怎麼達成、何時觸發、哪些路徑、邊界條件屬 TECH.md 或 _AIDocs，README 只放一個連結。已有技術文件完整涵蓋的段落（合併驅動、rebase 方向、Fork、SVN 衝突、LF）整段移除不保留摘要。
- [臨] 結構偏好：三層記憶用一張「放什麼／在哪／怎麼拿到」表；日常互動用「你說 → 它做」口令表；每節 ≤6 點、每點一句；設計理念與原生比較表屬 TECH 不進 README。
- [臨] 使用者給的切入點（原話）：「使用者必須操作、必須認知的，就是節錄進說明的切入思考點。」每段先標它是「要操作」還是「要知道否則會被影響」；兩者都不是（機制怎麼達成、設計理念、跟原生比較、升降級細節）就不進人讀文件。
