## 知識

- [臨] 使用者指正：現存的 code 具備的只是邏輯與規則，真正的需求不在裡面。AI 用「現存程式／腳本找合理性」來訴說一切，重大設計缺陷就看不見。實例：評估一個 proto 型別兼業務物件的模組重構，只盤點「出現幾次、有沒有測試、守門認不認得」，沒退一步說出「一個型別扮存檔、業務、推送三個角色」這個根。
- [臨] 「查得到就不猜」只管事實；設計好不好不是查得到的事，現有程式只證明現在長怎樣，不證明應該長怎樣。
- [臨] 批判若在讀完現有實作後才寫、問的又是「是這裡嗎、合理嗎」，就是以現況為參照，越照做越被錨住；要先寫需求與從零寫的最簡形狀，讀完現況再逐條比對多出來的部分：有真實限制寫理由，沒有就是壞味道、說出來不照抄。

## 行動

- 動手讀程式前先寫：需求（用使用者的話）＋從零寫的最簡形狀；需求寫不出來就問使用者
