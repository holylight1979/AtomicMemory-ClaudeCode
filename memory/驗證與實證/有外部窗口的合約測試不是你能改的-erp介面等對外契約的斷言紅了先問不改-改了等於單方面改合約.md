# 有外部窗口的合約測試不是你能改的-ERP介面等對外契約的斷言紅了先問不改-改了等於單方面改合約

## 知識

- [臨] 判準：測試名或說明指向外部系統的介面（ERP、金流、對方 API 的輸出格式）時，它封的是兩邊的合約，不是本專案的行為；改了需求讓它紅，正解是讓它紅、寫「不做｜<測試名>：對外合約，要對方確認」或問使用者，不是改斷言讓它綠。改了斷言＝單方面改合約。
- [臨] 反例：需求要求訂單加欄位，AI 第一回合就把 ERP 合約測試的斷言改成新格式並 commit；使用者後來說「跳過」時它做對了（還原、不加 skip、寫不做行），但前面那次改已進 HEAD。分辨法：這支測試的對面是誰？是本專案自己 → 可宣告改舊測試；是外部系統 → 不改。

## 行動

- 要改舊測試斷言前先看它封的是誰的行為：對外合約 → 照紅、寫不做行或問人
- 需求讓對外輸出格式變時，交付時列出哪些合約測試會紅、要誰確認
