## 知識

- [臨] 改量測或判定工具的邏輯後，只看總數（certain=236 前後一樣）會漏掉互相抵銷的變化。做法：把舊版工具用 git show 取到暫存目錄，新舊兩版量『同一份輸入』，逐條比對落點／邊的進出（舊確定→新不確定、反向），每一條出入都要能對上某條規則；再加一層邊級比對（目標配對有沒有遺失、未解有沒有變多）。
- [臨] 實證：這個做法抓到兩個自己造成的退化——『from pkg import 子模組』被新的穩定判斷誤標（某入口確定數從 236 掉到 219）、把函式內 import 次數併進『重新指定』導致找目標也放棄（未解從 408 跳到 445）；兩者都在交付前修掉。
- [臨] 量『工具自己』時被量的程式也改了，數字變化不代表規則變了：用舊工具量新程式碼做對照，確定集合相同才說明差異只來自程式碼成長。
