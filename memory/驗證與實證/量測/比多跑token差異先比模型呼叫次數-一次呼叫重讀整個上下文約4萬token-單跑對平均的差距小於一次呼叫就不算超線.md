## 知識

- [臨] 每一次模型呼叫都重讀整個上下文（帳上是 cache_read），系統提示＋skills 清單＋工具定義就約 4 萬 token，佔每次呼叫的 85% 以上；帳上「輸入 token」的差距幾乎等於「呼叫次數差」× 4 萬，hook 注入的字數通常只佔幾千。
- [臨] 所以比兩跑的 token 前先比模型呼叫次數（transcript assistant usage 去重後的筆數）：次數相同才能談注入字數的影響；多一次呼叫就去找是哪一步、前面有沒有提醒（沒有就是 AI 自己的變異）。單跑對平均的差距小於一次呼叫（約 4 萬）時不要宣告超線或進線，那是隨機變異。

## 行動

- 量 token 差先印兩跑的呼叫次數與每次 cache_read，再談百分比
- 多出的呼叫逐一對回 transcript：那一步前有沒有 hook 文字，沒有就不要歸給守門
- 線的設定要大於一次呼叫的變異，或者多跑取平均
