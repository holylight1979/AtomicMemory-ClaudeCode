## 知識

- [臨] 用事件帳重播量「改了省多少」：先拿舊碼重播，輸出跟實跑 transcript 逐字比對，對上了才換新碼量。沒對帳的重播，量到的差可能是環境差（輸入跟當時不同），不是改動效果。
- [臨] 重播輸入要還原到當時：候選名單、資料根、冷熱存取紀錄。存取紀錄可能被後來的跑次改掉，要用 transcript 證實的當時狀態填，不讀現在磁碟上的檔。
- [臨] 實例：量注入預算改動時，5 跑×2 回合的舊碼重播與實跑逐字相同後才換新碼，量出的數字才站得住。
- [臨] 對帳要逐字比（difflib 列出不同片段），不能只比字數：同字數的措辭改動字數比對看不出來。實例：「定位三行之後再加一行」改成「的下面加一行」，6 筆字數全對，逐字只對上 4 筆。
- [臨] 實例：重播擋訊息時沒還原 state 裡當時記下的使用者原話，動資料檔證據「(d) 3 則」重播成「1 則」；補回當時的 state 才逐字對上。state 也是要還原的輸入。
- [臨] 實例：重播沒帶事件帳記的意圖欄（feature），注入少了「視角／先問」兩行，逐字對帳 0/15；帶上後 15/15。事件帳記的意圖也是要還原的輸入。
- [臨] 拿 transcript 餵給被重播的函式時，只能給到「那一列之前」：整份給，函式會從未來讀到後面才寫的內容（例：之後才寫的定位行），重播結果跟當時不同。
- [臨] 同一批 tool_result 在 transcript 裡會整批再記一列；重播取第一次出現的那筆，不然同一事件算兩次。跟帳不同的部分先查是不是當時的 session 狀態造成（例：那時有目標樹，範本多兩行），不先算成改動效果。

## 行動

- 量改動效果前先跑「舊碼重播 vs 實跑紀錄」逐字比，不同就先修重播輸入
- 重播用的狀態以 transcript 證實的值填，不信現在磁碟上的檔
