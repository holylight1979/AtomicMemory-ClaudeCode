## 知識

- [臨] 現象：用 `[A-Za-z]:[/\\]` 在任意文字裡找 Windows 絕對路徑時，網址 `http://host/...` 的「p:/」、`https://` 的「s:/」都會命中，被當成 P 槽／S 槽路徑。只要被掃的文字可能含網址（diff、文件、log、提示詞），出界檢查就會誤擋；實遇是第二意見材料的 diff 有一行 `curl -s http://127.0.0.1:...`，守門判「提示詞指到暫存目錄以外的路徑」，整個流程起不來。
- [臨] 正解：磁碟代號前加 `(?<![A-Za-z])`。網址的 scheme 字母前面一定接著字母，被排除；`C:\x` 前面是空白／引號／等號照抓；`file:///C:/x` 的 `C:` 前是斜線，照樣抓得到真路徑。不要改成「排除含 :// 的整段」，那會連 `file:///C:/x` 一起漏掉。
- [臨] 替身落差：用「前一個字元是不是字母」代替「是不是網址」，黏字路徑（`xC:\...`）會漏抓；實務上 Windows 路徑前不會黏字母，可接受。只做 `re.match(r'^[A-Za-z]:...')` 對整個 token 錨定開頭的寫法不受影響，只有 `search`／`finditer` 在長文字中間找的才要加。
- [臨] 寫「期望不擋」的案例時，先斷言舊正則確實會在同一段文字命中，證明案例不是因為什麼都沒發生才通過。

## 行動

- 寫任何「從長文字裡找 Windows 絕對路徑」的正則：磁碟代號前加 (?<![A-Za-z])
- 出界／路徑守門誤擋時，先看被擋的字串是不是網址被切出來的 p:/、s:/
