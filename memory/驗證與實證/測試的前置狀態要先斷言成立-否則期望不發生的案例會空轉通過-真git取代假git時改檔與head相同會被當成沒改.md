## 知識

- [臨] 「期望某件事不發生」的案例（不記、不擋、不欠）在前置狀態沒建起來時會空轉通過；同組裡只有「期望發生」的對照案會紅，容易誤以為主案已驗到。
- [臨] 最常見的觸發：把測試環境換得更真（假目錄→真 git repo、mock→真服務）後，舊的前置步驟在新環境不再成立。例：模擬「某人改了檔」卻寫回原內容，假環境查不到所以照算有改，真版控正確判成沒改，後續要判的對象根本沒產生。
- [臨] 防法：先斷言前置狀態真的建起來（數量、紀錄、狀態欄），再斷言結果；「期望不發生」的案紅了又綠得太順，先看輸出裡有沒有把前置步驟判掉的規則。

## 行動

- 寫「期望不發生」的案例：先 assert 前置狀態真的建起來了，再 assert 結果
- 測試環境換成更真的實作後，重新確認舊的前置步驟在新環境裡還成立
