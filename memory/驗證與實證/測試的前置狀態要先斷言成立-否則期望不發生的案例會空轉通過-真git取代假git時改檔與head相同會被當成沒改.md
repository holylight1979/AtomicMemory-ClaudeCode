## 知識

- [臨] 「期望某件事不發生」的案例（不記漏判、不擋、不欠）在前置狀態沒建起來時會空轉通過，只有「期望發生」的對照案會紅，容易誤以為主案已驗到。實遇：把假版控目錄換成真 git repo 後，前一個 session 的改檔內容和 HEAD 相同，被判成「改過又原樣還原」→ 範圍沒結案 → 後面要判的漏判沒有對象，兩個「不記」案空轉通過。前置狀態先斷言成立（結案數、收據數、狀態欄），再斷言結果。
- [臨] 始末：寫「範圍漏判只在案例是自己新寫或改過才不記」的案例時把假版控目錄換成真 git repo。第 1 輪紅是刻意先紅（重試計數把它算進去是已知誤判）；第 2 輪實作後仍紅一案（期望記漏判却沒記），看 stderr 的 NET_UNCHANGED 才發現前一個 session 的 x.py 與 HEAD 相同、範圍根本沒結案；先把 x.py 改成不同內容、斷言結案數為 1 後全綠。
- [臨] 根因：換測試環境時沒重驗舊輔助函式的前提。舊輔助「宣告、改 x.py、跑綠、結案」假設 x.py 算改過；在假 repo 上 git 查不到所以照算改碼，在真 repo 上同內容被正確判成沒改。
- [臨] 設計原理：NET_UNCHANGED 讓「改過又原樣還原」不算改碼、不必宣告驗證範圍；閘的判定建在 git 事實上，測試環境越真，舊測試裡靠「git 查不到就照算」撐住的前提就會失效。運作連鎖：改檔被排除 → 沒有要宣告的改檔 → 不寫結案 → 歸因找不到宣告 → 期望「記」的案紅、期望「不記」的案空轉綠。

## 行動

- 寫「期望不發生」的案例：先 assert 前置狀態真的建起來了，再 assert 結果
- 測試環境換成更真的實作（假目錄→真 repo）後，重新確認舊的前置步驟在新環境裡還成立
