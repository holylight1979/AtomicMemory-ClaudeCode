## 知識

- [臨] 判準：沿呼叫點往上找——這段在「每次事件（每則訊息、每個工具呼叫、每個請求）」或「對每筆資料（每張卡、每一列）」都會跑，或所在路徑有時間預算（hook 整體 5 秒）→ 熱路徑；一天／一週跑一次的離線工具、啟動時跑一次的初始化 → 不是。
- [臨] 反例：「只改了一個小函式」不是否的理由——每個 PreToolUse 都會跑的路徑比對函式，對每條規則各叫一次，裡面多一次 os.path.realpath 就是乘上規則數再乘上工具呼叫數；是熱路徑，要量並印 `<NAME> DONE k=v`。
- [臨] 「量測｜不做」只在改動不會增加每次呼叫的成本（純改名、刪碼）時成立，理由要寫出這個事實；「改動很小」不算。

## 行動

- 答前先寫出呼叫點與頻率（每事件幾次 × 每次幾筆、有沒有時間預算）
- 是 → 寫一支小量測比新舊，印 `<NAME> DONE ms_old=… ms_new=…`；否 → 理由寫頻率事實
