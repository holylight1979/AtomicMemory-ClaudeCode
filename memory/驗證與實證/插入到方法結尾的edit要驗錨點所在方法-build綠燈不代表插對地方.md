## 知識

- [臨] **用「某行 + 右大括號」當錫點把呼叫插到「方法結尾」時，錫點可能落在另一個小方法裡**：大方法的最後一行往往是對小方法的呼叫，而小方法本體的結尾也長得一樣（同一句呼叫 + `}`）。插進小方法後 build 照樣綠燈，但小方法可能有提早 return（如「沒資料就 return」），新碼只在特定條件下執行 →實機「看不出效果」。實例：把 `DetectFinalBlow()` 插在 `ClearCollectedDrops(); }` 後，落進 `ProcessDropRewards()`（開頭 `if (沒掉落物) return;`）而非 `Simulate()` 結尾。
- [臨] **插入後的必做驗證（不靠 build）**：`grep -n` 拿到新呼叫行號，再確認它介於目標方法的首行與該方法結尾大括號之間（awk 從方法首行往下找第一個同縮排 `}`）；錫點優先選目標方法專屬的語句，不選「呼叫小方法那句」。
- [臨] 實機「看不出效果」的排查順序：①跑的是不是新 DLL（拿 log 堆疊行號對現行檔）②新碼有沒有被執行到（插入點與提早 return）③才懷疑邏輯。

## 行動

- 插入「方法結尾呼叫」後，grep 行號 + awk 確認落在目標方法內，再 build
- 實機無效果先對 log 堆疊行號確認跑的是新碼，再查插入點是否被提早 return 跳過
