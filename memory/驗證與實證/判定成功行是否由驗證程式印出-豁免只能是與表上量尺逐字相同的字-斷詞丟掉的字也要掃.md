## 知識

- [臨] 判斷「這行成功訊息是不是被驗證程式印出的」時，整條指令裡出現哨兵字樣就不採認；唯一豁免是精確對上的量尺片段裡、與表上那段**逐字相同**的字（同一字出現幾次扣幾次）。用「整個對上的指令段」或「只查環境前綴」當豁免範圍都會漏：行內環境值 `X='…DONE' 量尺`、正規化後才對上的腳本路徑 `"./X_CHECK DONE/../run.py"`。
- [臨] 斷詞器丟掉的字也要納入掃描：重導向目標（`2>"X_CHECK PASS"`）要另記保留；只有重導向、沒有程式的指令段（`; > "…"`）直接判不支援。原則：註解以外的每個字都要被看到。
- [臨] 把輸出端的 config regex 拿來掃指令時，錨點要全部拿掉，而且掃描器要懂 `(?#…)`（到第一個沒跳脫的 `)`，Python 斷詞把 `\)` 當一個字元）、verbose 模式的 `#` 註解、字元類界線（`[` 或 `[^` 後緊接的 `]` 是字面，`[a[]` 是 a 或 [）；處理不了的寫法（只對某段開關 verbose 的 `(?x:…)`）就拒用並在 stderr 說明，不默默漏查。
- [臨] 防線邊界要明寫：擋得住在白名單語法內用一般 shell 指令讓成功行不是驗證程式印的；擋不住「另寫或改用一支真程式去印假哨兵」，那屬刻意造假，不再加機制。

## 行動

- 設計或審查「收據採認」類判斷：先列出斷詞器會丟掉的字（重導向目標、註解外的特殊段），確認每一類都有被掃
- 豁免一律用「與表上逐字相同」的多重集合相減，不用片段範圍整段豁免
