## 知識

- [臨] 裁決順序：把 Codex 每條 BLOCK 轉成一個可檢查的反例（輸入 → 預期壞掉的結果），自己讀碼追或跑一次。重現成立 → 採納，補那個反例當案例先紅再修；重現不了（讀碼看得到已處理、或跑了沒壞）→ 不採，裁決寫出擋住它的那行碼或實跑輸出。
- [臨] 「我方測試全綠」不是駁回理由：Codex 的反例常正是我方案例沒涵蓋的輸入（空清單、None、超長輸入）。「Codex 說的」也不是採納理由：它看不到本機執行，常把已處理的分支當沒處理。
- [臨] 「不需第二意見」只在改動沒有邏輯影響（只改註解、docstring、字串、文件）或使用者已裁定這類交付不跑 codex 時成立；改到閘或高風險部位的判斷邏輯，哪怕只動一個門檻或一個條件，也要跑——「改動很小」不是理由。

## 行動

- 每條 BLOCK 先寫「反例：… → 重現：成立／不成立（依據）」再裁
- 宣告不需前先問：這次改動有沒有改到任何判斷、分支或比較
