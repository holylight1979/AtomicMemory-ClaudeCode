## 知識

- [臨] 用開源小模型（內網 Ollama gemma4:e4b）照「是非題規格」判文字品質，5 份樣本實測：一次全判 66%，逐條問 81%，逐條＋程式先切出該條要看的範圍（第一句、前三句）最穩（26b 到 88%）；一次全判時模型會拿後文湊答案。每份約 6～11 秒、付費模型 0 token。
- [臨] 裁判偏寬鬆（壞文字常被判過）、換前一個呼叫會翻（25 條翻 3 條）：上線順序固定「背景記帳 → 沒過提醒寫的 AI → 量到門檻才擋」，每條各自升段。問法改「找得到反例就答否並引用」，引用對不到原文就作廢（擋下裁判把提示詞裡的規格當原文引用）。
- [臨] 不適合：qwen3.5 4b／9b 逐條判不照 JSON；thinking 模式變慢 3 倍沒變準；本機 4GB 顯卡 qwen3:4b 一份 89～134 秒。Ollama 0.30.7 有 format＋think:false 被忽略的 bug（0.31.2 修）；num_ctx 預設 4096 會靜默截斷。完整研究與規格範例：_AIDocs/DevHistory/v6.0-寫程式碼的進化-2026-10/G15-規格評分表-研究與提案.md
- [臨] gemma4:e4b 對「找得到…嗎？找得到就答否」這種反向問法會照字面答成「否＝沒找到」，與題意相反（5 條錯有 3 條是這個）；規格條目寫正面問法（每一句都只講一種嗎？有混的就答否並引用）。它偶爾把引用改成簡體字，逐字校驗會作廢，留帳就好不做繁簡對照。
- [臨] 內網 Ollama 0.30.7 輸入超過 num_ctx 時 prompt_eval_count 回報整段長度（num_ctx=512 → 977～1112），不一定截到 num_ctx；截斷判定要用「回報數 × 門檻 ≥ num_ctx」推，快取情境未測。

## 行動

- 要讓 LLM 判文字規格：規格寫成是非題、逐條問、能程式切的範圍先切、要求引用原文並校驗引用存在
- 新裁判條目先走背景記帳，有誤判率與重跑一致率數字才升成提醒或擋
