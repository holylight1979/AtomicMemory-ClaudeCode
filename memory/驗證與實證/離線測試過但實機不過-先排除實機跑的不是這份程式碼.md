# 離線測試過但實機不過-先排除實機跑的不是這份程式碼

- Created-at: 2026-08-20

## 知識

- [臨] **同一份邏輯「離線測試過、實機不過」時，第一個要排除的不是邏輯而是「實機跡的不是這份程式碼」**。實例：`dotnet run` 的測試專案會自動重建來源檔，但已啟動的 GUI 執行檔是修正前 build 出來的——兩邊看起來在測同一份原始碼，實際差了一個修正。
- [臨] 排除順序：① 執行檔的 mtime 是不是晚於最後一次改碼② 跡的是哪一個路徑（別的輸出目錄？舊的安裝路徑？）③ 讀的設定檔是不是我以為的那份。這三項都是一行指令就能確認的，比推理邏輯便宜很多。
- [臨] 同一類陷阱：**設定檔也要重讀。**上一次看設定是 session 開頭讀的，中間可能已被使用者或程式自己改掉。實例：一條正則設定被放寬過，實際行為跟我手上那份快照完全不同。

## 行動

- 實機驗證失敗時，先比對執行檔 mtime 與最後一次改碼時間，再去怀疑邏輯
- 改完碼到實機驗證之間，把「重建」當成不可略的一步，不要靠記憶
- 引用設定值做判斷前重讀設定檔，不用 session 開頭的快照
