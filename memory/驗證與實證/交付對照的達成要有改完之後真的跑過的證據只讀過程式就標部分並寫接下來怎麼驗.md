# 交付對照的達成要有改完之後真的跑過的證據，只讀過程式就標部分並寫接下來怎麼驗

- Scope: global
- Author: holylight

- Confidence: [臨]
- Trigger: 交付前的目標對照, 完整對照, need_goal(action=reconcile, 標「達成」, 沒試過不算達成, 推論最多標部分, 最後一次改動之後跑, followup
- Created-at: 2026-10-21
- Entry: E26

## 知識

- [臨] 寫碼類節點標達成至少一筆：最後一次改動之後跑的沒紅收據 R<號>（實測），或讀碼級的驗證案例檔。改動之前跑的收據作廢，要用之後那張。
- [臨] 只讀過程式碼、覺得應該可以（file 證據或推論）→ 標 partial，followup 寫補哪支案例、怎麼驗。反例：xlsx 匯出寫完沒跑過就標達成，附 export.py:120 當證據。
- [臨] 「每個還活著的節點」含樹根：子節點有部分，樹根就不是達成。

## 行動

- 交 reconcile 前逐節點查：收據是不是在該節點最後一次改動之後
- 沒試過的老實標 partial＋followup
