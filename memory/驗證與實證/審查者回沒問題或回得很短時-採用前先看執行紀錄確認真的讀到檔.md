## 知識

- [臨] 審查者（codex 等）回「沒問題」或回得很短時，採用前先看它的執行紀錄，確認真的讀到檔：沒讀到材料的審查一樣會正常結束、回乾淨結論，而乾淨結論比可疑的 BLOCK 更容易被直接採用。
- [臨] 實例：一次閘小修的 codex 審查，第一次跑唯讀沙箱在本機起不來、一行都沒讀到；改完整讀檔權限重跑（全程沒改檔）才抓到 2 條成立的 BLOCK。起不來的原因未查、沒重現過。
- [臨] 不換權限的補法：codex 在 Windows 唯讀沙箱起不了讀檔工具時，把 diff＋相關檔全文（含行號）經 stdin 送，提示寫明不用執行工具。

## 行動

- 收到乾淨或很短的審查結論，先查執行紀錄有沒有讀檔指令失敗、有沒有真的開過檔，再採用
- 沒讀到就照 codex 執行卡的做法換權限重跑
