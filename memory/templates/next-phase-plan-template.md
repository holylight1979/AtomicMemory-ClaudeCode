# next-phase 計畫檔骨架模板

- Scope: global
- Confidence: [臨]
- Trigger: next-phase 模板, 計畫檔模板, 階段計畫骨架, staging 計畫, 六欄白話, 交接計畫格式
- Related: handoff-綜觀品質與抗失真寫法, workflow-icld

> 用法：寫任何 `memory/_staging/next-phase-<主題>.md` 時照本骨架填。
> 只定「要回答哪些問題」，不預填答案；不適用的段落明寫「不適用＋一句理由」，勿默刪。
> 實證效果：每階段附六欄白話說明後，AI 互動行為顯著不飄移、提問更精準（user 回饋，2026-08-05 定為標準）。

---

## 骨架（計畫層級，依序）

```markdown
# 階段計畫：<標題>

> 來源：<需求從哪來>。狀態：**規劃/進行中；是否已取得實作授權**。範疇：<core/local/專案>。
> 本檔為跨 session 執行 SoT，自足；Phase 之間可獨立停。

## 一句話說明
<不懂內部架構的人也看得懂的一段話：現在缺什麼、做了會怎樣>

## ⚓ 版本錨點（接手先對，數據會漂）
- 專案根（所有相對路徑的解析基準）、branch、錨點 commit
- 每個 load-bearing 數字：量測時間 + 可重跑指令；無法重驗者明標「未驗證快照，勿據此鎖死」

## ⚑ 核心方向（防偏離）
- 做什麼（含 user 原話依據）/ 不做什麼（已裁決勿翻案，附理由）

## N. Phase X — <一句話標題>
### 白話說明（六欄，每欄至少一句）
- **現在是什麼樣子**：改動前的真實現況，含痛點
- **什麼是現有的**：會用到、要保留、可複用的既有資產（防重造輪）
- **要改哪裡**：具體檔案/目錄；「不動什麼」同樣要寫
- **改成什麼樣**：改完的具體形狀
- **改好之後會怎樣**：預期成效，用「誰因此能做到什麼」描述
- **還不確定的**：未定參數、風險、未估工時——寫成可回答的問句並連到未解問題表
### 邊界 / 驗收
- 零行為改變？可對拍？驗收指令是什麼？

## 為什麼是這個順序
<Phase 間的前提鏈：前一階段的什麼結論成立，下一階段才值得做>

## 每階段的「不做就會怎樣」
| Phase | 不做的代價 | 做了的成本 |

## 未解問題（每項皆為可回答的具體問句）
| # | 問句 | 涉及檔 | 已驗狀態 | 禁止假設 |

## 授權閘門（文末重申）
- 本檔是計畫非授權；接手第一步（唯讀核對清單）
- 本檔是假說非真相：動碼前 grep 實碼對照，不符以實碼為準

## 規則連結
- 相關 atom / 相鄰計畫 / 完成後 atom 候選
```

## 檢核（寫完自問）

1. 陌生 session 只讀本檔能開工嗎？（路徑可解析、數據可重驗、問句可回答）
2. 每個 Phase 的六欄都填了嗎？「還不確定的」是空的＝多半沒想完，不是真的沒有。
3. 授權狀態在**首尾**都出現了嗎？
4. 有沒有把「現況快照」寫成永恆事實？（數字要帶量測時間與指令）
