# 彙整多份來源寫現況文件時-追蹤表裡的修法建議不是現況-每句現況要能指到程式

## 知識

- [臨] 實例：同步多軌合併後的共用文件時，從主追蹤表讀到某個閘的放行失效根因與修法「(b) 預算以使用者真打字開的回合計」，順手寫進技術文件閘序表與設定說明當現況；它其實是還沒派工的必修，程式仍是每則提示都加一。自審才發現並拿掉。若沒拿掉，文件會讓下一個人以為問題已修。
- [臨] 根因：追蹤表把現象、根因、修法寫在同一段、同一個肯定語氣，修法句讀起來像事實；草稿、退件單也一樣混著「已做」與「要做」。
- [臨] 判準：寫進現況文件的每一句，都要能指到程式裡的函式、常數或設定鍵（grep 得到）；來源是追蹤表、退件單、草稿的句子，先分「已合進主線」與「待修」，待修的不進現況文件，只留在追蹤表。

## 行動

- 從追蹤表或草稿抄句子進現況文件前，grep 一次程式確認已實作
- 寫完文件逐句問：這句指得到哪段程式？指不到就刪
