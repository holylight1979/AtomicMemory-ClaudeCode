## 知識

- [臨] 標題錨點：GitHub 與 GitLab 都是轉小寫、刪標點、空格換連字號；差在 GitLab 會把連續連字號壓成一個，GitHub 不壓。標題裡前後帶空格的「 → 」「 — 」「 / 」在 GitHub 變 `--`、在 GitLab 變 `-`，同一條站內連結只有一邊點得到。改成不帶空格的 →、：、／ 兩邊就一致（依兩家錨點規則推算並用程式模擬驗過，未在網頁實點）。
- [臨] 使用者在網頁讀寬表格時欄位被擠成細條、讀不下去：表格最多 4 欄、每格一句；格子裡的長句與清單改成「每項一個小標＋條列」的區塊；先後順序畫箭頭圖；邊界條件與實作細節移到附錄或獨立檔，主文每節結尾一行連過去。
- [臨] repo 內相對路徑連結 `[x](dir/file.py)` 兩邊都能點、中文路徑可原樣寫；空白與括號要百分號編碼。執行期才產生、不進版控的路徑不要加連結（點了 404）。

## 行動

- 寫要在 GitHub／GitLab 網頁讀的文件：標題不放前後帶空格的 → — /
- 表格超過 4 欄或格子超過一句 → 改成每項一個小區塊
- 站內連結交付前用兩套錨點規則各算一次，對不上就改標題
