# 團隊產出上傳前先問人-記憶庫自動做滿

## 知識

- [臨] **兩種產出、兩種尺度，別用同一套判斷：**
- [臨] **(a) 團隊開發範圍的異動 — 上傳前必須再次向使用者(團隊成員、人)確認過。** 問法：『包含驗證都無誤了，是否確定上傳？』，得到明確同意才執行。理由：那是共有物，上傳等於替其他人做決定；且多數版控提交不可逆。
- [臨] **(b) 記憶庫(atom、分類、索引、連結) — 盡可能自動做好做滿，不必逐次徵詢。** 寫入、去重、歸類、建立交叉連結、修正錯誤條目都直接做完。理由：那是我自己的知識管理，問只是增加摩擦。
- [臨] **分界問法**：『這個產出會不會進到別人也要用的東西？』——會 → 問；不會(只是我自己的知識整理) → 自動做完。
- [臨] **單次授權不得外推成長期授權**：使用者說『上傳你自己的』只授權那一次、那幾支檔；之後又修了別的東西，就算測過也要重新問。把修正做完、驗證做完、**停在提交前**，不算退避。

## 行動

- 要提交團隊程式碼時：先列『檔案清單 + 驗證做了什麼 + 哪些驗證沒做』，再問『是否確定上傳？』，等明確同意
- 記憶庫的寫入/歸類/修正/刪除錯誤條目：直接做，不反問『要不要我…』
- 分不清時就問自己：這東西會進到別人也要用的產出嗎？
