# 提問掛節點要看這題在決定哪件事，不照擋訊息建議的編號抄；判斷得了的不問

- Confidence: [臨]
- Trigger: 提問前要寫出這題掛在目標樹哪個節點, 目前最可能的是, ASK_LINKED_TO_GOAL, ASK_NEEDS_RECOMMENDATION, 沒附推薦, (Recommended), 建議：, 自己判斷得了的不推給人
- Created-at: 2026-10-21
- Quote: 「A」

## 知識

- [臨] 擋訊息「目前最可能的是 Tn」是程式挑的「還沒完成的節點裡編號最前的」，不看題目內容。要自己看：這題的答案會改變哪個節點的做法或結果，就掛那個；都不是就先 add 一個節點再問。反例：問 CSV 分隔符，照建議掛到「日期修好」節點。
- [臨] 推薦選你真的判斷最好的那個，理由寫對節點目標的影響（成本、風險、使用者原話）；使用者原話或節點已經給了答案的，不問、照做。
- [臨] 可逆、屬原請求自然延伸的事（刪掉已刪函式的專屬測試、順手修 typo）自己判斷得了，不問、直接做；只有不可逆、業務取捨、缺了答案就推不動的才問。被擋「沒附推薦」時先問這題該不該問，再補推薦。

## 行動

- 掛節點前把題目要決定的事跟每個節點文字對一次
- 擋下時先判「該不該問」，該問才補推薦與節點
