## 知識

- [觀] 使用者的設計對話節奏（音效頻道案）：他提概念 → 我評估 → 他問「你準備做的更動，有什麼是我預期外的」→ 他用一句話重述概念問「這樣理解有沒有落差」→ 才說動。他要的不是方案描述，是「跟他腦中模型不一樣的地方」被明列出來。
- [觀] 「預期外清單」的寫法：逐條列「他可能以為 X，實際是 Y，因為 Z」（例：以為零註冊，實際預設 fade > 0 每次都有短協程；以為播完自滅，loop 是淡入完就滅；以為靠事件，實際是精確睡眠），含行為差異（當幀開播、真實時間）與不動的東西。他對一句話重述的回答要直接「有落差，補上什麼」，不要客套。
- [觀] 「順帶發現、這次不動」在他看來是要一起修的：同一個類裡的既有 bug（比對失效、無用的 finalizer）他直接說「看起來也要一起修正才對」。不懂的原理（finalizer 多一輪 GC）他會直接問，要用白話講機制、不要只給結論。
- [觀] 提案時把自己前一輪的半套方案明講收回（「收成一條 Tick 仍是輪詢，我收回」），他接受度高；不要堆選項要他選（見 [[feedback-強迫選擇也是退避-自動化承諾要對團隊每人成立-不可把專案層動作推給使用者貼prompt]]）。

## 行動

- 重構類提案一律附「你可能預期外」段：預設參數導致的例外、行為差異、不動的東西、順帶發現
- 他用一句話重述時，直接回「有/無落差 + 補哪幾個字」
- 順帶發現的同類 bug 預設納入同一批，除非不可逆或會飄移主任務
