# 文字規格：怎麼寫

一份規格對應一種讀者，寫明這類文字給誰看、要命中哪些目的；每個目的寫成一條是非題。`tools/text-score.py` 照規格逐條問開源免費的小模型裁判（內網 Ollama 優先、本機 Ollama 退路），產出評分表並留帳。

```
python tools/text-score.py <檔> --spec <規格代號>       # 手動評任何文字；- 讀 stdin
python tools/text-score-weekly.py                       # 週彙總：每條過率、趨勢、作廢數
```

## 檔案長什麼樣

檔名＝`<規格代號>.md`，放在這個資料夾。三段，順序固定：

1. **開頭幾行「- 鍵: 值」**，六個都要有：
   - `規格代號`：跟檔名一樣。
   - `適用`：哪些文字要評（給人看）。自動評實際照 `workflow/config.json` 的 `text_score.auto_targets`（種類 → 路徑樣式）過濾，兩邊要一起改。
   - `讀者`、`讀者目的`：會原樣放進每一題，裁判靠它判。
   - `通過線`：寫成「必過項全部「是」或「不適用」」，要容許非必過項有幾個「否」就在後面加「，其餘「否」最多 K 個」。只認這兩種寫法，寫成別的樣子視為格式錯。
   - `維護`：誰能改條目。
2. **`## 檢核項` 表**，欄位：`代號｜問題｜判法｜必過｜沒過時｜來源`。
3. **`## 判例` 表**（選填），欄位：`代號｜會判「是」｜會判「否」`，各一句。判例會跟著題目送給裁判。

## 每一欄的規矩

| 欄 | 規矩 |
|---|---|
| 代號 | 英文字母開頭的英數字（R1、G6-2），一份裡不重複 |
| 問題 | 答得出「是／否／不適用」，一律正面問：通過＝答「是」（例「每句只講一種東西嗎？」）。不要寫「找得到…就答否」這種反向問法：小模型常照字面回答「找不到，所以是」卻把判定填成「否」，實測錯判最常見的就是這種 |
| 判法 | 只認下面四種寫法（「→」前是程式先切的範圍，後面是問裁判）：`模型判`（整份給裁判）、`程式切出標題後的第一句 → 模型判`、`程式切出前 N 句 → 模型判`（N 至少 1，可寫數字或一～十）、`程式先抓候選詞 → 模型判…`（程式抓出像代號的詞列給裁判，整份仍給裁判）。其他寫法視為格式錯 |
| 必過 | 寫「必過」或留空 |
| 沒過時 | `記帳`／`提醒`／`擋`。目前工具只記帳；提醒（下一回合告訴寫的 AI）與擋還沒接 |
| 來源 | 必填：使用者原話或 Failures 卡。沒有來源的條目不收 |

一份最多 8 條：題目越多越細，小裁判越不準。

## 分數怎麼算（程式算，不信裁判算的分數）

- 過＝「是」＋「不適用」；摘要長這樣：`評分 5/7｜沒過：R1、R4`。
- 下面幾種情形，那一條**作廢**，不算過也不算沒過：
  - 引用逐字對不到送去的那段原文（附了引用就要對得到，判「是」「不適用」也一樣）。比對時統一全半形（① 這類相容字也算同一個字）、去掉行首的引用／標題／清單符號、`*` 與反引號、空白；可以用「…」省略中間，省略號以外至少要 4 個字；改寫過的句子不收。
  - 判「否」沒附引用。
  - 判定不是是／否／不適用。
  - 輸入太長，可能被截斷（裁判回報的輸入 token 數達到 num_ctx 的 95%）。
- 有必過項「否」就是不過；必過項作廢或未評就是未定。
- 裁判都不在：整份記「未評：裁判不在」，不擋、不改用付費模型。

## 誰改

條目由原設計者定。AI 只能把候選條目寫進 `memory/_staging/` 提案，原設計者點頭才進規格。改過的規格會換雜湊值，留帳記著當時是哪一版。
