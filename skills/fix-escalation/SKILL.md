# 精確修正升級（Fix Escalation Protocol）

> 同一問題修正第 2 次起自動觸發（Guardian 注入 `[Guardian:FixEscalation]`），或手動 `/fix-escalation` 啟動。
> 依證據擴大：**Stage 1 根因調查＋獨立驗證（≤2 個代理）→ 證據一致且可重現就直接修；矛盾或無法重現才進 Stage 2 會議。** 不固定跑滿 9 次代理。

## 問題描述

$ARGUMENTS

## 執行指令

主 AI 角色：**使用者意圖定向與問題精準修復大師** — 不確定處主動向使用者確認，綜合所有證據做最終決策。
每個代理用 Agent tool 啟動；代理 prompt 只給它需要的脈絡，不整段轉貼。

---

### Stage 0 — 暫停與盤點

向使用者宣告：「⚠ 進入精確修正模式 — 暫停直接修復，先查根因。」

記錄：
- 問題描述（$ARGUMENTS 或當前問題）
- 每次已嘗試修正的內容與結果（第 1 次、第 2 次…）
- 錯誤訊息／症狀／重現步驟（沒有重現步驟就先問使用者或自己找）

---

### Stage 1 — 根因調查＋獨立驗證（最多 2 個代理，**單一訊息並行**）

**代理 A（根因調查）prompt：**
```
你是「根因調查者」。任務：對以下問題找出根因，不提修法。
1. Glob/Grep 找相關程式碼（定義、呼叫端、型別、設定）
2. 讀 _AIDocs/（先 _INDEX.md 定位）與相關 atom
3. git log -20 / git blame 查問題行來源與近期改動
4. 追資料流：從症狀往回找第一個不符預期的值／狀態，附檔:行

輸出：
## 根因報告
### 症狀 → 第一個異常點（檔:行 + 證據）
### 為何之前的修正沒用（對照每次修正的內容）
### 未確定的假設（各附一個可判別的檢查）

問題：{問題描述}
已嘗試：{每次修正內容與結果}
症狀：{錯誤訊息／重現步驟}
```

**代理 B（獨立驗證，不看代理 A 的結論）prompt：**
```
你是「獨立驗證者」。任務：不預設原因，實際重現問題並鎖定觸發條件。
1. 依重現步驟跑一次（測試／腳本／指令），記錄實際輸出
2. 改變一個變數再跑（輸入／環境／版本／時序），找出讓症狀出現與消失的最小差異
3. 外部資料只在本機證據不足時查（WebSearch ≤2 個關鍵字、WebFetch ≤2 頁），註明來源

輸出：
## 驗證報告
### 能否重現（步驟 + 實際輸出）
### 最小觸發條件／消失條件
### 與已知外部資訊的對照（有則列，無則寫「未查」）

問題：{問題描述}
重現步驟：{步驟}
```

**判定閘（主 AI）**——兩份報告到齊後只問一件事：**根因是否單一、且兩邊證據一致、且可重現？**
- **是** → 直接進 Stage 3（修）。不開會議。
- **否**（兩邊指向不同原因／無法重現／根因落在自己不熟的外部系統）→ 進 Stage 2，並把「矛盾點」寫成一句話當會議題目。
- 資訊不足但方向明確 → 只補一次針對性檢查（自己跑或再派 1 個代理），不重跑整個 Stage 1。

---

### Stage 2 — 會議（只在證據矛盾／無法重現時）

同時啟動 3 個代理（**單一訊息並行**），輸入＝Stage 1 兩份報告＋主 AI 寫的矛盾點：

- **正向策略**：基於證據提根因假設與修法（含程式碼片段）、預期效果、信心程度＋理由
- **反向策略**：每個方案的盲點與風險、正方沒考慮的替代路線、最壞情況
- **落地執行**：每個方案可行／有風險／不可行＋原因、優先順序、前置條件與副作用；**禁止數值化「命中率」，只做定性分析**

主 AI 綜合：共識直接採用；仍有分歧 → **就分歧點**再派一輪（最多 2 個代理：正向＋反向，各自逐條回應對方），不重跑三方。分歧涉及業務取捨 → 問使用者。

---

### Stage 3 — 修正與收尾

1. 向使用者簡報：根因一句話、修法、影響範圍；無異議後執行。
2. 修正**只動根因路徑**；順手發現的其他問題記下，不併修。
3. 收尾自查（主 AI 自己做，不派代理）：`git diff --stat` 對照修改範圍；殘留 debug 輸出／暫存檔／未用 import／TODO 註解當場清。

---

### Stage 4 — 驗證

1. 用 Stage 1 的重現步驟再跑一次：症狀消失＋原本正常的路徑仍正常（測試／編譯／手動確認，附輸出）。
2. **成功** → 回報：「精確修正 ✓ — 根因：…；驗證：…」
3. **失敗** → 回到判定閘：這次驗證產生的新證據算進去，重判是否需要 Stage 2；向使用者說明卡點與已試方案。
4. **連續 3 次**精確修正未解決 → 強制暫停，與使用者全面對齊（問題定義是否對、是否該換路線）。
