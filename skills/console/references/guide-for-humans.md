# 雙總控台怎麼用（給人看的一頁）

> 給誰：想叫 Claude Code 多開幾個分頁一起做事的人。你只要讀這一頁；技術步驟在 SKILL.md，由 AI 自己照做。
> 底稿是原設計者寫給別人的說明，以下標「改」「補」的是依實際跑過一輪後修正的地方。

## 1. 先有計畫檔

讓 AI 把計畫寫成 checklist，你要嚴格審：看不懂的（太多繞口的技術說明、或看起來根本不相干的）一律指出來退件、重寫。適當的時候推進到「計畫前準備」，再推進到「計畫」。

## 2. 開哪些分頁

**A) 總控台**
- 平行的工作只有一兩條：開一個總控台就好，它一個人兼兩職。〔改〕
- 三條以上：開兩個。
  - **對人總控台**：你主要只跟它說話。它用最快速度回答你的問題、收你的命令、轉給調度。
  - **調度總控台**：跟所有工作分頁說話、派工、收交付、合併、推送，並負責最後一次全量驗證（每一軌自己的驗證由工作分頁自己跑）。
- 模型依工作分：調度用 Opus 就夠；對人平常用 Opus，碰到要密集裁定的階段才換 Fable。〔改：原本兩個總控台都推薦 Fable 或 Opus ExtraHigh〕

**B) 工作分頁**
- 推薦 Opus（小修也用 Opus），或看工作類型用 Sonnet、Haiku。
- 你負責開新分頁、貼上總控台給的第一句話（開工句），之後基本上不用再說話。
- 例外只有兩種，總控台會明說要你去哪一頁：〔補〕
  1. 那一頁跳出「放行這一回合」的選擇題，要你點（程式擋滿了，只有人能放行）。
  2. MCP 程式改了，要你 Reload Window（新程式才載得進來）。
- 總控台叫工作分頁用的名字（claude-xx）你看不到。開工句第一句就是軌名，分頁標題會跟著變成軌名，你用標題跟總控台核對是哪一軌就好。

## 3. Reload Window 之後〔補〕

Reload 會把所有分頁的 claude-xx 名字全部重編，沒接回來的分頁會從名單消失。對人總控台會先點名、把新名字轉給調度和各軌，你不用做事。只要記得：Reload 前先讓兩個總控台寫好交接備忘。

## 4. 常用口令

| 口令 | 什麼時候說 | 會發生什麼 |
|---|---|---|
| SendMessage | （不用你說）分頁之間互傳訊息，CC 內建 | — |
| 派工 | 想做一件新事 | 對人轉給調度，調度寫派工單派給某一軌 |
| 收割後關 | 某軌做完、你想關它之前 | 它把經驗收進記憶、清乾淨，回報「可關」你再關 |
| 寫交接備忘〔補〕 | 某分頁 context 用到約 85%（你看得到百分比） | 它停手、寫一份自足備忘，換一個新分頁接手 |
| [分頁標題] | 跟總控台提某一軌 | 直接講分頁標題，總控台會對應到內部名字 |

## 5. 覺得太慢

問對人總控台：「是不是適合再多開分頁並行？」它會看還有哪些互不相干的工作可以拆。

## 6. 效果

你主要只跟一個分頁講話；開、關分頁，偶爾瀏覽各分頁概況；其他的 CC 自己跑。想一眼看全部軌的狀態，叫總控台跑 `console-status.py`。
