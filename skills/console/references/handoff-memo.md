# 交接備忘範本（context 到 85%、Reload 前、換人前寫）

> 給誰：要換手的總控台或工作軌。讀者是沒看過你對話的接手者，所以每條都要自足：路徑寫絕對路徑、hash 寫出來、「剛才」「那個」一律換成實物。
> 口令：總控台對快滿的分頁說「寫交接備忘」，對方停手、不 commit、照下面回。

## 門檻

- 80%：總控台不再派新件給它。
- 85%：寫交接備忘換手，不等自動壓縮（壓縮會丟細節，換手前寫清楚比壓縮後補救穩）。

## A. 工作軌接手備忘（20 行內，用 SendMessage 回調度）

```markdown
# <軌名> 接手備忘（<名字> → 接手者，<日期>）
- worktree／分支／HEAD：<路徑>／<分支>／<hash>（有沒有未 commit 的改動）
- 派工單：<路徑>；做到第幾步：<…>
- 每個未提交檔改到哪：<檔：狀態>
- 做過的選擇與理由：<…>
- 程式碼看不出的坑：<…>
- 還沒跑的驗證：<…>
- 我在等：<…>
```

調度收到後存 `from-track-<軌>/`，寫一份接手派工單（原話目標、待修清單、備忘路徑、「開工先核對未提交清單，不准 checkout／stash／reset 整棵樹」）到 `to-track-<軌>/`，再派給待命 session。

## B. 總控台交接備忘（存 `_console/<角色>交接-<日期>.md`）

```markdown
# <對人／調度>總控台交接備忘（<名字> → 接任，<日期>）

> 自己的絕對路徑：<…>。對人總控台＝<名字>（分頁標題「…」）。裁定帳到 #<N>。
> 接任者：先照接續單待命三步報到，再讀本檔。

## 1. 現況
- main <hash>，未推 <N> 筆；live 未提交的檔與屬於誰。
- worktree 清單（`console-status.py` 貼上即可）。

## 2. 在跑的事與等誰
| 事 | 狀態 | 等誰 | 接任要做 |
|---|---|---|---|

## 3. 各軌待收／待派
- <軌名>：派工單 <路徑>、交付信 <路徑>、下一步。

## 4. 這場新增的規則與裁定
- #<N>：<一句>。

## 5. 腳本與 log 在哪
```

## 換手步驟

1. 總控台：寫備忘 → 更新接續單「現任」行與待辦 → SendMessage 待命 session「接手<角色>總控台：<接續單路徑>」。
2. 接任者：用 Read 讀 `~/.claude/skills/continue/SKILL.md`、照它對接續單做（continue 與 console 都只能人打，模型叫不了）→ ListAgents → 通知另一個總控台與各軌新名字。
3. 舊的收到接任回報後停手；人關掉舊分頁。
4. 要 Reload Window 時：兩個總控台都先寫好備忘、接續單寫好，Reload 後由對人先點名（見 SKILL.md 用法一 Step 4）。
