# 派工單範本與信箱擺法

> 給誰：調度總控台寫派工單時照填。工作軌只讀這一份就要能開工，所以要自足：原話目標、定死的規則、驗法、交付格式都寫在裡面。

## 信箱擺法

```
<專案根>/workflow/inbox/          ← 路徑可換；本機用，不進版控（換機要另外帶）
├── to-track-<軌>/NNN-<題>.md        ← 派工單（調度寫）
├── from-track-<軌>/NNN-<題>.md      ← 交付信（調度收到後存檔）
└── _console/                        ← 總控台自己的：裁定帳、交接備忘、驗證 log、腳本原稿
```

- 編號 NNN 每軌自己往上加；退件單接著編（例 002 退件 → 003）。
- 腳本、素材不要以 `.py`／`.sh` 放進信箱（程式會當成改碼記欠帳），存成 `.py.txt` 讓工作軌自己複製去用。
- 看現況：`python ~/.claude/tools/console-status.py`（印各軌最新來信與 `_console/verify*.log` 的結果）。

## 開新軌

1. 軌名望文生義（`track-login-fix`）。小幅改動不開軌，直接在 main 改、驗、推。
2. 建 worktree 與分支：`git worktree add <worktree 路徑> -b <分支> main`。
3. 寫派工單到 `to-track-<軌>/000-prompt.md`。
4. `/console 開工句 <軌名> <派工單路徑>`，交對人轉給人貼。

## 派工單範本

```markdown
---
to: <軌名>
seq: <NNN>
type: 派工（<一句話這件要做成什麼>）
from: 調度總控台（<對人或人的要求>）
---
這封在說什麼：<兩三句白話：目標是什麼、現在缺什麼>

## 原話目標
- <使用者原話或接續單裡的目標原文；判準以原文為準>

## 定死
1. <不准自由發揮的規則：放哪支檔、規則名、判定只看什麼>
2. 不放寬既有的閘、不加例外清單。

## 紅案例（改前紅、改後綠）
- <情境 → 該擋／該收>

## 做法
第一步 EnterWorktree 切進 `<worktree 絕對路徑>`（分支 <分支>）。need_goal set → 讀 <檔清單> → 改 → 紅案例 → 跑 <目標 verify 清單> 全綠；退回舊碼看紅；
（選）自跑 codex 一輪，停止條件「只有一般寫法才 BLOCK」；文件類不跑。
含 git 字樣的指令寫成 worktree 內 Python 啟動器再跑；不跑全量、不輪詢；commit 不推。
交 <NNN+1> SendMessage <調度名>（送前 ListAgents）：HEAD、改檔、passed、退回看紅、codex、live 未動、need_goal 每步、已知限制，結尾「我在等：…」。
開工前 SendMessage 調度「<軌名> 收到開工」。
```

## 退件單多寫三件

- 退件原因附「怎麼重現」（讀碼或指令），讓工作軌不必猜。
- 原話目標照抄，不只寫症狀。
- 同一面退第二次：不再列症狀，把規則定死或改設計。
