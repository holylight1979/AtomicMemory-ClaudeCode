# 交付信範本（工作軌 → 調度）

> 給誰：工作軌交付時照填，用 SendMessage 送全文（worktree 裡寫不到信箱，所以不寫檔）。調度收到後存成 `from-track-<軌>/<NNN>-<題>.md`，在信尾加「調度對帳」段。

## 範本

```markdown
---
from: <軌名>（<你的名字>）
to: 調度總控台 <調度名>
seq: <NNN>
---
<一句話總結>：commit <短 hash>（分支 <分支>，基底 <基底 hash>，未推），<檔數> 檔 +<加>/-<減>，目標 verify <N> passed、<探針結果>、codex <幾條 BLOCK 怎麼處理>。

盤點（改前 → 改後）：<每個行為點一句>

改檔：<檔：改了什麼>（每檔一句）

驗證：
- 目標 verify：<指令> → <N passed>
- 先紅後綠：退回舊碼跑 → <幾紅>；改後 → 綠
- merge-tree 對 main <hash>：<有無衝突>
- codex：<BLOCK／WARN 與處理；文件類寫「不跑」>
- live 未動：開工與交付前 `git status --porcelain` 相同（<列出內容>）
- need_goal：<set／add／update／reconcile 每步與結論>
- 判斷寫成固定規則：<這次有沒有把需要判斷的事寫成固定清單、檔名對應、門檻數字；有就列位置與為什麼合理，沒有寫「無」；看到別處同類也列>

已知限制／待裁：<照實寫；不准寫「之後再」「另外處理」「延後」>

我在等：<調度對帳合併／對人裁定 X／無>
```

## 調度對帳段（調度收件後加在信尾）

```markdown
---
調度對帳（<名字>）：改檔集＝自述／禁字無／CR 無／merge-tree 無衝突／live 未動；
基底 <hash> 對 main <hash>：<含最新 main 可快轉 → 直接推｜落後 → 合後補驗>；閘本體改動：<有 → 快照｜無 → 信收據>。
```

## 寫交付信的三個坑

- 「完成」要有沒紅的收據；只有讀碼或推論的寫成「推論」，不寫「通過」。
- 子代理寫的部分照實標出來，你自己 review 過 diff、自己跑過 verify。
- 結尾沒有「我在等」＝調度看不出你卡在誰身上。
- 「順手看到最該修」與「已知限制」裡的問題，該誰解只有兩種：「已修」（相關且確實有問題 → 同分支立即修完再交）或「飄移，不做，因為…」；寫「下一個寫碼 session」「合併後再排」會被當場派回來補件（原設計者 2026-10-20 定，細節見 dispatch.md）。
