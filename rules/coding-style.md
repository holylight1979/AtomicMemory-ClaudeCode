# 寫碼傾向

> 優先序：正確與安全邊界 > 使用者這次的目標 > 真實限制 > 專案現有做法 > 可讀可驗證的簡單 > 最小修改面 > 個人語法偏好。目標跟規則檔、紀錄、現有程式衝突時，照 `rules/code-thinking.md`「設定衝突時的處置」。極簡永遠排在正確後面。

## 設計取捨的尺（判斷好設計、批判現況都用這把尺）
- 分類與處置要清晰：
  - 資料：資料本身就能攤成二維表格（列×欄）來看，所以應用要直觀，打開就看得懂（例：SQL 表欄位）；這個方向優先於任何套件、格式或框架的方便。
  - 數值與資料：避免浮濫。只有 5 種值就寫成 5 個值的 enum；硬開成 byte（0～255），讀的人得猜哪些值合法，就是反例。
  - 可讀性：減少匿名（沒有名字的函式、型別、神奇數字），註解白話。
- 少綁定：資料不必綁某種序列化格式或大量自動產生的物件；工具自動產生的程式綁了套件，卻失去可讀性與抽象思考的空間，不能算優點。
- 精要、易讀、易想像：讓讀的人腦中直接浮現資料的長相和流向。
- 取用彈性：要什麼撈什麼，查詢照需求寫；工具自動產生程式碼，只是好讀之後順帶的延伸。

## 結構
- 先選最貼近問題語義的資料模型與標準操作，再選控制結構。
- 不把 if / for / while 排成互相取代的階級；分支處理選擇、迴圈處理重複。
- 同一語義可選時，取「讀者要記的狀態最少」的構件：直線 > guard clause / early return > 有界迭代（for-each、map/filter）> 單層分支 > 無界迴圈 > 遞迴 > 高階抽象 / metaprogramming。
- 遞迴只用於天然遞迴且深度可界定的問題；狀態機只用於狀態轉移本身就是問題。
- 壓平第一步：先踢例外讓主路徑不縮排；迴圈內用 continue / break 提早離開。
- 壓平第二步：條件複雜就命名判斷式；if 鏈變長就查表或 dict dispatch。
- 壓平第三步：巢狀來自重複搜尋就 Set / Dict 預建索引，常順便把重複掃描降成單次查詢。
- 巢狀 ≤2 免談。
- 巢狀 =3 是審查線：三層若各守一個獨立條件，讀者得同時記住三件事，必須壓平；若只是同一個局部決策仍能直線追蹤，可保留。
- 巢狀 ≥4 一律重構。
- 上面三條只管我這次寫或改的段落；既有巢狀不要求順手重構。
- 扁平化不過頭：抽函式要 ≥2 處呼叫、或能用一個名詞命名且有實質內容；不為壓層數製造一次性小函式。
- comprehension 只准一層 for 一層 if；clear > clever。
- 一個檔案看完一件事；跨檔抽取必須換來明確的重用、隔離或責任邊界。

## 極簡
- 不加沒被要求的參數、設定、抽象、預防性分支；外部邊界與已知失敗模式仍要處理。
- 同一段「必須同步變更的知識」第 2 次出現才抽共用；文字相似不算重複。
- 自己弄出來的死碼、暫存、廢話註解當場刪；不戀 code。
- 極簡不砍可觀測性：錯誤訊號、日誌、資源釋放、資安檢查不刪，禁止靜默失敗。

## 節奏
- 讀碼有目的：每個實作目標先列要確認的契約、呼叫點、資料流、測試。
- 從搜尋命中處沿真實依賴逐跳擴讀，不因同模組就整包載入。
- 停止條件：能說清輸入輸出、不變量、影響路徑、驗法就停；只為會改變決策的未知再讀一跳。
- 舊碼只是證據，不預設它正確。
- 旁支死碼與問題改到一半不順手動，先記下；本段做完再依反退避契約處理。
- 先立最小可驗證假設就動工，小步推進；每段完成只重整本次觸及範圍。
- 腳本家族一個入口附 --help；每支腳本檔頭一段「做什麼、怎麼跑」，完整參數以 --help 為準。

## 自檢
> 三個停點：動手前、結果違反預期時、交付前。明點＝停下來靜觀的那個位置。
- 每次只確認四件事：目前目標、已知事實、暫定假設、下一個可判別動作。
- 證據與預期不符：不替原方案辯護、不擴大修改；先更新假設，再做能區分候選原因的最小檢查。
- 交付前針對異動範圍實跑；回報分清已驗證事實、推論、未知，不用自信語氣填補證據缺口。
- 以陌生維護者視角順資料流重讀；無法連續解釋的段落就要整理，但不因此自動拆分重寫。
- 驗證腳本結尾印一行哨兵 `<NAME>_CHECK PASS` 或 `<NAME>_CHECK FAIL`（格式 `^[A-Z][A-Z0-9_]*_CHECK (PASS|FAIL)$`），exit 0／1 對應；只印 `<NAME>_CHECK` 缺字尾不算 PASS。
- 量測類腳本結尾印 `<NAME> DONE k=v k=v`（格式 `^[A-Z][A-Z0-9_]* DONE( \w+=\S+)*$`），數字是尺不是判決，不印 PASS。
- 既有工具尾行格式不同時不改工具，在專案 `.claude/overview-hub.json` 的 `prebuild_checks[]` 該項加 `sentinel_regex` 映射成上面兩種之一。
- 驗證只跑異動範圍與確實相關的案例；整組只在使用者點名時跑。真要跑超過單次工具呼叫上限（10 分鐘）的驗證程式，印完哨兵後要自寫收據（呼叫 `~/.claude/lib/self_receipt.write_self_receipt`，寫到 `workflow/verify-ledger/_runs/`，不准手寫），量尺閘才認得到背景跑完的結果；跑量尺照部位表上的原字串單獨跑。
