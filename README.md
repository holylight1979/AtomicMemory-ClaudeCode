# 原子記憶系統 Atomic Memory

Claude Code 的「長期記憶」擴充套件：AI 記得你們一起做過的決定、踩過的坑、養成的習慣——換一個 session、換一個專案、換一台電腦都不失憶。知識以一張張「記憶卡片」存放、分門別類，你每問一句，系統只把最相關的幾張送到 AI 眼前。

---

## 記憶分三層

| 層 | 放什麼 | 在哪裡 | 怎麼拿到 |
|----|------|------|------|
| **根層** | 系統本身＋跨專案都用得到的通則、工具踩坑 | `~/.claude/` | 裝一次（[Install.md](Install.md)）；全員共用同一個版控庫 |
| **公司層** | 全公司、所有專案共用：公司級工具卡、跨專案共識 | 公司記憶庫（自己一個 git／svn repo，接上時 AI 會問你放哪） | 每台機器接一次：對 AI 說「接上公司記憶」 |
| **專案層** | 這個專案的決策、踩坑、共識 | `{專案}/.claude/memory/` | 跟著專案版控走，pull 專案就有 |

三層都分「大家的」與「我的」：針對專案的規則進共享區並記下提出者；只關於你的偏好只有你看得到。你是誰、做什麼職務，直接取自 Windows 登入帳號與 AD 群組，不用填設定。

Claude Code 自帶的自動記憶（auto memory）在本系統裡是關掉的：記憶統一存成卡片，`/memory` 會顯示 Auto-memory off，不影響使用。

---

## 開始用

1. 裝根層：照 [Install.md](Install.md) 貼一段 prompt 給 Claude Code，它自己裝。
2. 第一次啟動時 AI 會問你公司記憶庫放哪，回答即接上。
3. 第一次進某個專案，對 AI 說「初始化原子記憶庫」，之後照原本的方式用 Claude Code 就好。

## 它平常替你做什麼

- **每句話自動帶記憶**：你每問一句，它挑最相關的幾張卡片給 AI。不用提醒「上次我們說過……」。
- **做完一段就盤點**：AI 宣告完成時，系統要它先回頭看這場學到什麼——該記的寫成卡片、舊卡片錯了就修正或取代、沒用的退役，然後才准收尾。
- **自動學教訓**：跑失敗、被你糾正、做了決策，背景自動寫成卡片；卡片標 [臨] 是剛學到、[固] 是反覆驗證過，久沒用的自動淡出。
- **收尾把關**：回合結束前檢查——測試沒轉綠、說「修好了」卻沒在這回合跑過驗證、把事推給「下次再說」、改了檔沒上版控，都會被攔下來要求處理。
- **多機自動同步**：卡片在背景自動上版控、自動拉別人的新卡片。

**寫碼守門預設開、只在寫程式的回合跑**：說修好要有跑綠的收據、提交前擋新寫的病形、問你之前附推薦、讀到跟舊坑有關的檔就提醒先看那張卡；純問答、只改文件的回合不跑。要關：設環境變數 `WG_CODING_GUARD=0`，或在 `workflow/config.local.json`（不進版控）寫 `{"coding_guard": {"enabled": false}}`；`WG_CODING_GUARD=1` 強制開。舊鍵 `v6`、舊變數 `WG_V6` 仍可用。

## 你會對它說的話

| 你說 | 它做 |
|------|------|
| 「接上公司記憶」「公司記憶接上沒」 | 接上／查看公司層（`/org`） |
| 「把這條記到公司層」「登記工具」 | 寫入公司層；把 skill／MCP 登記成公司工具卡 |
| 「初始化原子記憶庫」 | 在專案建立記憶層（首次） |
| 「幫這個專案建部位表」 | 掃出專案的部位表骨架與每塊的導讀卡（先預覽，你同意才落檔） |
| 「整理記憶分類」 | 把專案裡舊的卡片按「大家的／我的」歸位（啟動看到 `[Guardian:ScopeLayout]` 時） |
| 「整理這場會議 `<音檔>`」 | 錄音 → 逐字稿 → 決議／待辦／未決摘要，決議寫進專案記憶；辨識在內網跑，音檔不出門 |
| 「上GIT」「上SVN」 | 把這次改到的檔 commit → push 一氣做完 |
| 「執P」 | 分階段執行：完成 → 驗證 → 上版控 → 給下一階段的 prompt |
| `/console` | 多軌並行：你只跟總控台說話，它在背景開工作 session（名字就是軌名，各自一份工作目錄）。某個 repo 第一次用 `/console 開工` 前，先在那個 repo 的主目錄開終端機跑一次 `claude`、接受信任提示，不然開不成，會退回一段開工句請你自己貼 |
| `/handoff`、`/continue` | 產出跨 session 交接 prompt／接續上個 session |
| `/memory health` | 記憶庫健檢報告 |
| `/conflict pending` | 檢視、核准或退回待審的卡片 |
| 「這張卡片哪來的」「誰說的」「你哪裡看到的」 | 回這張卡片的來源：日期＋當時的原話＋前後文；原對話已清掉就回落檔時留的原句或「已逾保留期」 |

不經 Claude、直接查一句：`python ~/.claude/tools/memory-search.py "問題"`。

## 版控：卡片自己上，程式碼等你說

- **記憶卡片**：三層的記憶目錄由系統在背景自動 commit、push、拉取，git／SVN 都一樣，你不用管。
- **程式碼與設定**：只有你說「上GIT」／「上SVN」，AI 才會 commit 與 push——有程式閘擋著。你還有程式碼沒推時，卡片也會等你一起推，不會偷推。
- **唯一免口令的例外**：改的是這套記憶系統自己的程式與文件（`~/.claude` 這個 repo，或它開出來的 worktree），AI 驗證過就直接 commit、push，不會問你。你其他專案的程式碼一律照上面那條等口令。

---

## 收尾被擋住時：只有你能放行

AI 說「改好了」卻拿不出對得上的驗證、改了程式沒補測試案例、該跑的量尺沒跑，收尾會被擋。擋滿兩次它不能自己放過去，只能用【收尾放行確認】問你：你選「放行」或直接打「放行」，這一回合才會放；你不答它就一直擋。子代理和背景裁判沒有人可問：同樣擋滿兩次就放行，並把這次放行記下來，主 session 收尾時照樣檢查它們改的檔。每次放行會記下來，週健檢會列出。
- **多台電腦、多人同時寫卡片**：索引檔的衝突系統自動合，不停下來問你。人工介入的少數情況見 [_AIDocs/MultiMachineMemorySync.md](_AIDocs/MultiMachineMemorySync.md)。

## 看得見的介面

Claude Code 開著時：

- **狀態列**：模型、context 用量、本 session 改／讀了幾個檔、向量服務是否在線。
- **Dashboard**：`http://127.0.0.1:3848/`——記憶、session 狀態、健檢。
- **腦內世界**：用瀏覽器直接開 `tools/workflow-guardian-mcp/world.html`，卡片視覺化成生態世界。
- **每週一**健檢自動跑，有問題下次啟動會提示一行。

## 不用 Claude Code 的同事

Codex、Gemini CLI、Antigravity 等支援 MCP 的 AI 工具，貼一段 prompt 跑 `python ~/.claude/tools/ai-client-setup.py` 就接上公司記憶，可查可寫，但沒有「每句話自動帶記憶」，要主動說「查記憶」。連 MCP 都沒有的人，有 Python 就能跑上面的 `memory-search.py`。做法見 [TECH.md](TECH.md) §5.8。
